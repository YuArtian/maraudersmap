# 图片优化

## TL;DR

**图片往往占页面体积大头，优化四路并进：格式（WebP/AVIF + picture 回退）、尺寸（srcset 响应式 + CDN 裁剪）、时机（原生 loading=lazy / IntersectionObserver 懒加载）、体验（宽高占位防 CLS、渐进式加载）**。手写懒加载 = IntersectionObserver + data-src 赋值，这是必备手写题。

---

## 1. 格式选型

| 格式 | 特点 | 用途 |
|---|---|---|
| JPEG | 有损、无透明 | 照片类的兼容兜底 |
| PNG | 无损、透明 | 需要精确边缘/透明的 UI 图 |
| **WebP** | 比 JPEG 小约 25-35%，支持透明与动图 | **现代默认**（各主流浏览器已全面支持） |
| **AVIF** | 压缩率更优 | 渐进采用，走 picture 回退 |
| SVG | 矢量 | 图标、插画（见 [[1.09 CSS 工程化：模块化方案、iconfont 与字体]]） |

回退写法（浏览器按序选第一个支持的）：

```html
<picture>
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <img src="hero.jpg" alt="…">
</picture>
```

工程捷径：**图片走 CDN 的处理参数**——URL 上加参数即可转格式、裁尺寸、压质量、开渐进式（interlace），一张原图按需分发（CDN 机制见 [[1.05 DNS 与 CDN]]）。

---

## 2. 响应式尺寸：srcset + sizes

```html
<img src="w800.jpg"
     srcset="w400.jpg 400w, w800.jpg 800w, w1600.jpg 1600w"
     sizes="(max-width: 600px) 100vw, 50vw"
     alt="…">
```

浏览器按「视口 × DPR × sizes 声明」自动挑最合适的资源——手机不下 4K 图、Retina 屏不糊。密度写法 `srcset="a.jpg 1x, a@2x.jpg 2x"` 适合固定尺寸的头像图标。

## 3. 懒加载：从原生到手写

**第一答案是原生**：`<img loading="lazy">`——浏览器自带视口检测与预取距离策略，零 JS。需要更多控制（响应式懒加载、曝光埋点复用）才手写：

```js
const io = new IntersectionObserver((entries) => {
  for (const e of entries) {
    if (!e.isIntersecting) continue;
    const img = e.target;
    img.src = img.dataset.src;                    // 真实地址从 data-src 换入
    if (img.dataset.srcset) img.srcset = img.dataset.srcset;
    io.unobserve(img);                            // 加载一次即退订
  }
}, { rootMargin: '200px' });                      // 提前 200px 预热

document.querySelectorAll('img[data-src]').forEach(img => io.observe(img));
```

判分点：**IntersectionObserver 而非 scroll + getBoundingClientRect**（老方案要节流且每次强制布局，见 [[2.03 浏览器渲染原理与回流重绘]] 的强制同步布局）；rootMargin 提前量；加载后 unobserve。

**防 CLS 的占位**（懒加载的孪生问题）：图片未到位时高度为 0，加载后内容跳动——现代解法直接写 `width`/`height` 属性（浏览器自动按 aspect-ratio 预留），或 CSS `aspect-ratio: 16/9`；老手法是 padding-bottom 百分比盒（原理见 [[1.01 盒模型与 box-sizing]] 的纵向百分比基准）。SEO 顾虑：正式 src 保留原图、srcset 放缩略图控制实际下载——爬虫与分享读 src 不受影响。

**预加载**是反方向：LCP 主图 `<link rel="preload" as="image">` 提前抢跑（见 [[2.04 script 加载与资源提示]]）——「首屏预加载、首屏外懒加载」一句话收束。

## 面试问答

### Q: 图片优化有哪些手段？

满分答案：四个维度——格式：默认 WebP、渐进上 AVIF，picture 标签按支持度回退，图标用 SVG；尺寸：srcset/sizes 响应式分发，CDN 参数化裁剪压缩一图多吃；时机：首屏外 loading=lazy 或 IntersectionObserver 懒加载、LCP 主图反向 preload；体验与稳定：width/height 或 aspect-ratio 占位防 CLS、渐进式 JPEG、低清晰度占位图（LQIP）。收尾点指标：图片优化直接作用于 LCP 与 CLS。

### Q: 手写一个图片懒加载？

满分答案：真实地址放 data-src，IntersectionObserver 配 rootMargin 提前量观察所有懒图，进入视口把 data-src 赋给 src（响应式同步赋 srcset），随即 unobserve 防重复。主动对比老方案：scroll 监听加 getBoundingClientRect 需要节流、且每次读取触发强制布局，IO 是异步批量回调无此开销。再补一句原生 loading=lazy 已覆盖多数场景，手写价值在于自定义策略与埋点复用。

### Q: 懒加载图片导致页面抖动怎么办？

满分答案：根因是图片加载前后高度变化引发布局偏移（CLS 恶化）。方案：img 直接写 width/height 属性，现代浏览器据此推导宽高比预留空间；或 CSS aspect-ratio；老兜底是外层容器 padding-bottom 百分比撑出比例盒。配合骨架屏/占位色可进一步优化感知。这题实际考「CLS 的成因与预留空间」的理解。
