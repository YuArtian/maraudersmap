# Web 性能指标与前端监控

## TL;DR

**Core Web Vitals 现役三大件：LCP（加载，<2.5s）、INP（交互响应，<200ms，2024 年起替代 FID）、CLS（视觉稳定，<0.1）**。采集靠 `PerformanceObserver` 订阅性能条目；监控 SDK 的三大板块：性能指标、异常捕获（五种错误各有各的钩子）、行为链路上报。

> Sentry 的接入与实践见已有笔记：[[Breadcrumbs]]、[[Log]]（Infrastructure/Sentry 目录）。

---

## 1. 指标体系：按页面生命周期记

**加载阶段**：TTFB（首字节，后端+网络）→ FP/FCP（首次绘制/首次内容绘制——「白屏时间」的口径）→ **LCP**（最大内容元素渲染完成——「主角出场」）；
**交互阶段**：TTI（可稳定交互）→ **INP**（整个生命周期内交互延迟的高分位值——**已取代 FID** 成为正式 Core Web Vital，FID 只测「首次」输入且只算输入延迟，INP 覆盖全程与渲染反馈）；
**稳定性**：**CLS**（累计布局偏移——图片无尺寸、动态插入广告导致内容跳动）。

三大件的达标线与主治手段：

| 指标 | 良好 | 主治 |
|---|---|---|
| LCP | < 2.5s | 预加载关键资源、CDN/缓存、SSR/SSG、压缩（见 [[2.02 首屏加载优化]]） |
| INP | < 200ms | 拆长任务、时间切片、减少主线程 JS（见 [[2.04 并发控制与耗时任务优化]]） |
| CLS | < 0.1 | 图片视频写尺寸、骨架占位、动态内容不插在已有内容上方 |

## 2. 指标采集原理

```js
// PerformanceObserver：订阅式拿指标（现代标准做法）
new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) report('LCP', entry.startTime);
}).observe({ type: 'largest-contentful-paint', buffered: true });
// 同理订阅 layout-shift（CLS 累加）、event（INP）、longtask、resource…

// 传统时间点：performance.timing（已废弃）→ 用 PerformanceNavigationTiming
```

工程直接用 **web-vitals** 库（Google 官方，封装好口径与上报时机）。上报细节：**用 sendBeacon/fetch keepalive 在页面卸载时发**（普通 XHR 会被 unload 打断）；抽样上报控量。

## 3. 异常监控：五类错误五个钩子

| 错误类型 | 捕获方式 |
|---|---|
| JS 运行时错误 | `window.onerror` / `addEventListener('error')` |
| **Promise 未处理拒绝** | `unhandledrejection` 事件（onerror 抓不到） |
| **资源加载失败**（img/script） | `addEventListener('error', fn, true)`——**资源错误不冒泡，必须捕获阶段**（见 [[3.05 事件模型与事件委托]]） |
| 接口错误 | 拦截封装 fetch/XHR（改写原型或请求库拦截器） |
| 框架内错误 | React 错误边界 / Vue errorHandler（见 [[1.10 Vue 高频细节题集]]），拦截后手动上报 |

跨域脚本报错只有 "Script error."——补 `crossorigin` 属性 + 资源响应 CORS 头才能拿到堆栈；线上压缩代码靠 **sourcemap 还原**（上传到监控平台而非公网，呼应 [[2.02 Loader 与 Plugin 开发]] 里「插件上传 sourcemap」的场景）。

**行为链路（面包屑）**：SDK 劫持 console、点击、路由跳转、请求，环形缓冲记录最近 N 条——错误发生时连同面包屑一起上报，还原「用户做了什么才崩的」。

---

## 4. 答题组织：监控体系三层

「**采集层**（性能 PerformanceObserver、异常五钩子、行为面包屑）→ **上报层**（sendBeacon 卸载期可靠上报、抽样、批量合并）→ **平台层**（sourcemap 还原、聚合去重告警、大盘与版本对比）」。加一句指标驱动：上线优化用 LCP/INP/CLS 的变化验证效果——闭环思维是面试的区分点。

## 面试问答

### Q: 说说 Core Web Vitals？各自怎么优化？

满分答案：三大件——LCP 最大内容绘制衡量加载（<2.5s 良好），靠关键资源预加载、CDN 缓存、SSR、图片优化；INP 交互到下一帧的延迟高分位衡量响应性（<200ms），2024 年正式取代 FID——FID 只测首次输入延迟、INP 覆盖全生命周期含渲染反馈，优化靠拆长任务与减少主线程阻塞；CLS 累计布局偏移衡量稳定（<0.1），靠媒体元素预留尺寸、骨架屏、避免上方插入内容。主动说明 FID→INP 的更替体现知识时效。

### Q: 前端异常监控怎么做？各类错误怎么捕获？

满分答案：五类五钩子——运行时错误 window.onerror；Promise 未处理拒绝用 unhandledrejection；资源加载失败用捕获阶段的 error 监听（不冒泡）；接口错误在 fetch/XHR 封装层拦截；框架内错误用 React 错误边界和 Vue errorHandler 兜住再上报。配套三件事：跨域脚本加 crossorigin 与 CORS 头解决 Script error、sourcemap 上传平台还原压缩堆栈、面包屑记录用户行为链路辅助复现。

### Q: 性能数据怎么采集和上报？

满分答案：采集用 PerformanceObserver 订阅 largest-contentful-paint、layout-shift、event、longtask 等条目类型（buffered 补历史），导航与资源细节用 PerformanceNavigationTiming/ResourceTiming，工程上直接用官方 web-vitals 库保证口径一致。上报用 navigator.sendBeacon 或 fetch keepalive——页面卸载时仍能可靠送达；配抽样率与批量合并控制量级，维度带上版本、机型、网络类型便于切片分析。
