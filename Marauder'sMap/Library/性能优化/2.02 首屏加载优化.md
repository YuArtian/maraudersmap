# 首屏加载优化

## TL;DR

**按请求流水线逐环节优化，别背散点**：网络层（DNS 预解析、CDN、HTTP/2、缓存）→ 体积层（分包、Tree Shaking、压缩、按需 polyfill）→ 加载层（路由懒加载、preload 关键资源、defer 非关键脚本）→ 渲染层（关键 CSS 内联、SSR/SSG、骨架屏）。每一环都能与已有专题文章对上——本篇是「汇总索引 + 答题框架」。

---

## 1. 答题主框架：沿着一次加载的生命周期

（完整流水线机制见 [[2.02 从输入 URL 到页面展示]]，指标口径见 [[2.01 Web 性能指标与前端监控]]）

**① 网络与传输**：dns-prefetch/preconnect 提前建连；静态资源上 CDN（[[1.05 DNS 与 CDN]]）；HTTP/2 多路复用、开 brotli 压缩（[[1.02 HTTP 协议与版本演进]]）；缓存策略「HTML 协商 + hash 资源长缓存」（[[1.04 HTTP 缓存策略]]）；关键内容挤进 TCP 首窗约 14KB。

**② 产物体积**：splitChunks 按更新频率分包（基础库/组件库/业务分层缓存）、runtimeChunk 独立；Tree Shaking 与按需引入；动态 import 路由懒加载；browserslist 收紧减 polyfill——全套见 [[2.04 代码分割与构建优化实战]] 与 [[2.03 Tree Shaking 与按需引入]]。

**③ 资源加载次序**：preload 首屏字体与 LCP 大图、prefetch 下一路由 chunk；script defer/async；图片懒加载（[[2.03 图片优化]]、[[2.04 script 加载与资源提示]]）。

**④ 渲染路径**：关键 CSS 内联防阻塞；JS 不挡解析；**SSR/SSG**——首屏 HTML 服务端直出（原理见 [[1.10 Vue 高频细节题集]] 的 SSR 节 / [[3.02 React 性能优化清单]]），静态内容 SSG 优于 SSR；骨架屏改善**感知**性能（LCP 没变但用户觉得快了——「测量性能」与「感知性能」的区分是加分点）。

## 2. 一个可讲述的优化案例模板

「先用 Lighthouse/监控大盘定位：LCP 4.2s，瓶颈在 1.8MB 的入口 JS 和未压缩 banner 图 → 动手：路由级动态 import 把入口砍到 300KB、banner 转 WebP + preload、第三方库拆 vendors 长缓存、接口开启 HTTP/2 与 brotli → 复盘：LCP 降到 2.1s，转化率提升 X%——用监控数据闭环」。**定位 → 分层动手 → 指标验证**的叙事结构比手段罗列值钱。

## 3. 高频追问速答

- **白屏怎么查**：Performance 面板看时间去哪了——TTFB 长查后端/网络；FCP 迟查阻塞资源（CSS/同步 JS）；FCP 到 LCP 间隔大查大图/接口瀑布；
- **秒开的极限手段**：SSR/SSG + 边缘渲染、HTML 流式输出、Service Worker 缓存壳（PWA）、bfcache 命中；
- **加载 waterfall 治理**：减少关键请求链深度（CSS 里 @import 是串行元凶）、接口预取与合并、HTTP/2 下不再需要域名分片与雪碧图。

## 面试问答

### Q: 首屏加载优化有哪些手段？

满分答案：按流水线分四层——网络：预连接、CDN、HTTP/2 + brotli、缓存策略（HTML 协商 + hash 长缓存）；体积：按更新频率分包、Tree Shaking 按需引入、路由懒加载、收紧 browserslist；加载：preload 关键字体与 LCP 图、prefetch 下一页、defer 脚本、图片懒加载；渲染：关键 CSS 内联、SSR/SSG 直出、骨架屏兜感知。收尾强调闭环：Lighthouse/监控定位瓶颈，优化后用 LCP/INP 验证。

### Q: 白屏时间过长怎么排查？

满分答案：先分段归因——Performance 或监控把时间切成 TTFB、FCP、LCP 三段：TTFB 长是后端与网络（缓存、CDN、链路）；TTFB 到 FCP 长是渲染阻塞资源（同步脚本、巨型 CSS、字体阻塞）；FCP 到 LCP 长是主内容资源（大图、数据接口）。每段各有药方，关键是先测量再动手，避免「上来就上 SSR」式的盲目优化。

### Q: SSR、SSG、CSR 怎么选？

满分答案：CSR 交互后加载全靠客户端，首屏最慢但架构最简单，适合后台系统；SSR 每请求服务端渲染 HTML，首屏快、SEO 好，代价是服务器成本与注水复杂度，适合内容 + 交互混合的 toC 页面；SSG 构建期生成静态页，性能天花板且可全量 CDN，适合内容稳定的官网博客文档；实践中用 Next/Nuxt 按页面粒度混用（静态页 SSG + 动态页 SSR + 局部 CSR），再加 ISR 增量再生成兜内容更新。
