# 虚拟列表实现

## TL;DR

**虚拟列表 = 万条数据只渲染视口内的几十条：外层滚动容器 + 一个撑起总高度的占位 + 绝对定位/translate 摆放可见项**。定高版三个数就够（scrollTop 算 startIndex、可视条数算 endIndex、translateY 摆位置）；**不定高版**的核心是「预估高度渲染 → 实测修正缓存 → 二分查找定位」。

---

## 1. 为什么需要

一万条 DOM 直接渲染：节点数爆炸 → 首次渲染与每次回流都不可接受（渲染成本模型见 [[2.03 浏览器渲染原理与回流重绘]]）。虚拟列表把 DOM 数量钉在「可视条数 + 缓冲区」常量级——**用计算换 DOM**。

---

## 2. 定高版（先答这个，结构清晰）

```text
┌ 容器 height:600px overflow:auto ─┐
│ ┌ 占位 div height: 总条数×itemH ┐│ ← 撑出真实滚动条
│ │  ┌ 渲染层 translateY(offset) ┐ ││ ← 只有 start..end 的真实 DOM
└─┴──┴───────────────────────────┴─┴┘
```

```js
const itemH = 50, buffer = 5;
container.addEventListener('scroll', throttle(() => {
  const scrollTop = container.scrollTop;
  const start = Math.max(0, Math.floor(scrollTop / itemH) - buffer);
  const count = Math.ceil(container.clientHeight / itemH) + buffer * 2;
  const end = Math.min(total, start + count);
  renderItems(start, end);                          // 只渲染这一窗
  listEl.style.transform = `translateY(${start * itemH}px)`;  // 摆到正确位置
}, 16));
```

判分点：**占位元素撑滚动条**（总高 = 总条数 × 行高）；**start 由 scrollTop 整除行高**得出；**缓冲区 buffer** 防快速滚动白屏；**transform 摆位**（合成层，不回流，见 [[1.08 CSS 动画与渲染性能]]）；滚动回调节流或 rAF（[[3.02 防抖与节流]]）。

---

## 3. 不定高版（进阶，答思路）

高度依赖内容（动态文本、图片）时 scrollTop / itemH 失效。五步法：

1. **预估高度**建初始位置缓存 `positions = [{height: 预估, top, bottom}]`——先让列表能滚起来；
2. 按预估渲染当前窗口；
3. **渲染后实测**：updated/useEffect 里 `getBoundingClientRect()` 拿每项真实高度，**更新缓存并顺延修正后续项的 top/bottom**；
4. 定位改用**二分查找**：在有序的 positions 里找「bottom ≥ scrollTop 的第一项」作 start（列表位置单调递增，天然适合二分）；
5. 总高度 = 缓存末项的 bottom，动态修正占位高度——滚动条不跳。

再进阶的现实问题：**图片加载引起的二次高度变化**（ResizeObserver 监听每项）、**触底加载更多**（IntersectionObserver 哨兵元素）、快速滚动时的占位骨架。

**生产选型**：react-window / react-virtuoso、vue-virtual-scroller——面试手写定高版 + 讲清不定高思路，工程用库（造轮子的价值在理解滚动、缓存与二分这三件事）。

## 面试问答

### Q: 虚拟列表的原理？手写定高版的关键步骤？

满分答案：只渲染可视区数据，DOM 数量恒定——容器内放一个「总条数×行高」的占位元素撑出真实滚动条，监听滚动：scrollTop 除以行高得 startIndex，可视高度除以行高加缓冲得渲染条数，切片渲染后用 translateY(start×行高) 把渲染层摆到对应位置。判分细节：上下缓冲区防白屏、transform 而非 top 摆位（不回流）、滚动回调 rAF/节流。

### Q: 列表项高度不固定怎么办？

满分答案：预估 + 实测修正——先用预估高度建每项的 {height, top, bottom} 位置缓存，让滚动条先工作；窗口渲染后用 getBoundingClientRect 实测真实高度，更新缓存并顺延修正后续项位置与总高度；查找 start 从「整除」换成在单调的位置数组里二分「第一个 bottom ≥ scrollTop」。补充：内容异步变化（图片）用 ResizeObserver 持续修正。这题核心是缓存结构 + 二分。

### Q: 快速滚动出现白屏怎么优化？

满分答案：多管齐下——加大上下 buffer 让窗口外多渲染几屏；滚动回调用 rAF 对齐渲染帧而非过度节流；渲染不及时的间隙用骨架占位（占位色/骨架条）降低感知；列表项组件做 memo 避免重复渲染开销；极端场景用「滚动停止再精确渲染、滚动中只画骨架」的降级策略。本质是渲染预算和视觉兜底的平衡。
