# React 性能优化清单

## TL;DR

**React 性能优化四个层面，按顺序做：先测量（Profiler 定位）→ 结构优化（状态下沉、children 提升，零成本）→ 记忆化（memo 三件套）→ 加载优化（lazy 分包、虚拟列表、KeepAlive）**。答题忌堆砌名词，要按「减少渲染次数 / 降低渲染成本 / 减少加载体积」分类叙述。

---

## 1. 先测量：DevTools Profiler

React DevTools 的 Profiler 录制交互 → 看火焰图：哪些组件渲染了、渲染了几次、各花多少毫秒；「Highlight updates」直观暴露无谓重渲染。**没有测量的优化都是猜**——这句话本身就是面试加分项。指标口径：交互卡顿看渲染耗时（对应 INP），首屏看包体与请求（见 [[2.02 从输入 URL 到页面展示]] 的流水线）。

---

## 2. 减少渲染次数

**结构优化（免费，优先做）**：

```jsx
// ① 状态下沉：把频变状态圈进小组件，别放在大组件顶层
function Page() {            // ✗ query 一变整页重渲染
  const [query, setQuery] = useState('');
  return <><SearchBox … /><HugeTree /></>;
}
// ✓ 把 query 挪进 SearchBox，HugeTree 与它无关

// ② children 提升：children 引用不变就不重渲染
function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  return <div className={theme}>{children}</div>;  // theme 变时 children 不重渲染
}
```

**记忆化**：React.memo + useMemo/useCallback 配套（准则与陷阱见 [[2.04 记忆化：memo、useMemo 与 useCallback]]）；未来由 React Compiler 自动化（见 [[ReactCompiler]]）。

**精准订阅**：全局状态用带 selector 的方案（见 [[3.01 Redux 原理与取舍]]），避免 Context 一变全更（见 [[1.08 组件通信与 Context]]）。

**列表 key 正确**：错误 key 造成整列表重建（见 [[1.03 Diff 算法与 key]]）。

---

## 3. 降低单次渲染成本

- **虚拟列表**：万级列表只渲染可视区（react-window / react-virtuoso）——「长列表怎么优化」的第一答案；
- **非紧急更新降级**：startTransition/useDeferredValue 让大渲染可中断（见 [[1.05 并发特性与优先级调度]]）；
- 昂贵计算 useMemo 缓存，或挪出渲染路径（Worker，见 [[2.04 并发控制与耗时任务优化]]）；
- 避免渲染期间创建重对象/深拷贝，样式对象、配置常量提到组件外。

---

## 4. 加载与体积优化

**代码分割 React.lazy + Suspense**：

```jsx
const Settings = lazy(() => import('./Settings'));   // 动态 import → 单独 chunk
<Suspense fallback={<Spinner />}>
  <Settings />
</Suspense>
```

按路由分包是基本盘；**路由层的正确姿势**（lazy 直接包路由会白屏闪烁的问题与 route-level lazy 方案）见 [[React Router v7 路由懒加载与切页 UI]]。配合 prefetch 预取下一路由 chunk（见 [[2.04 script 加载与资源提示]]）。

**KeepAlive（缓存页面状态）**：React 没有内置 Vue 的 keep-alive。现状分层答：

- 社区方案 react-activation 等：把「卸载」改为「移出可视区但保留组件树」（Portal/display 控制），副作用要配套「激活/失活」钩子；
- **官方方向：`<Activity>` 组件**（React 19.x 起逐步落地，前身 Offscreen）——原生支持隐藏时保留 state、降低优先级渲染。答出 Activity 说明知识是新的；
- 轻量替代：状态提升到路由外（store/URL 参数），组件重挂载后恢复数据而非保 DOM。

**SSR/RSC 一句话**：首屏性能的框架级方案——服务端渲染出 HTML + 流式传输 + 选择性水合（Next.js 系），React Server Components 让不交互的部分零 JS 下发。按需展开即可。

---

## 5. 答题组织模板

「先用 Profiler 定位 → 渲染次数类：状态下沉、children 提升、memo 配套、selector 订阅、正确 key → 渲染成本类：虚拟列表、transition 降级、useMemo → 加载类：路由分包 lazy+Suspense、资源预取、SSR → 最后提 React Compiler 的自动化趋势」——每类举一个自己项目里的真实例子最加分。

## 面试问答

### Q: React 项目你会怎么做性能优化？

满分答案：按框架分层答——先 Profiler 测量定位，不盲优化；减少渲染次数：状态下沉与 children 提升（零成本优先）、memo/useMemo/useCallback 配套使用、全局状态用 selector 精准订阅、列表 key 稳定；降低渲染成本：长列表虚拟化、非紧急更新用 startTransition、昂贵计算缓存或下 Worker；加载优化：路由级 React.lazy 分包、Suspense 兜底、prefetch 预取、必要时 SSR/RSC。收尾提 React Compiler 将把手工记忆化自动化。

### Q: React.lazy 的原理和使用注意？

满分答案：lazy 接收返回动态 import 的工厂，得到的组件首次渲染时触发 chunk 加载并挂起（suspend），由最近的 Suspense 显示 fallback，加载完成后渲染真身——打包器遇到动态 import 自动切分代码。注意点：必须配 Suspense；加载失败要错误边界兜底；路由层直接用它会导致切页白屏闪烁，route-level lazy（router 在导航期间 await）体验更好；可在鼠标悬停时预调用工厂函数实现预加载。

### Q: React 怎么实现类似 Vue keep-alive 的页面缓存？

满分答案：React 没有内置方案，分三层答——社区库（react-activation）通过不真正卸载、用 Portal/display 隐藏来保留组件树，需处理激活/失活副作用；官方演进是 Activity 组件（前身 Offscreen），原生支持「隐藏但保留 state、后台低优先级渲染」，是未来的标准答案；很多场景更简单的解法是状态提升——把表单/滚动位置存到 store 或 URL，重挂载后恢复，避免缓存整棵树的内存与副作用复杂度。能对比三者取舍即满分。
