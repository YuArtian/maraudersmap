# 合成事件系统

## TL;DR

**React 不把监听器绑在你的元素上，而是在根容器统一委托，事件冒泡上来后包装成跨浏览器一致的合成事件（SyntheticEvent），再沿 Fiber 树模拟捕获与冒泡派发**。React 17 的两大变化必须知道：委托点从 document 挪到根容器、废除事件池。

---

## 1. 机制：委托 + 包装 + 模拟派发

三层设计（动机各不同）：

1. **委托**：所有事件类型只在根容器绑一次（原生事件委托的框架级应用，原理见 [[3.05 事件模型与事件委托]]）——省内存、动态组件免绑定、React 还能在入口按事件类型标记更新优先级（点击 SyncLane、滚动 ContinuousLane，衔接 [[1.05 并发特性与优先级调度]]）；
2. **包装**：原生事件包成 SyntheticEvent，抹平浏览器差异；`e.nativeEvent` 拿原生对象；阻止默认行为必须显式 `e.preventDefault()`（**return false 无效**，这一点与 jQuery/内联 onclick 不同）；
3. **模拟派发**：事件到达根容器后，React 沿触发节点的 fiber 链向上收集 onXxxCapture / onXxx 回调，先反向执行捕获、再正向执行冒泡——React 的「捕获/冒泡」是自己模拟的，不是原生流。

---

## 2. React 16 → 17 的重要变化（高频）

| | React 16 | React 17+ |
|---|---|---|
| 委托挂载点 | **document** | **createRoot 的根容器** |
| 执行顺序 | document捕获 → 原生捕获 → 原生冒泡 → React捕获 → React冒泡（React 两段都在 document 冒泡时才统一跑，顺序怪异） | 捕获阶段真的在捕获期执行：document捕获 → **React捕获** → 原生捕获 → 原生冒泡 → **React冒泡** |
| 事件池 | SyntheticEvent 复用，回调结束后属性清空——异步里读 e 要先 `e.persist()` | **废除**，随便异步读 |

**挂载点迁移的动机**：多版本 React 共存（微前端场景）时，两套框架都在 document 上代理会互相干扰；挪到各自根容器后天然隔离。

**经典 Modal bug**：点击弹窗外关闭——在 document 上挂原生 click 关弹窗，弹窗内容里 React 的 `e.stopPropagation()` 在 16 下**拦不住**那个原生监听（React 冒泡本来就发生在 document 层，得用 `e.nativeEvent.stopImmediatePropagation()`）；17 起委托点在根容器、低于 document，React 里 stopPropagation 就能阻断事件继续冒到 document。这题能完整讲出来等于把机制全打通了。

---

## 3. 使用注意清单

- 合成事件回调里 `e.stopPropagation()` 拦得住 React 事件与更外层原生监听（17+），但**拦不住同节点已触发的原生监听**——混用原生 addEventListener 与 React 事件时要清楚两套系统的次序；
- 原生监听（`ref` + addEventListener）的场景：需要捕获非冒泡事件、需要 `passive: false` 阻止滚动（React 的 onWheel/onTouchMove 默认 passive）、对接非 React 代码；记得在 effect 清理中解绑；
- this 绑定问题是类组件时代的伴生题（见 [[1.06 生命周期与类组件遗产]]）。

## 面试问答

### Q: React 合成事件的原理？为什么要这么设计？

满分答案：三件事——在根容器统一委托监听，把原生事件包装成跨浏览器一致的 SyntheticEvent，然后沿 fiber 树收集回调、自行模拟捕获和冒泡两个阶段派发。动机：委托节省大量监听器并让 React 在入口给不同事件标记更新优先级（并发调度的输入端）；包装抹平兼容性；统一派发让事件行为与组件树（而非真实 DOM 结构）一致，Portal 里的事件也能沿组件树冒泡。

### Q: React 17 对事件系统改了什么？为什么？

满分答案：两点——委托点从 document 迁到应用根容器，为了微前端等多 React 版本共存时互不干扰，也让 stopPropagation 能真正阻止事件冒到 document（修复了「点击外部关闭弹窗」类 bug 在 16 下的反直觉行为）；废除事件池（16 里 SyntheticEvent 复用、异步访问要 e.persist()，17 起不再复用）。另外捕获阶段监听改为真正在原生捕获期执行，顺序更符合直觉。

### Q: 合成事件和原生事件混用会有什么问题？

满分答案：两套系统的执行次序问题——原生监听（尤其挂在 document/window 上的）和 React 委托的回调触发顺序取决于版本和挂载点；React 的 stopPropagation 只能阻止「还没冒泡到的」监听，拦不住已经执行的。原则：能用 React 事件就统一用；必须原生（非冒泡事件、passive 控制、第三方集成）时用 ref + effect 绑定并清理，注意别在两套系统里重复处理同一交互。
