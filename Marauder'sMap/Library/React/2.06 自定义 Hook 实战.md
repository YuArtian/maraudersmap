# 自定义 Hook 实战

## TL;DR

**自定义 Hook = 以 use 开头、内部调用其他 Hook 的函数：复用的是「逻辑」，每处调用的「状态」彼此独立**。面试手写四大件：useDebounce、useWindowSize、useLatest、usePrevious；讲设计则拿 ahooks 的 useRequest 说插件化。

---

## 1. 手写四大件（每个都有判分点）

**useDebounceFn**——防抖一个函数（原理见 [[3.02 防抖与节流]]）：

```ts
function useDebounceFn(fn, delay = 300) {
  const timer = useRef(null);
  const fnRef = useLatest(fn);            // ★ 镜像最新 fn，防闭包过期
  useEffect(() => () => clearTimeout(timer.current), []);  // ★ 卸载清理

  return useCallback((...args) => {
    clearTimeout(timer.current);
    timer.current = setTimeout(() => fnRef.current(...args), delay);
  }, [delay]);
}
```

判分点：timer 放 ref（跨渲染同一个）、返回函数 useCallback 稳定身份、卸载清理、fn 走 ref 避免依赖它导致函数身份频繁变化。姊妹题 useDebounceValue：state + effect 里 setTimeout 更新，返回延迟值。

**useWindowSize**——订阅型 Hook 的模板：

```ts
function useWindowSize() {
  const [size, setSize] = useState({ width: innerWidth, height: innerHeight });
  useEffect(() => {
    const onResize = throttle(() =>
      setSize({ width: innerWidth, height: innerHeight }), 200);
    window.addEventListener('resize', onResize);
    return () => window.removeEventListener('resize', onResize);  // ★
  }, []);
  return size;
}
```

判分点：清理函数必须是 `() => removeEventListener(...)`——**直接写 `return removeEventListener(...)` 是执行了移除并返回 undefined**（源笔记里就是这个经典 bug）；移除时传的必须是**同一个函数引用**。

**useLatest / usePrevious**——两个「一行但常考」：

```ts
const useLatest = (v) => { const r = useRef(v); r.current = v; return r; };

function usePrevious(v) {
  const r = useRef();
  useEffect(() => { r.current = v; });   // 渲染后才写入 → 渲染期间读到的是上一次的
  return r.current;
}
```

useLatest 解闭包陷阱（见 [[2.03 Hooks 闭包陷阱]]）；usePrevious 的巧思在「effect 晚于渲染执行」的时序差。

**批次移交题：用 useReducer 实现 useState**：

```ts
const useMyState = (initial) =>
  useReducer((prev, action) =>
    typeof action === 'function' ? action(prev) : action, initial);
// setState(v) 与 setState(prev => v) 都成立：reducer 里区分动作类型即可
```

本质：useState 就是内置了这个 reducer 的 useReducer——React 源码里 basicStateReducer 正是同款。

## 2. useRequest 的设计（讲架构的题）

ahooks 的 useRequest 把「请求」拆成**内核 + 插件**：

- **内核 Fetcher**：管理 loading/data/error 三态与 run/cancel 生命周期，暴露 onBefore/onRequest/onSuccess/onError/onFinally 钩子；
- **插件**：轮询、防抖节流、缓存与 SWR、重试、依赖刷新、窗口聚焦重新请求……每个插件只实现自己关心的钩子，入口把 `useXxxPlugin` 列表与用户插件合并注入。

答题要点：**单一职责 + 开放封闭**——加能力只加插件不改内核；每个插件本身也是自定义 Hook，体现 Hook 的组合性。对比手写 fetch-in-effect（见 [[2.02 useEffect 与 useLayoutEffect]]），这类库把竞态、缓存、重试等横切关注点标准化了；同类更重的方案是 React Query（服务端状态管理）。

## 3. 设计自定义 Hook 的守则

1. **命名 use 开头**——lint 靠它校验 Hook 规则；
2. 输入输出像普通函数一样显式：参数进、`[state, actions]` 或对象出，别偷偷读全局；
3. 内部副作用必须自带清理（订阅、定时器），做到「即插即拔」；
4. 返回的函数用 useCallback 稳定、返回的对象注意引用稳定性（消费方可能放进依赖数组）；
5. 复用的是逻辑不是状态——需要共享状态时该用 Context/store，不是自定义 Hook（见 [[1.08 组件通信与 Context]]）。

## 面试问答

### Q: 自定义 Hook 是什么？和普通函数、HOC 的区别？

满分答案：以 use 开头、内部可调用其他 Hook 的函数，是有状态逻辑的复用单元；与普通函数的区别是它能持有 state/effect 并受 Hook 规则约束；与 HOC 相比无组件嵌套、数据来源显式、无 props 冲突。关键性质：逻辑复用、状态隔离——每个调用方各有一份独立 state。设计守则：自带清理、输出引用稳定、不隐式依赖全局。

### Q: 手写一个 useDebounce？

满分答案：函数版——timer 存 useRef，返回 useCallback 包装的函数：清旧定时器、设新定时器延迟调用；fn 用 useLatest 镜像避免闭包过期，组件卸载时清理定时器。值版——内部 state，effect 里 setTimeout(setValue) 并在清理中 clearTimeout。主动报判分点：ref 存 timer、清理、函数身份稳定、最新 fn。

### Q: useRequest 这类请求 Hook 是怎么设计的？

满分答案：插件化架构——内核只管请求三态（loading/data/error）与生命周期钩子；轮询、缓存 SWR、防抖、重试、聚焦重请求各自实现为插件 Hook，入口聚合注入。优点：单一职责、加功能不动内核、插件本身可组合可测试。对比裸写 useEffect 请求：库统一解决了竞态取消、缓存共享、错误重试这些横切问题，这也是 React Query 流行的原因。

### Q: 用 useReducer 实现 useState？

满分答案：useReducer 传一个「action 是函数就调用它算新值，否则直接当新值」的 reducer 即可，同时兼容直接赋值和函数式更新两种用法——React 内部的 useState 就是预置了这个 basicStateReducer 的 useReducer。此题考两点：理解两个 Hook 的包含关系，以及函数式更新的分发机制。
