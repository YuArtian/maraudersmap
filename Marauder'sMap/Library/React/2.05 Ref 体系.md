# Ref 体系

## TL;DR

**ref 是「渲染之外的口袋」：useRef 返回跨渲染不变的 `{ current }` 对象，改它不触发渲染**。两大用途：拿 DOM/组件实例做命令式操作；存「不参与渲染的可变值」（定时器 id、最新值镜像）。ref 和 state 的分界：**值变了要不要重新画界面**。

---

## 1. useRef 的本质

```jsx
const ref = useRef(initialValue);   // { current: initialValue }
```

三个特征：**每次渲染返回同一个对象**（这是它与手写 `{current: …}` 字面量的唯一区别——字面量每次渲染都是新的）；**修改 current 不触发重渲染**；它就是个普通可变对象，React 不追踪它。

与 state 对照（高频对比题）：

| | useState | useRef |
|---|---|---|
| 改变触发渲染 | ✅ | ❌ |
| 渲染期间读取 | 当前帧快照 | 不应在渲染期间读写（非受控数据流） |
| 语义 | 参与 UI 的数据 | 不参与 UI 的「实例变量」 |

经验法则：**渲染输出用得到 → state；只有事件/副作用用得到 → ref**。典型 ref 内容：定时器 id、WebSocket 实例、上一次的值、DOM 节点、useLatest 镜像（解闭包陷阱，见 [[2.03 Hooks 闭包陷阱]]）。

惰性初始化昂贵对象的惯用法（useRef 没有 useState 那种惰性初始化参数）：

```jsx
const obRef = useRef(null);
function getObserver() {
  if (obRef.current === null) obRef.current = new IntersectionObserver(cb);
  return obRef.current;    // 只创建一次
}
```

## 2. 获取 DOM 与组件实例

```jsx
const inputRef = useRef(null);
<input ref={inputRef} />          // commit 后 inputRef.current = DOM 节点
inputRef.current.focus();          // 命令式操作：聚焦、滚动、测量、播放
```

ref 绑定对象随目标类型而变：宿主元素 → DOM 节点；类组件 → 组件实例；**函数组件 → 直接传会拿到 null**（没有实例），需要转发。

**回调 ref**：`ref={node => {...}}`——节点挂载时以节点调用、卸载时以 null 调用，适合动态列表逐项收集节点或需要「挂载即测量」的场景。

正当用途清单：焦点/滚动控制、测量尺寸、媒体播放、集成非 React 库（图表、地图）、动画。红线：**不要用 ref 去改 React 管理的 DOM 内容**——两套写入源会打架，那是 state 的事。

## 3. Ref 转发与命令式句柄

函数组件暴露内部 DOM/方法给父组件：

```jsx
const FancyInput = forwardRef(function FancyInput(props, ref) {
  const inputRef = useRef(null);
  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),   // 只暴露白名单方法，而非整个 DOM
    clear: () => (inputRef.current.value = ''),
  }));
  return <input ref={inputRef} {...props} />;
});

// 父组件
const fancyRef = useRef(null);
<FancyInput ref={fancyRef} />;
fancyRef.current.focus();
```

useImperativeHandle 的价值：**收窄命令式接口**——父组件拿到的是受控句柄而非裸 DOM，封装不泄漏。这也是「父组件怎么调用子组件方法」的标准答案（通信全景见 [[1.08 组件通信与 Context]]）。

**React 19 更新**：函数组件的 `ref` 可以直接作为普通 prop 接收，`forwardRef` 不再必需（旧 API 仍兼容）——答题时点一句体现版本意识。

## 面试问答

### Q: useRef 和 useState 的区别？各适合存什么？

满分答案：两者都能跨渲染保存数据，分水岭是「变化要不要反映到 UI」——state 变化触发重渲染、渲染中读到的是该帧快照；ref 是跨渲染同一个 { current } 可变对象，改它不渲染。state 存渲染要用的数据；ref 存实例变量类的东西：定时器 id、外部库实例、DOM 节点、最新值镜像。反模式：用 ref 存 UI 数据然后手动强刷，或在渲染期间读写 ref。

### Q: 怎么在父组件调用子组件（函数组件）的方法？

满分答案：forwardRef 让函数组件接收 ref，配合 useImperativeHandle 暴露一个方法白名单句柄（focus、reset 等），父组件 useRef 拿句柄调用。强调 useImperativeHandle 的封装价值：不泄漏整个 DOM/内部实现。补充 React 19 起 ref 可作为普通 prop 直接传入，forwardRef 逐步退役。同时给出边界：命令式调用是逃生舱，多数需求应优先「状态提升 + props」的声明式方案。

### Q: 回调 ref 是什么？和对象 ref 怎么选？

满分答案：ref 接受函数形式，挂载时以 DOM 节点调用、卸载时以 null 调用。适合：动态列表收集多个节点（配合 Map）、需要在「节点出现的瞬间」做测量或订阅（比 useEffect 更精确地对准挂载时机）。普通的单节点持有用对象 ref 即可。细节：内联回调 ref 每次渲染都是新函数，会经历一次 null 再赋值的过程，需要稳定就用 useCallback 包住。

### Q: 为什么修改 ref.current 不会触发重新渲染？

满分答案：设计使然——ref 就是 React 提供的「渲染系统之外」的可变容器，它不进 fiber 的状态更新队列、没有与之绑定的调度。这保证了高频写入（如动画帧数据、滚动位置）不会引起渲染风暴。推论：ref 的变更 UI 不感知，如果 UI 需要感知就说明选错了工具，应该用 state。
