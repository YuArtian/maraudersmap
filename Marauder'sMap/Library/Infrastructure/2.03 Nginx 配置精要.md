# Nginx 配置精要

## TL;DR

**前端要会的 Nginx 四件事：反向代理（API 转发 + 解决跨域）、静态站托管（root/alias + try_files 兜 history 路由）、HTTPS（强制跳转 + 证书配置）、负载均衡（upstream）**。root 与 alias 的区别一句话：**root 拼接 location 路径，alias 替换 location 路径**。

---

## 1. 正向代理 vs 反向代理

**正向代理代理客户端**（服务器不知道真实用户是谁——翻墙、公司出口网关）；**反向代理代理服务器**（客户端不知道真实后端是谁——Nginx 挡在源站前）。反代的收益：统一入口收敛跨域（见 [[1.06 同源策略与跨域]]）、TLS 终止、负载均衡、静态动态分流、限流与缓存。

---

## 2. 静态站托管：root、alias 与 history 路由

```nginx
server {
  listen 80;
  server_name example.com;

  # root：最终路径 = root + location  →  /data/www/static/a.png
  location /static/ {
    root /data/www;
  }

  # alias：最终路径 = alias 替换 location  →  /data/assets/a.png
  location /static/ {
    alias /data/assets/;    # alias 必须写在 location 里，目录记得带尾斜杠
  }

  # SPA history 模式兜底（见 Vue Router 篇的「刷新 404」）
  location / {
    root /data/www/dist;
    try_files $uri $uri/ /index.html;
    # 配合缓存策略：HTML 不缓存、hash 资源长缓存（见 HTTP 缓存篇）
  }
}
```

**root vs alias 判分句**：root 把 location 部分**拼**进文件路径，可写在 server 级；alias 用自己的路径**替换** location 部分，只能写在 location 内——目录名与 URL 前缀不一致时必须用 alias。

## 3. 反向代理与负载均衡

```nginx
upstream api_servers {
  least_conn;                      # 策略：默认轮询 / weight 加权 / ip_hash 会话粘滞 / least_conn
  server 10.0.0.1:3000 weight=2;
  server 10.0.0.2:3000;
  server 10.0.0.3:3000 backup;     # 备用机
}

server {
  location /api/ {
    proxy_pass http://api_servers/;        # 注意尾部斜杠决定是否剥掉 /api 前缀
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;   # 后端据此识别原始协议
  }

  # WebSocket 代理要额外升级头（见 WebSocket 篇）
  location /ws/ {
    proxy_pass http://api_servers;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
```

`proxy_pass` 尾斜杠细节（高频坑）：`proxy_pass http://up/` **带**斜杠会把 location 前缀剥掉再拼剩余路径；**不带**斜杠则原样透传整个 URI。

## 4. HTTPS 与强制跳转

```nginx
server {                       # 80 端口只做跳转
  listen 80;
  server_name example.com;
  return 301 https://$host$request_uri;    # 现代写法，取代 rewrite/if
}

server {
  listen 443 ssl http2;
  server_name example.com;
  ssl_certificate     /etc/nginx/cert/fullchain.pem;
  ssl_certificate_key /etc/nginx/cert/privkey.pem;
  ssl_protocols TLSv1.2 TLSv1.3;           # ★ 只留现代协议——SSLv3/TLS1.0 早已禁用
  add_header Strict-Transport-Security "max-age=31536000" always;   # HSTS
}
```

时效提醒：老教程里的 `ssl on;` 已废弃（listen 443 ssl 取代）、`ssl_protocols SSLv2 SSLv3` 是安全事故——答题带出「TLS 1.2/1.3 + HSTS」的现代口径（TLS 原理见 [[1.03 HTTPS 与 TLS 握手]]）。

常用杂项：`gzip on`（配 brotli 模块更优）、`expires`/`add_header Cache-Control` 配合前端缓存策略、`limit_req` 限流、`client_max_body_size` 上传上限。

## 面试问答

### Q: 正向代理和反向代理的区别？

满分答案：方向看「代理谁」——正向代理站在客户端一侧，替用户访问外部（出口网关、跨境访问），服务端看不到真实客户端；反向代理站在服务端一侧，替源站接收请求（Nginx 入口层），客户端看不到真实后端。反代的工程价值：统一域名解决跨域、TLS 终止、负载均衡、动静分流、缓存与限流——前端部署几乎都躲不开它。

### Q: nginx 里 root 和 alias 的区别？

满分答案：处理 location 匹配部分的方式不同——root 是拼接：最终路径 = root 值 + 完整 location 路径；alias 是替换：location 匹配的前缀被 alias 值替代，仅剩余部分拼接。因此 URL 前缀与磁盘目录名不一致时必须用 alias；alias 只能出现在 location 内且目录写法注意尾斜杠，root 可以放在 server 级作默认。

### Q: SPA 部署后刷新 404 怎么解决？

满分答案：history 路由的路径在服务器上没有对应文件，刷新是真实请求。Nginx 用 try_files $uri $uri/ /index.html 兜底——静态文件命中则返回，否则回退入口 HTML 由前端路由接管。配套：HTML 设 no-cache、带 hash 的静态资源设长缓存；若应用部署在子路径，前端路由 base 与 location 前缀要对齐。

### Q: Nginx 负载均衡有哪些策略？

满分答案：upstream 默认轮询；weight 加权轮询按机器性能分配；ip_hash 按客户端 IP 粘滞会话（有状态服务的权宜方案，更好的做法是会话外置 Redis）；least_conn 最少连接适合长短请求混合；商业版和三方模块还有一致性哈希。配套要点：proxy_set_header 透传 Host 与 X-Forwarded-For/Proto，backup 标记备用节点，健康检查靠被动失败或三方模块。
