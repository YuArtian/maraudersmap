# 泛型与类型编程

## TL;DR

**泛型 = 类型的参数**：让「类型关系」被保留而不是被 any 抹平。类型编程四件套：**keyof（取键的联合）、条件类型 `T extends U ? X : Y`、infer（在条件类型里捕获类型）、映射类型 `{ [K in Keys]: ... }`**——所有内置工具类型（Partial/Pick/Omit/ReturnType）都是这四件套的组合。

---

## 1. 泛型基础

```ts
function identity<T>(arg: T): T { return arg; }   // T 捕获调用时的类型
identity('hi');            // 推断 T = 'hi'（字面量），返回值类型精确
```

与 any 的本质区别：`any` 把类型信息**扔掉**，泛型把类型信息**留住并传递**——`(arg: any) => any` 的返回值无类型可言，泛型版返回值与入参严格同型。

**泛型约束**（extends 在这里是「限制」不是「继承」）：

```ts
function len<T extends { length: number }>(x: T) { return x.length; }
function pick<T, K extends keyof T>(obj: T, key: K): T[K] { return obj[key]; }
//                  ↑ K 只能是 T 的键，返回值精确到该键的值类型
```

默认值 `<T = string>`、多参数、泛型接口/类/工具类型同理。

---

## 2. 类型编程四件套

```ts
type User = { id: number; name: string; age: number };

// ① keyof：取键的联合类型
type UserKeys = keyof User;              // 'id' | 'name' | 'age'

// ② 索引访问
type NameType = User['name'];            // string

// ③ 条件类型（三元）+ 分发特性
type IsString<T> = T extends string ? true : false;
type R = IsString<'a' | 1>;              // ★ 裸类型参数会「分发」：boolean（true | false）

// ④ infer：在条件类型中捕获
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
type ElementOf<T> = T extends (infer E)[] ? E : never;

// ⑤ 映射类型：遍历键生成新类型
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyReadonly<T> = { readonly [K in keyof T]: T[K] };
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
//                                  ↑ as 重映射键（TS 4.1+）+ 模板字面量类型
```

## 3. 内置工具类型的实现（手写题）

```ts
type Partial<T>       = { [K in keyof T]?: T[K] };
type Required<T>      = { [K in keyof T]-?: T[K] };          // -? 去掉可选修饰
type Readonly<T>      = { readonly [K in keyof T]: T[K] };
type Pick<T, K extends keyof T> = { [P in K]: T[P] };
type Record<K extends keyof any, T> = { [P in K]: T };
type Exclude<T, U>    = T extends U ? never : T;             // 靠条件类型的分发特性
type Extract<T, U>    = T extends U ? T : never;
type Omit<T, K>       = Pick<T, Exclude<keyof T, K>>;        // 组合出来的
type NonNullable<T>   = T & {};                              // 新版实现；老版是 T extends null|undefined ? never : T
type ReturnType<T>    = T extends (...a: any) => infer R ? R : never;
type Parameters<T>    = T extends (...a: infer P) => any ? P : never;
type Awaited<T>       = T extends Promise<infer U> ? Awaited<U> : T;   // 递归解包
```

**Exclude 为什么能过滤联合**：条件类型作用于**裸类型参数**时会分发——`Exclude<'a'|'b', 'a'>` 展开为 `('a' extends 'a' ? never : 'a') | ('b' extends 'a' ? never : 'b')` = `never | 'b'` = `'b'`（never 在联合中被吸收）。这条「分发律」是理解一切联合类型操作的钥匙。

**按值类型过滤键**（经典类型体操，源笔记里的题）：

```ts
type FilterByType<T, V> = Pick<T, {
  [K in keyof T]: T[K] extends V ? K : never    // 命中留 K，否则 never
}[keyof T]>;                                     // ★ 索引取值把「值的联合」取出，never 自动消失
type StringKeys = FilterByType<User, string>;    // { name: string }
```

套路名叫「**映射生成键联合 + 索引访问收集**」——类型体操里出现频率最高的组合技。

---

## 4. 工程价值（别只会体操）

泛型的真实用武之地：**API 层类型贯通**（`request<T>(url): Promise<T>` 让响应类型一路传到业务）、**组件 props 泛型**（表格列与数据行的字段类型联动，写错列名编译报错）、**状态管理与 hooks 的类型推导**。判断标准：**类型代码是为了减少运行时 bug 与提升 IDE 提示，不是炫技**——过度复杂的类型会拖慢编译、劝退同事。

## 面试问答

### Q: 什么是泛型？它比 any 好在哪？

满分答案：泛型是类型层面的参数，让函数/类/类型在使用时才确定具体类型，同时保留类型之间的关系。相比 any：any 直接抹掉类型信息，入参出参失去关联，IDE 无提示、错误漏到运行时；泛型让「传入什么类型就返回什么类型」这条关系被编译器记住。配合 extends 约束（如 K extends keyof T）还能表达「键必须来自这个对象」这类精确契约，是类型安全 API 设计的基础。

### Q: 手写 Pick / Omit / ReturnType？

满分答案：Pick 是映射类型 { [P in K]: T[P] }，K 约束为 keyof T；Omit 是组合——Pick<T, Exclude<keyof T, K>>，其中 Exclude 靠条件类型对裸类型参数的分发特性逐个判断、不匹配的变 never 被联合吸收；ReturnType 用 infer 在条件类型里捕获函数返回类型：T extends (...args: any) => infer R ? R : never。能顺带说明「分发律」和 infer 的位置约束即满分。

### Q: 怎么实现「挑出对象中所有 string 类型的属性」？

满分答案：两步套路——先用映射类型把键筛一遍：值类型匹配就保留键名 K、否则 never；再用 [keyof T] 索引访问把这些键取成联合类型（never 在联合中自动消失）；最后交给 Pick。写作 Pick<T, { [K in keyof T]: T[K] extends V ? K : never }[keyof T]>。这是类型体操里「生成键联合再收集」的标准组合技，理解它就能解一大类过滤题。
