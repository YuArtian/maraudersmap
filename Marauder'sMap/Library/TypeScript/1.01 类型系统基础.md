# 类型系统基础

## TL;DR

**TS 是 JS 的静态类型层，编译期擦除、运行时零负担**。四个特殊类型必须分清：**any（放弃检查，会传染）、unknown（安全的 any，用前必须收窄）、void（没有有意义的返回值）、never（根本不会有值/不会返回）**。TS 的类型系统是**结构化类型**（鸭子类型）——形状匹配即兼容，与 Java 的名义类型截然不同。

---

## 1. 类型全景

基础类型：`number / string / boolean / null / undefined / symbol / bigint`（对应 JS 八种原始类型，见 [[1.01 数据类型与类型判断]]）+ `object`；TS 新增：`any / unknown / void / never / 元组 / 枚举 / 字面量类型`。

**any vs unknown**（高频对比）：

```ts
let a: any = getData();
a.foo.bar();          // ✅ 编译通过，运行时可能崩 —— any 是「关掉检查」

let u: unknown = getData();
u.foo;                // ❌ 编译报错 —— unknown 是「我还不知道，你先证明」
if (typeof u === 'string') u.toUpperCase();   // ✅ 收窄后可用
```

结论：**外部输入（接口响应、JSON.parse、第三方库）用 unknown 而非 any**——它强制你在使用前做类型收窄，把风险挡在编译期。any 的真正问题是**传染性**：一个 any 会顺着调用链把类型安全一路污染掉。

**void vs never**：

| | void | never |
|---|---|---|
| 含义 | 函数没有有意义的返回值（实际返回 undefined） | 函数**永不正常返回**：抛异常、死循环 |
| 可赋值性 | 可接受 undefined | **不能赋任何值**；但 never 可赋给任何类型（底类型） |
| 典型 | `function log(): void {}` | `function fail(): never { throw new Error() }` |

never 的实用价值是**穷尽性检查**（switch 漏分支时编译报错）：

```ts
type Shape = Circle | Square;
function area(s: Shape) {
  switch (s.kind) {
    case 'circle': return Math.PI * s.r ** 2;
    case 'square': return s.w ** 2;
    default:
      const _exhaustive: never = s;   // ★ 新增 Shape 成员却忘了处理 → 这行编译报错
      return _exhaustive;
  }
}
```

## 2. 数组与元组

```ts
const arr: number[] = [1, 2, 3];              // 等价 Array<number>
const tuple: [age: number, ok: boolean] = [18, false];   // 固定长度 + 固定位置类型
```

元组的三个考点：**固定长度与顺序**（越界索引访问报错）；**具名元素只是提示**——`tuple['age']` 取不到值（编译产物就是普通数组，标签只服务于 IDE）；`push` 等方法**能绕过长度限制**（TS 的已知短板），需要严格约束用 `readonly [number, boolean]`。

实战：元组是 `useState` 返回 `[value, setValue]` 这类 API 的类型基础。

## 3. 类型断言与收窄

```ts
const el = document.getElementById('app') as HTMLDivElement;   // as 语法
// <HTMLDivElement>x 的尖括号写法在 .tsx 里与 JSX 冲突，一律用 as
el!.focus();                     // ! 非空断言：我保证它不是 null
```

**断言不是类型转换**——它只是「我比编译器更清楚」的单方面声明，错了运行时照样崩。更安全的替代是**类型收窄（narrowing）**：`typeof`、`instanceof`、`in`、字面量比较，以及**自定义类型守卫**：

```ts
function isUser(x: unknown): x is User {        // 返回类型是「类型谓词」
  return typeof x === 'object' && x !== null && 'id' in x;
}
if (isUser(data)) data.id;                       // 收窄成功，此处 data 是 User
```

对配置对象「既想校验又想保留字面量推断」的场景，用 **satisfies**（见已有笔记 [[satisfies 操作符]]）——它是 as 与类型注解之外的第三条路。

**strictNullChecks**（tsconfig 里最重要的开关）：开启后 null/undefined 不再能随意赋给其他类型，必须显式处理——这是 TS 防「undefined is not a function」的核心防线，新项目必开（配置见 [[1.05 模块、配置与工程实践]]）。

## 面试问答

### Q: any 和 unknown 的区别？

满分答案：都能接收任意值，区别在「取用时」——any 关闭全部检查，任何属性访问和调用都放行且会顺着数据流传染，把类型安全一路侵蚀；unknown 是类型安全的 any，赋值随意但使用前必须收窄（typeof/instanceof/类型守卫）才能操作。工程准则：外部边界数据（接口响应、JSON.parse、第三方库返回）一律用 unknown 加运行时校验（zod 等），any 只在迁移过渡期临时用并留 TODO。

### Q: void 和 never 的区别？never 有什么实际用途？

满分答案：void 表示函数没有有意义的返回值，实际返回 undefined，变量可以接受 undefined；never 表示「不可能有值」——函数抛异常或死循环永不正常返回，不能给 never 变量赋任何值，但 never 可赋给任意类型（它是底类型）。实用价值是穷尽性检查：switch 的 default 分支把联合类型的剩余值赋给 never 变量，日后给联合类型加成员却漏处理时编译立即报错——用类型系统守住分支完整性。

### Q: 类型断言和类型收窄有什么不同？

满分答案：断言（as / 非空 !）是开发者单方面向编译器宣称类型，编译器让路但不做验证，判断错了运行时照样出错；收窄是编译器基于代码逻辑（typeof、instanceof、in、字面量比较、自定义类型守卫函数返回 x is T）自动推导出更精确的类型，安全且可验证。原则：优先收窄，断言仅用于「编译器确实拿不到信息」的场景（如 DOM 查询结果），且尽量配合运行时校验。
