# 类、枚举与装饰器

## TL;DR

**extends 是继承（类继承类、接口继承接口或类），implements 是「声明我符合这个契约」（类实现接口，只做校验不带实现）**。**enum 编译产物是一个带双向映射的对象**（`Direction[1] === 'Up'`），`const enum` 直接内联无运行时对象。**装饰器 = 运行时执行的包装函数**，配合 Reflect Metadata 实现依赖注入这类元编程。

---

## 1. extends vs implements

| 关系 | 合法 | 语义 |
|---|---|---|
| 类 extends 类 | ✔ | 继承实现（单继承） |
| 类 implements 接口/类 | ✔（可多个） | **只校验形状**，不继承任何实现 |
| 接口 extends 接口/类 | ✔（可多个） | 接口继承；继承类时只取**实例的属性与方法**（构造函数、静态成员不算） |
| 类 extends 接口 | ✘ | 接口没有实现可继承 |

```ts
class Car extends Vehicle implements Alarm, Light { … }   // 单继承 + 多实现
```

关键澄清：由于 TS 是**结构化类型**（见 [[1.02 interface 与 type]]），不写 implements 也能通过形状兼容——**implements 的价值是「提前报错」**：在类定义处就校验契约，而不是等到赋值给某个类型时才发现少了方法。

## 2. enum 的编译产物

```ts
enum Direction { Up = 1, Down, Left, Right }   // 数字枚举自动递增
```

编译后（原理必背）：

```js
var Direction;
(function (Direction) {
  Direction[Direction["Up"] = 1] = "Up";   // ★ 一行做两件事：正向 Up→1，反向 1→'Up'
  Direction[Direction["Down"] = 2] = "Down";
})(Direction || (Direction = {}));
```

拆解那行赋值：`Direction["Up"] = 1` 是表达式，值为 1，于是外层变成 `Direction[1] = "Up"`——**双向映射一行搞定**。注意：**只有数字枚举有反向映射，字符串枚举没有**（没法反查）。

```ts
const enum Level { Low, High }      // const enum：编译期内联，产物里没有对象
const x = Level.High;               // → const x = 1;
```

取舍：const enum 省运行时对象但**不支持反向映射、与 isolatedModules/Babel 单文件转译冲突**（Babel 不做跨文件类型分析，无法内联）；现代替代方案是 **`as const` 对象 + 联合类型**——零运行时、类型更灵活、Tree Shaking 友好：

```ts
const Level = { Low: 0, High: 1 } as const;
type Level = typeof Level[keyof typeof Level];   // 0 | 1
```

## 3. 装饰器

**现状要说准**（时效关键）：TS 长期提供的是 `experimentalDecorators` 的旧版实现；**TC39 标准装饰器已到 Stage 3，TypeScript 5.0 起原生支持标准版（不需要 experimental 开关）**，两套语义有差异（参数装饰器、metadata 的支持时间线不同）——回答时注明用的是哪一套（见 [[1.06 继承与 class]] 的装饰器现状）。

四类装饰器与本质：

```ts
function Log(target: any, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (...args: any[]) {     // 包装原方法
    console.log(`call ${key}`, args);
    return original.apply(this, args);
  };
}
class Service { @Log fetch(id: string) { … } }
```

装饰器就是**在类定义时执行的函数**，拿到目标（类/原型/属性描述符）后做增强——本质是「[[1.07 对象属性与属性描述符]] 的编程式改写」。

**执行顺序**（考点）：装饰器工厂表达式**自上而下求值**，实际装饰函数**自下而上执行**——洋葱模型（同 [[1.03 中间件原理：Express、Koa 与洋葱模型]]）。同一个类中的顺序：参数装饰器 → 方法/访问器/属性装饰器 → 类装饰器（先成员后类）。

**Reflect Metadata 与依赖注入**：`emitDecoratorMetadata` 让 TS 把参数类型信息写进元数据，装饰器在运行时用 `Reflect.getMetadata('design:paramtypes', Target)` 读出构造函数参数类型 → **容器据此自动实例化并注入依赖**——这就是 NestJS/Angular DI 的原理内核。

## 面试问答

### Q: extends 和 implements 的区别？

满分答案：extends 建立继承关系——类继承类（获得实现，单继承）、接口继承接口或类（继承类时只取实例成员，不含构造与静态）；implements 只是声明「本类满足该契约」，编译器校验形状但不提供任何实现，可以同时实现多个。类不能 extends 接口。补充关键点：TS 是结构化类型，不写 implements 也能形状兼容，implements 的价值在于在类定义处提前报错而不是使用处才暴露。

### Q: TS 的 enum 编译成什么？const enum 有什么区别？

满分答案：数字枚举编译成 IIFE 里逐项赋值的对象，利用 `obj[obj["Up"] = 1] = "Up"` 的表达式返回值同时建立正反双向映射，因此支持 Direction[1] 反查名字；字符串枚举没有反向映射。const enum 在编译期把引用直接内联成字面量、不产出运行时对象，但不支持反查、且与 Babel/isolatedModules 单文件转译不兼容。现代推荐用 as const 对象加 typeof + keyof 派生联合类型：零运行时、Tree Shaking 友好。

### Q: 装饰器的原理和执行顺序？

满分答案：装饰器是在类定义时执行的函数，接收类构造器、原型、属性名与属性描述符，通过替换描述符的 value 或返回新构造器实现增强，编译后由 __decorate 辅助函数按序调用。顺序规则：装饰器工厂表达式自上而下求值，装饰函数自下而上应用（洋葱模型）；成员装饰器先于类装饰器。现状要说明：TS 5.0 起支持 TC39 Stage 3 的标准装饰器，与旧的 experimentalDecorators 语义不同，选用哪套要在 tsconfig 里明确。

### Q: NestJS/Angular 的依赖注入是怎么实现的？

满分答案：装饰器 + Reflect Metadata。开启 emitDecoratorMetadata 后，TS 在编译时把构造函数参数的类型信息以 design:paramtypes 元数据写入；@Injectable 等装饰器在运行时用 Reflect.getMetadata 读出这些类型，DI 容器据此递归解析并实例化依赖后注入。所以 DI 的「魔法」由三部分组成：装饰器提供挂载点、编译器提供类型元数据、容器负责实例化与生命周期管理。
