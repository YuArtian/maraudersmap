# fetch 与 XHR

## TL;DR

**XHR 是回调风格的老 API，fetch 是 Promise 风格的现代标准**。fetch 的三个「反直觉」必须记牢：**404/500 不会 reject（只看网络层成败，用 response.ok 判断）**、默认不带跨域 Cookie（credentials）、原生没有超时和进度（超时用 AbortSignal.timeout，上传进度只能回退 XHR）。

---

## 1. XHR：理解它才能懂封装的由来

```js
function request(method, url, data) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open(method, url, true);          // 第三参 async
    xhr.timeout = 5000;
    xhr.responseType = 'json';
    xhr.withCredentials = true;           // 跨域带 Cookie
    xhr.onreadystatechange = () => {
      if (xhr.readyState !== 4) return;   // 0~4：UNSENT→OPENED→HEADERS→LOADING→DONE
      if (xhr.status >= 200 && xhr.status < 300) resolve(xhr.response);
      else reject(new Error(`HTTP ${xhr.status}`));
    };
    xhr.ontimeout = () => reject(new Error('timeout'));
    xhr.onerror = () => reject(new Error('network error'));
    xhr.upload.onprogress = (e) => {      // 上传进度：fetch 至今做不到
      if (e.lengthComputable) console.log(e.loaded / e.total);
    };
    xhr.send(data ? JSON.stringify(data) : null);
  });
}
```

XHR 的独门能力：**上传进度**（`xhr.upload.onprogress`）、同步模式（别用）、`abort()` 原生自带。axios 的浏览器端底层长期就是这套封装（axios 1.x 起也支持 fetch adapter）。

## 2. fetch：现代标准与它的坑

```js
const controller = new AbortController();

async function request(url, options = {}) {
  const res = await fetch(url, {
    method: 'GET',
    credentials: 'include',          // 坑②：默认 same-origin，跨域 Cookie 要显式开
    signal: AbortSignal.timeout(5000),  // 坑③的现代解法：标准超时信号
    headers: { 'Content-Type': 'application/json' },
    ...options,
  });
  if (!res.ok) {                     // 坑①：404/500 不 reject，必须自己判
    throw new Error(`HTTP ${res.status} ${res.statusText}`);
  }
  return res.json();                 // body 是流，json()/text() 只能消费一次
}
```

fetch 的特性清单：

- **只有网络故障/跨域拦截/中止才 reject**；HTTP 错误码算「成功收到响应」，用 `res.ok`（200–299）判断；
- **取消**：AbortController 的 signal 传入，`controller.abort()` 中止；超时直接用 `AbortSignal.timeout(ms)`（现代浏览器已支持，老代码里的 Promise.race + setTimeout 手法可以退休，但要能讲出来）；
- **Response.body 是 ReadableStream**：可以流式消费——AI 打字机效果、大文件边下边处理靠它；body 只能读一次，要复用先 `res.clone()`；
- 下载进度可以靠读流累计字节数实现；**上传进度至今没有**（需要进度条的上传场景回退 XHR/axios）；
- cache、redirect、referrerPolicy、keepalive（页面卸载时发日志，替代 sendBeacon 的场景）等细粒度控制。

## 3. 对比总表

| | XHR | fetch |
|---|---|---|
| 风格 | 事件回调 | Promise / async-await |
| HTTP 错误 | 自己判 status | 同样自己判（res.ok），**不会 reject** |
| 跨域 Cookie | withCredentials | credentials: 'include' |
| 超时 | 原生 xhr.timeout | AbortSignal.timeout() |
| 取消 | xhr.abort() | AbortController |
| 上传进度 | ✓ upload.onprogress | ✗ |
| 下载流式 | ✗（等完整响应） | ✓ ReadableStream |
| 可用环境 | 浏览器 | 浏览器 + Node 18+ + Worker/Service Worker（拦截请求的基础） |

## 4. 封装一个请求库要考虑什么（开放题提纲）

统一入口（baseURL、默认头、序列化）→ **拦截器**（请求：注入 token；响应：统一错误码处理、401 跳登录/静默刷新 token）→ 超时与取消（组件卸载时 abort，路由切换批量取消）→ 重试（幂等请求 + 指数退避）→ 防重复提交（相同请求签名去重）→ 错误上报。答题时按这个流水线讲，每一环给一个实际例子。

## 面试问答

### Q: fetch 和 XHR 的区别？

满分答案：fetch 是 Promise 风格的现代标准，支持流式响应、AbortController 取消、Service Worker 环境；XHR 是事件回调风格，但有 fetch 缺的上传进度。fetch 三个易错点要主动说：HTTP 错误状态不 reject（只看网络层，需判 res.ok）、跨域凭据默认不带（credentials: 'include'）、原生超时用 AbortSignal.timeout。工程上一般用 axios 等库统一封装，其浏览器底层历史上基于 XHR。

### Q: fetch 为什么 404 不报错？怎么正确处理错误？

满分答案：fetch 的 Promise 语义是「网络往返是否完成」——404/500 说明请求成功到达并收到响应，所以 resolve；只有 DNS 失败、断网、CORS 拦截、abort 才 reject。正确姿势：先 catch 网络层错误，再用 res.ok / res.status 分支处理业务层错误，封装时把两类错误归一成统一的错误对象抛出。

### Q: 如何取消一个请求？如何实现超时？

满分答案：AbortController——signal 传给 fetch，abort() 触发 reject（AbortError），XHR 用 xhr.abort()。超时的现代答案是 AbortSignal.timeout(ms) 一行搞定；组合场景（手动取消 + 超时同时要）用 AbortSignal.any。旧写法 Promise.race 包一个 setTimeout 的 reject——注意它只是「不等了」，请求仍在飞，真正中止还是要 abort。应用：组件卸载、路由切换、搜索框连续输入时取消上一次请求。

### Q: 大文件上传/下载的进度怎么做？

满分答案：上传进度只有 XHR 能做——xhr.upload.onprogress 的 loaded/total；这是 fetch 目前的能力空白，需要进度条的上传用 XHR 或 axios。下载进度 fetch 反而更强：读 response.body 的 ReadableStream，按 chunk 累计字节数对比 Content-Length，还能顺便实现流式渲染（如 AI 逐字输出）。
