# 排行榜（Leaderboard）查询模式

## TL;DR

**做排行榜会反复遇到 5 个 SQL 模式，背下来就能套：分组取最高、Top N + 当前用户、upsert、版本标志位、Window 函数排名。**

- 分组取最高分：`GROUP BY ... MAX(score)` 或 `DISTINCT ON`
- Top N + 当前用户：两次查询 `UNION` 或 CTE + `WHERE rank ≤ N OR user_id = ?`
- baseline 数据导入：`INSERT ... ON CONFLICT DO UPDATE`（upsert）
- 多版本数据集：`isLatest` 标志位 vs 子查询 `MAX(version)` 的权衡
- 多维度排名融合：`ROW_NUMBER() OVER (PARTITION BY ...)` + Borda/RRF

---

## 1. 分组取最高分

**场景**：一个用户对同一个智能体可能跑很多次，榜单只展示最高分那次。

### 方法 A：GROUP BY + MAX

```sql
SELECT user_id, agent_name, MAX(total_score) AS best_score
FROM submission
WHERE status = 'COMPLETED' AND is_public = true
GROUP BY user_id, agent_name;
```

简单直接，但**只能拿到聚合后的分数**，拿不到这条 submission 的其他字段（如 created_at、report_data）。

### 方法 B：DISTINCT ON（PostgreSQL 专属）

```sql
SELECT DISTINCT ON (user_id, agent_name)
  *
FROM submission
WHERE status = 'COMPLETED' AND is_public = true
ORDER BY user_id, agent_name, total_score DESC;
```

拿到完整行。`DISTINCT ON (...)` 按括号里的列分组，`ORDER BY` 决定每组保留哪一条。

### 方法 C：Window 函数（跨方言）

```sql
WITH ranked AS (
  SELECT *,
         ROW_NUMBER() OVER (
           PARTITION BY user_id, agent_name
           ORDER BY total_score DESC
         ) AS rn
  FROM submission
  WHERE status = 'COMPLETED' AND is_public = true
)
SELECT * FROM ranked WHERE rn = 1;
```

| 方法 | 优点 | 缺点 |
|------|------|------|
| GROUP BY + MAX | 通用、性能好 | 拿不到完整行 |
| DISTINCT ON | 语法极简 | 只 PG 有 |
| Window 函数 | 通用、能拿完整行、能处理"取前 3" | 语法稍复杂 |

## 2. Top N + 当前用户

**场景**：榜单只展示前 10 名，但当前登录用户即使排第 200 也要显示自己。

### 方法 A：两次查询 UNION

```sql
-- top 10
(SELECT * FROM ranked_submissions ORDER BY rank LIMIT 10)
UNION
-- 当前用户行
(SELECT * FROM ranked_submissions WHERE user_id = :me);
```

简单清晰，可能产生重复（self 已在 top 10 里），需要 `DISTINCT` 或后端去重。

### 方法 B：CTE 一次查

```sql
WITH ranked AS (
  SELECT *,
         ROW_NUMBER() OVER (ORDER BY overall_score DESC) AS rank
  FROM leaderboard_view
)
SELECT * FROM ranked
WHERE rank <= 10 OR user_id = :me
ORDER BY rank;
```

一次查询解决，自动去重。**推荐方法。**

### 边界处理

| 情况 | 处理 |
|------|------|
| self 已在 top 10 | CTE 方法自动去重，UNION 方法靠 `UNION`（去重）而非 `UNION ALL` |
| 未登录用户 | 跳过 self 行查询，只查 top N |
| self 没有任何提交 | 返回 `self = null`，前端不渲染 self 行 |

## 3. baseline 数据 upsert

**场景**：seed 脚本要把官方 baseline 模型的分数注入榜单，且支持重复跑（覆盖更新）。

### PostgreSQL：ON CONFLICT

```sql
INSERT INTO submission (user_id, agent_name, dataset_id, total_score, report_data)
VALUES (:user_id, :agent_name, :dataset_id, :score, :report)
ON CONFLICT (user_id, agent_name, dataset_id)
DO UPDATE SET
  total_score = EXCLUDED.total_score,
  report_data = EXCLUDED.report_data,
  updated_at = NOW();
```

前提：在 `(user_id, agent_name, dataset_id)` 上建了 `UNIQUE` 约束。

### Prisma 等价写法

```ts
await prisma.submission.upsert({
  where: {
    userId_agentName_datasetId: {
      userId, agentName, datasetId,
    },
  },
  create: { ..., totalScore, reportData },
  update: { totalScore, reportData },
});
```

`userId_agentName_datasetId` 是 Prisma 根据 schema 中的 `@@unique([userId, agentName, datasetId])` 自动生成的复合键名。

### upsert 而非 insert 的好处

| 维度 | INSERT | UPSERT |
|------|--------|--------|
| 重跑 seed 脚本 | 重复记录 / 主键冲突报错 | 自动更新 |
| baseline 改进数据 | 要先 DELETE 再 INSERT，两步事务 | 一步搞定 |
| 并发安全 | 需要事务包裹 | 数据库原子操作 |

## 4. 多版本数据集：isLatest vs 子查询

**场景**：评测数据集有版本号（如 `full-20260417` → `full-20260520`），榜单只展示最新版的分数。

### 方法 A：isLatest 标志位

```sql
-- schema
CREATE TABLE dataset (
  id          SERIAL PRIMARY KEY,
  batch       TEXT NOT NULL,         -- full-20260520
  is_latest   BOOLEAN DEFAULT false,
  ...
);

CREATE UNIQUE INDEX idx_latest_per_bench
  ON dataset (eval_benchmark)
  WHERE is_latest = true;            -- 部分索引：每个 benchmark 最多一个 latest

-- 查询
SELECT s.* FROM submission s
JOIN dataset d ON s.dataset_id = d.id
WHERE d.is_latest = true;
```

更新版本时：

```sql
BEGIN;
UPDATE dataset SET is_latest = false WHERE eval_benchmark = 'medhall';
UPDATE dataset SET is_latest = true  WHERE id = :new_dataset_id;
COMMIT;
```

### 方法 B：子查询取最新

```sql
SELECT s.* FROM submission s
JOIN dataset d ON s.dataset_id = d.id
WHERE d.id IN (
  SELECT DISTINCT ON (eval_benchmark) id
  FROM dataset
  ORDER BY eval_benchmark, created_at DESC
);
```

### 权衡

| 维度 | isLatest 标志位 | 子查询 |
|------|-----------------|--------|
| 查询性能 | 快（直接索引） | 慢（每次跑子查询） |
| 写入复杂度 | 切换版本要事务 | 写入无副作用 |
| 出错风险 | 忘记切 isLatest，全榜空 | 无 |
| 历史版本展示 | 自动隐藏 | 自动隐藏 |
| 并发切换 | 短暂双 true 风险（事务可控） | 无 |

**经验**：读多写少（榜单天然是这样）用 isLatest 标志位 + 部分索引最划算。

## 5. 多维度排名融合

**场景**：智能体在 ESL-Bench 和 MedHall-Bench 上各有总分，想给出综合排名。直接相加会被尺度大的项拉偏。

### 第一步：用 Window 函数算每个维度的 rank

```sql
WITH per_bench AS (
  SELECT
    agent_name,
    'esl'    AS bench, esl_score    AS score,
    ROW_NUMBER() OVER (ORDER BY esl_score    DESC NULLS LAST) AS rank
  FROM agent_scores
  WHERE esl_score IS NOT NULL
  UNION ALL
  SELECT
    agent_name,
    'medhall' AS bench, medhall_score AS score,
    ROW_NUMBER() OVER (ORDER BY medhall_score DESC NULLS LAST) AS rank
  FROM agent_scores
  WHERE medhall_score IS NOT NULL
)
```

### 第二步：融合

**Borda count**（第 k 名得 N-k+1 分）：

```sql
SELECT agent_name,
       SUM((SELECT COUNT(*) FROM agent_scores) - rank + 1) AS borda_score
FROM per_bench
GROUP BY agent_name
ORDER BY borda_score DESC;
```

**RRF (Reciprocal Rank Fusion)**，c 取 60 是经验值：

```sql
SELECT agent_name,
       SUM(1.0 / (rank + 60)) AS rrf_score
FROM per_bench
GROUP BY agent_name
ORDER BY rrf_score DESC;
```

| 方法 | 公式 | 特点 |
|------|------|------|
| Borda | `Σ (N - rank + 1)` | 线性，每名差距均匀 |
| RRF | `Σ 1/(rank + 60)` | 头部权重大，长尾压扁，抗噪 |

### 处理"未参评"

某个智能体只参加了 ESL，没参加 MedHall，怎么算综合分？

| 策略 | 实现 | 后果 |
|------|------|------|
| 给最差 rank | `COALESCE(rank, N+1)` | 严厉惩罚，鼓励全参与 |
| 忽略缺项 | 只对已参评维度算 | 偏袒参评少的（rank 高的概率大） |
| 平均 rank | 缺项算 `(N+1)/2` | 居中折中 |

## 6. 性能注意事项

| 模式 | 必要索引 |
|------|---------|
| 分组取最高 | `(user_id, agent_name, total_score DESC)` 覆盖索引 |
| Top N | `(overall_score DESC)`，配合 `LIMIT` |
| 多版本 isLatest | 部分索引 `WHERE is_latest = true` |
| upsert | `(user_id, agent_name, dataset_id)` UNIQUE |
| Window 函数 | `PARTITION BY` 字段建索引，否则全表排序 |

**常见坑**：

- `WHERE` 条件用了函数包裹列（如 `LOWER(name) = 'x'`）→ 索引失效，要么建表达式索引，要么提前规范化数据
- `ORDER BY rank LIMIT 10` 看起来快，但如果 rank 是 CTE 算出来的，整个 CTE 都得物化
- `UNION` 会去重（隐式 DISTINCT），数据量大时慢；能用 `UNION ALL` 就用
