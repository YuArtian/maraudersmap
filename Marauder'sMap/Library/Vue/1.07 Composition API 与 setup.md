# Composition API 与 setup

## TL;DR

**组合式 API 解决 Options API 的「关注点被选项切碎」：同一功能的状态、计算、副作用聚在一起，还能抽成可复用的组合式函数（composable）**。`<script setup>` 是编译时语法糖：顶层绑定直接进模板、编译期宏（defineProps/defineEmits/defineModel）零运行时。心智对照：composable 之于 Vue ≈ 自定义 Hook 之于 React，但**只执行一次、无闭包陷阱**。

---

## 1. 为什么需要组合式 API

Options API 的问题在**大组件**上爆发：一个「搜索 + 分页」功能的代码被拆进 data、computed、methods、watch、mounted 五个选项——阅读要上下跳，抽离复用更难（Vue 2 时代的 mixin 三宗罪：来源不清、命名冲突、隐式耦合，与 HOC 的问题同构，见 [[2.01 Hooks 原理与规则]]）。

组合式 API 按**功能**组织代码，并把复用单元定义为**组合式函数**：

```ts
// useSearch.ts —— 状态+逻辑打包，来源清晰、可组合、天然 TS 友好
export function useSearch(fetcher) {
  const query = ref('');
  const results = ref([]);
  const loading = ref(false);
  watch(query, async (q, _, onCleanup) => {
    loading.value = true;
    const ctrl = new AbortController();
    onCleanup(() => ctrl.abort());        // 竞态清理
    results.value = await fetcher(q, ctrl.signal);
    loading.value = false;
  });
  return { query, results, loading };     // 返回 ref 便于解构（见 1.02）
}
```

三大收益背下来：**逻辑聚合**（同一功能不再散落）、**复用无损**（composable 替代 mixin，来源显式）、**类型推导完整**（比 Options 的 this 类型体操好一个时代）。

## 2. setup 与 `<script setup>`

`setup()` 是组合式 API 的入口函数：在**组件实例创建前**执行（早于所有 Options 钩子），返回的对象暴露给模板。SFC 里用 **`<script setup>`** 语法糖，普通 script 与它的关键差异：**普通 script 模块级只执行一次，setup 代码每次组件实例化都执行**。

`<script setup>` 的编译期福利：

- 顶层变量/函数/导入**直接可用于模板**，无需 return；
- **编译宏**（不需要导入、编译后消失）：`defineProps`/`defineEmits`（支持纯 TS 类型声明）、`defineExpose`（默认封闭，显式暴露给父 ref）、`defineModel`（3.4+，双向绑定样板一行）；
- 性能红利：模板编译成同作用域渲染函数，跳过渲染上下文代理。

生命周期映射（高频表格）：`onMounted`/`onUpdated`/`onUnmounted` 等在 setup 里注册；**beforeCreate/created 没有对应物——setup 本身就在那个时机**。

## 3. 与 React Hooks 对比（超高频）

| | Vue composable | React Hook |
|---|---|---|
| 执行次数 | **setup 只跑一次**，响应式系统追踪更新 | 每次渲染重新执行函数体 |
| 调用约束 | 无顺序限制，可条件调用 | 只能顶层按固定顺序（链表定位，见 [[2.01 Hooks 原理与规则]]） |
| 闭包陷阱 | 基本不存在（ref 是稳定容器，取 .value 即最新） | 常见（快照捕获，见 [[2.03 Hooks 闭包陷阱]]） |
| 记忆化 | 不需要 useMemo/useCallback（依赖追踪自动精确） | 需要（或 React Compiler） |
| 代价 | .value 心智、响应式边界（解构丢失） | 依赖数组心智 |

根因一句话：**Vue 靠响应式系统在「数据层」追踪变化，函数只建一次；React 靠重新执行「组件函数」产出新快照**——各自的一切优缺点都从这里长出来。

---

## 4. Vue 3 的优点（综合答法提纲）

面试问「Vue 3 比 Vue 2 好在哪」，按四层组织：**响应式**——Proxy 替代 defineProperty（惰性深代理、增删/下标/Map/Set 全支持，见 [[1.02 Vue 3 响应式原理]]）；**编译**——静态提升、patch flags、block tree（见 [[1.03 模板编译与静态优化]]）；**架构**——组合式 API + 完整 TS 支持 + 源码 ESM 模块化可摇（@vue/reactivity 可独立用）；**新能力**——Fragment 多根、Teleport（弹层挂 body）、Suspense（异步组件等待）、参数化多 v-model。

## 面试问答

### Q: 为什么要用组合式 API？相比 Options API 好在哪？

满分答案：Options API 把一个功能的代码切碎到 data/computed/methods/watch 各选项，大组件里同一逻辑上下横跳，复用只能靠 mixin（来源不清、命名冲突）。组合式 API 按功能聚合代码，复用单元是组合式函数——显式导入、参数返回值清晰、可嵌套组合，且对 TS 的类型推导是完整的。小组件用 Options 依然没问题，规模和复用需求是分水岭。

### Q: script setup 相比 setup() 函数有什么优势？

满分答案：编译时语法糖四件事——顶层绑定自动暴露给模板省掉 return；defineProps/defineEmits 等编译宏支持纯类型声明、零运行时；模板编译进同一作用域跳过上下文代理，性能更好；配合 defineExpose 默认封闭组件内部。另一个易忽略差异：普通 script 只在模块加载时执行一次，setup 代码每次实例化执行——放实例状态的位置必须在 setup 里。

### Q: Vue 的 composable 和 React Hook 有什么本质区别？

满分答案：执行模型不同——setup 与 composable 只执行一次，状态装在 ref/reactive 这些稳定容器里，由响应式系统精确追踪更新，所以没有调用顺序限制、可条件调用、几乎无闭包陷阱、不需要 useMemo/useCallback；React 组件函数每次渲染重跑，Hook 靠调用顺序在链表上定位状态，闭包捕获快照带来陷阱、引用稳定要手工记忆化。代价对调：Vue 付出 .value 与响应式边界的心智，React 付出依赖数组的心智。

### Q: Vue 3 相比 Vue 2 有哪些提升？

满分答案：四层框架答——响应式：Proxy 惰性代理，新增/删除/数组下标/Map/Set 天然支持，初始化不再全量递归；编译：静态提升、patch flags、block tree 让更新成本只与动态节点相关；工程：组合式 API 解决逻辑复用与 TS 支持，源码 ESM 化可 tree shaking；能力：Fragment、Teleport、Suspense、参数化多 v-model。每层能展开细节（如被追问 Proxy 就切到响应式原理）。
