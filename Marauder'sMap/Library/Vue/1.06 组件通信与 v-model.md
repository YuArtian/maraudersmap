# 组件通信与 v-model

## TL;DR

**通信通道按关系记：父子 props/emit，父调子 ref + defineExpose，跨层 provide/inject，任意 Pinia，透传 $attrs**。v-model 是语法糖：**表单元素 = :value + @input，组件 = :modelValue + @update:modelValue**。props 单向数据流的边界：基础类型改不动（警告），引用类型改内部属性「能生效」但属于反模式。

---

## 1. 通信方式全景（Vue 3 口径，标注 Vue 2 差异）

| 关系 | 手段 | 备注 |
|---|---|---|
| 父 → 子 | props（`defineProps`，支持类型声明） | 单向数据流 |
| 子 → 父 | `emit`（`defineEmits`，可校验载荷） | 事件命名 kebab-case |
| 父操作子 | 模板 ref + **`defineExpose`** | script setup 默认封闭，必须显式暴露 |
| 透传 | `$attrs`（未声明的属性/事件自动落到单根组件根元素） | Vue 3 中事件也并入 attrs，**$listeners 已移除**；多根组件需手动 `v-bind="$attrs"` |
| 跨层级 | `provide` / `inject`（key 可用 Symbol 防冲突） | 传响应式数据 + 只读包装是惯例 |
| 任意组件 | **Pinia**（见 [[1.09 Vuex 与 Pinia]]） | 事件总线时代结束：**Vue 3 移除 $on/$off**，确需广播用 mitt |
| 兄弟 | 提升到共同父级 或 Pinia | 同 React 的状态提升思想（见 [[1.08 组件通信与 Context]]） |

Vue 2 遗产考点：`$parent/$children`（Vue 3 删 $children）、EventBus（new Vue() 当总线）——答题时说明「已废弃/移除 + 现代替代」。

## 2. v-model：双向绑定的真身

**表单元素上**——按类型选择 prop 与事件的语法糖：

```html
<input v-model="msg">
<!-- 等价于 -->
<input :value="msg" @input="msg = $event.target.value">
```

text 用 value+input；checkbox 用 checked+change（多选绑数组）；select 用 value+change。修饰符：`.lazy`（改监听 change）、`.number`、`.trim`。

**组件上**（Vue 3）：

```html
<MyInput v-model="msg" />
<!-- 等价于 -->
<MyInput :modelValue="msg" @update:modelValue="msg = $event" />
```

子组件实现：接 `modelValue` prop，改动时 `emit('update:modelValue', 新值)`；**Vue 3.4+ 的 `defineModel()`** 一行搞定（编译宏生成上述样板）。多个 v-model：`v-model:title="t"` → `title` + `update:title`。

**.sync 的历史**：Vue 2 里 `v-model` 组件版固定用 value/input，额外的「双向」props 用 `.sync`（`:title.sync` = `:title` + `@update:title`）——**Vue 3 已移除 .sync，统一并入参数化 v-model**。答题连线：.sync 与 v-model:xxx 是同一机制的两代语法。

本质澄清（追问必出）：所谓「双向绑定」= **「单向数据流 + 事件回写」的语法糖**，数据仍然只从父流向子，子只是「请求」父更新——与 React 受控组件（value + onChange）思想完全一致，Vue 只是把样板代码编译掉了。

## 3. props 单向数据流的三问

**为什么不允许子组件改 prop**：父组件重渲染会用自己的数据覆盖子组件的擅自修改——改了也白改还难排查；数据流向单一才可追踪。

**改了会怎样**：直接对 prop 赋值（基础类型或替换引用）→ 开发环境警告、生产静默失败（父一更新就被打回）；**改引用类型内部属性「能生效」**——因为 Vue 只监控 prop 本身的引用没变，改内部属性不触发警告——但这是**反模式**：父组件无法感知数据被谁改了，调试地狱。

**正确姿势**：想以 prop 为初值 → 拷到本地 data/ref；想派生 → computed；想真正双向 → v-model/emit 让父组件改。

## 面试问答

### Q: Vue 组件间有哪些通信方式？

满分答案：按关系分层——父子：props 下行、emit 上行（defineProps/defineEmits 带类型）；父操作子：模板 ref 配 defineExpose（script setup 默认封闭）；隔代：provide/inject，key 用 Symbol；任意组件：Pinia 全局状态；属性透传走 $attrs（Vue 3 中事件监听器也在其中，$listeners 已移除）。补充演进：EventBus 与 $on 在 Vue 3 已移除，广播需求用 mitt 或状态管理替代。

### Q: v-model 的实现原理？组件上怎么用？

满分答案：语法糖两层——表单元素上按类型展开为 value+input / checked+change / value+change，配 lazy/number/trim 修饰符；组件上展开为 :modelValue + @update:modelValue，子组件 emit 该事件请求父更新，3.4 的 defineModel 宏进一步简化，多值用 v-model:xxx（取代 Vue 2 的 .sync）。点破本质：不是真「双向」，是单向数据流加事件回写的封装，与 React 受控组件同构。

### Q: 子组件修改 props 到底能不能生效？

满分答案：分两种——对 prop 本身赋值（基础类型或换引用）不生效：开发警告、且父组件下次渲染会覆盖；修改引用类型 prop 的内部属性会「生效」，因为 Vue 只在 prop 引用层面做保护、对象内部变更共享同一响应式数据。但后者是反模式：破坏单向数据流、变更来源不可追踪。正解：本地副本、computed 派生、或 v-model/emit 交还父组件修改。

### Q: provide/inject 的适用场景和注意点？

满分答案：跨多层组件传递「上下文型」数据——主题、表单尺寸、当前用户，组件库（如 Form 与 FormItem 的联动）是重度用户。注意：传 ref/reactive 保持响应性；提供方用 readonly 包装防止注入方反向修改（维持单向流）；key 用 Symbol 避免命名冲突；它解决的是「层层转发的 props drilling」，全局高频状态还是该用 Pinia。
