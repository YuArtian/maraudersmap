# Vue 3 响应式原理

## TL;DR

**Vue 3 用 Proxy 整对象代理：get 里 `track` 收集依赖，set 里 `trigger` 触发更新，副作用统一抽象为 `effect`**。依赖存储结构必背：`WeakMap<target, Map<key, Set<effect>>>`。ref 是「带 value 的响应式盒子」（原始值也能响应），reactive 只收对象——两者的取舍与解构丢响应是最高频考点。

> Proxy/Reflect 的机制与 receiver 问题见 [[1.08 Proxy 与 Reflect]]；与 Vue 2 defineProperty 的对比动机见 [[1.01 Vue 2 响应式原理]]。

## 1. 核心三件套：reactive、effect、track/trigger

```js
const targetMap = new WeakMap();   // target → Map(key → Set(effect))
let activeEffect = null;

function effect(fn) {
  const _effect = () => {
    activeEffect = _effect;
    fn();                          // 执行期间读到的属性完成收集
    activeEffect = null;
  };
  _effect();
}

function reactive(target) {
  return new Proxy(target, {
    get(t, key, receiver) {
      track(t, key);                              // 收集
      const res = Reflect.get(t, key, receiver);
      return typeof res === 'object' && res !== null ? reactive(res) : res;  // 惰性深代理
    },
    set(t, key, value, receiver) {
      const ok = Reflect.set(t, key, value, receiver);
      trigger(t, key);                            // 触发
      return ok;
    },
  });
}

function track(target, key) {
  if (!activeEffect) return;
  let depsMap = targetMap.get(target) ?? targetMap.set(target, new Map()).get(target);
  let dep = depsMap.get(key) ?? depsMap.set(key, new Set()).get(key);
  dep.add(activeEffect);           // Set 天然去重
}

function trigger(target, key) {
  targetMap.get(target)?.get(key)?.forEach(fn => fn());
}
```

结构设计的三个「为什么」：**WeakMap** 键弱引用——目标对象没人用了，依赖表随之可回收（见 [[1.09 Set、Map 与弱引用]]）；**Set** 去重同一 effect 的多次读取；组件渲染函数、computed、watch 全是 effect 的变体——**统一抽象**是 Vue 3 比 Vue 2 三种 Watcher 更漂亮的地方。

源码级细节（加分）：activeEffect 处理嵌套 effect 用 parent 链（组件嵌套渲染就是 effect 嵌套）；effect 同样做**双向记录 + 每次运行前清理**（同 Vue 2 Watcher 清 dep 的动机）；数组的 length、for...in（ownKeys trap）、delete（deleteProperty trap）都有对应处理——**Proxy 十三个 trap 让新增、删除、下标全部天然可拦**，Vue.set 退出历史舞台。

## 2. ref vs reactive（必考对比）

| | `ref` | `reactive` |
|---|---|---|
| 接受类型 | 任意（原始值 + 对象） | 仅对象/数组 |
| 形态 | `{ value }` 包装对象，getter/setter 劫持 value | Proxy 代理原对象 |
| 访问 | `.value`（模板中自动解包） | 直接访问属性 |
| 整体替换 | `r.value = 新值` ✔ 保持响应 | `state = 新对象` ✘ **丢失响应**（变量重新赋值绕过了代理） |
| 解构 | ref 本身传递不丢 | **解构即丢**（拿到的是普通值/内层引用），需 `toRefs` |

机制解释：ref 对**原始值**用对象 getter/setter 包一层（原始值无法被 Proxy 代理）；传入对象时内部自动调 reactive。`toRefs` 把 reactive 对象的每个属性转成「读写都代理回源对象」的 ref，解构后仍然响应。

实践口径：**组合式函数返回值用 ref（可解构、可整体替换）；组件内局部状态成组时可用 reactive**；团队统一「全 ref」也是主流选择。

## 3. computed 与 watch 家族

**computed = 带缓存调度的 effect**：内部 dirty 标记，依赖变化时它的 scheduler 只做两件事——置 dirty、通知「读过我的 effect」更新；真正重算延迟到下次读取。**惰性 + 缓存 + 自身也是依赖源**三点答全。

**watch vs watchEffect**：

| | watch | watchEffect |
|---|---|---|
| 依赖 | 显式声明（源 + 回调分离） | 自动收集（回调里读到啥依赖啥） |
| 初次执行 | 默认惰性（immediate 可改） | 立即执行一次（借此完成收集） |
| 旧值 | 能拿到 oldValue | 不能 |
| 适用 | 精确监听、需要新旧对比 | 「让副作用与状态保持同步」 |

---

## 4. 对 Vue 2 的四大改进（呼应前篇）

新增/删除属性天然拦截（不再 Vue.set）；数组下标与 length 生效；**惰性深代理**——访问到才代理子对象，初始化 O(1) 对比 Vue 2 的全量递归；配合 ESM 可 Tree Shaking（响应式模块 @vue/reactivity 可独立使用）。代价：Proxy 无法 polyfill，放弃 IE11。

## 面试问答

### Q: Vue 3 响应式原理？依赖存在哪？

满分答案：reactive 返回 Proxy，get 捕获器里 track、set 里 trigger，副作用统一为 effect——执行前挂到全局 activeEffect，执行中读到的属性把它收进依赖表。存储结构三层：WeakMap 以目标对象为键（弱引用可回收）→ Map 以属性名为键 → Set 存 effect 去重。trigger 按 target+key 取出集合依次运行。补充：嵌套 effect 用 parent 链维护 activeEffect；转发用 Reflect 并传 receiver 保证 getter 里 this 正确。

### Q: ref 和 reactive 的区别？怎么选？

满分答案：ref 万物皆可包——原始值用 {value} 的 getter/setter 劫持（原始值没法 Proxy），对象自动转 reactive，模板自动解包；reactive 只收对象、直接代理。两个坑决定选择：reactive 整体重新赋值和解构都会丢响应（重新赋值绕过代理、解构拿到裸值），需 toRefs 补救；ref 整体替换 .value 和跨函数传递都安全。所以组合式函数返回值一律 ref，reactive 只做组件内成组状态，或团队干脆统一全 ref。

### Q: computed 的实现原理？

满分答案：本质是带自定义 scheduler 的 effect 加 dirty 缓存——首次读取时运行 getter 并收集依赖，结果缓存、dirty 置 false；依赖变化时 scheduler 不重算，只把 dirty 置 true 并通知依赖 computed 的外层 effect；下次被读取才重算。三个关键词：惰性求值、脏标记缓存、自身也是可被依赖的响应源（双层依赖关系）。

### Q: watch 和 watchEffect 的区别？

满分答案：watch 显式声明侦听源，惰性执行、可拿新旧值、可配 deep/immediate/once，适合「值变化后做某事」且需要对比的场景；watchEffect 立即执行并自动收集回调中读到的全部依赖，写法省但依赖隐式、无旧值，适合「让副作用与若干状态持续同步」。共同注意点：组件卸载自动停止，手动调用返回的 stop 可提前解除；异步回调里的清理用 onCleanup 防竞态。
