# nextTick 与异步更新队列

## TL;DR

**Vue 的数据更新不会立刻改 DOM：同一轮同步代码里的所有变更被收进去重队列，在微任务里一次性 flush（重渲染 + patch）**。所以「改完数据立刻读 DOM 是旧的」，要用 `nextTick(cb)`——它把回调排到**DOM 更新之后**执行。原理是共用同一个微任务时机（Promise.then）。

> 宏微任务基础见 [[2.01 事件循环与宏微任务]]。

---

## 1. 为什么更新是异步批量的

```js
this.count = 1;
this.count = 2;
this.count = 3;   // 只触发一次重渲染，DOM 直接到 3
```

没有批处理的话，三次赋值 = 三次「render + diff + patch」，前两次纯属浪费。Vue 的做法：

1. setter/trigger 触发时，把对应的 Watcher（Vue 2）/组件更新 effect（Vue 3 的 scheduler）**推入队列并按 id 去重**——同一组件改一百个数据也只排一次；
2. 用微任务安排一次 `flushQueue`：本轮同步代码执行完、微任务时机到 → 队列按组件 id 排序（保证父先子后）依次执行更新。

对比 React 的批处理（见 [[1.04 setState 与批量更新]]）：目标一致（合并渲染），Vue 靠响应式自动完成（无需 setState 之类的显式入口），React 18 靠调度器按优先级分组。

## 2. nextTick 的原理与使用

```js
this.list.push(newItem);
// 此刻 DOM 还是旧的——更新任务还在微任务队列里排着
await this.$nextTick();          // Vue 3: import { nextTick } from 'vue'
// DOM 已更新，可安全测量/滚动
this.$refs.listEl.scrollTop = this.$refs.listEl.scrollHeight;
```

原理：**nextTick 的回调与「组件更新任务」进的是同一条微任务流水**——更新任务先入队，你的回调排在其后，所以执行时 DOM 必然已刷新。Vue 3 直接用 `Promise.resolve().then()`；Vue 2 有历史降级链（Promise → MutationObserver → setImmediate → setTimeout，处理老浏览器与 iOS 怪癖），现代环境里实际都是 Promise 微任务——「nextTick 是宏任务还是微任务」的答案：**现代版本是微任务**，降级链是历史知识。

典型场景：改数据后测量 DOM（滚动定位、弹层对齐）、等子组件渲染完再操作、在测试里等待视图稳定。

**细节题**：nextTick 回调里再调 nextTick，会进「下一轮」微任务批次（当前队列已在 flush 中）；多个 nextTick 按注册顺序执行。

---

## 3. 「响应式更新精确到什么粒度」

Vue 的更新粒度是**组件级**：一个组件对应一个渲染 Watcher/effect，数据变化只让「订阅了它的组件」重渲染，组件内部再靠虚拟 DOM diff（配合编译期 patch flags 定点更新，见 [[1.03 模板编译与静态优化]]）。对比 React：父组件 setState 默认整棵子树重渲染，需要 memo 手工剪枝（见 [[2.04 记忆化：memo、useMemo 与 useCallback]]）——「Vue 为什么不太需要 shouldComponentUpdate」的答案就在依赖追踪的精确订阅上。

## 面试问答

### Q: Vue 的 DOM 更新是同步的吗？nextTick 是干什么的？

满分答案：异步批量——数据变化只把组件更新任务推入去重队列，微任务时机统一 flush（排序保证父先子后），同轮多次修改只渲染一次。因此改完数据立即读 DOM 拿到的是旧值；nextTick(cb) 把回调排到同一微任务流水里更新任务之后，执行时 DOM 已就绪，适合测量、滚动、聚焦类操作，支持 Promise 用法可直接 await。

### Q: nextTick 的实现原理？是微任务还是宏任务？

满分答案：本质是「把回调追加到与组件更新共用的异步队列」。Vue 3 直接 Promise.resolve().then 调度，纯微任务；Vue 2 因兼容有降级链——Promise、MutationObserver、setImmediate、setTimeout 依次回退，现代浏览器同样落在微任务。因为与更新任务同队列且靠后，天然保证「回调时 DOM 已更新」。补充细节：回调中再次 nextTick 会排入下一轮批次。

### Q: 为什么要做异步更新队列？去重是怎么做的？

满分答案：避免同一轮同步代码的多次数据变更触发多次「render+diff+patch」——渲染只关心最终状态。实现：触发更新时 Watcher/effect 按 id 入队去重（Set 或 has 判断），同一组件任意多次变更只保留一个更新任务；微任务 flush 时按组件 id 升序执行，保证父组件先于子组件、user watcher 先于渲染。效果等价于「自动的批处理」，不需要开发者手动合并。

### Q: Vue 和 React 的更新粒度有什么不同？

满分答案：Vue 依赖追踪精确到组件——谁的渲染函数读过这个数据，谁才进更新队列，组件内再用带 patch flags 的 diff 定点更新，默认性能好、无需手工优化；React 是 push 模型——setState 后默认整棵子树重渲染，靠 memo/useMemo 手工或 React Compiler 自动剪枝。代价方向相反：Vue 花在依赖追踪的内存与收集开销，React 花在重渲染与比对开销。
