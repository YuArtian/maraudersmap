# Vue 高频细节题集

## TL;DR

**零散但常考的细节合集**：v-if/v-for 优先级（Vue 2 与 3 相反！）、Options API 里箭头函数丢 this、组件 data 必须是函数、强制刷新三法、错误处理双钩子、SSR 原理概览。每题都短，适合面试前快速过一遍。

---

## 1. v-if 和 v-for 谁优先级高（版本陷阱题）

- **Vue 2：v-for 更高**——先循环再逐项判断 v-if，`v-if="false"` 也要跑完整个循环，白白浪费；
- **Vue 3：v-if 更高**——先判断，且此时 **v-if 读不到 v-for 的迭代变量**（`v-if="item.show"` 直接报错）。

两版结论相反，回答必须带版本。**正确姿势**（官方风格指南）：不要同标签混用——过滤场景用 computed 先筛（`v-for="item in visibleItems"`），条件包裹场景把 v-if 提到外层 template 上。

## 2. Options API 里的箭头函数陷阱

```js
methods: {
  handleClick: () => { this.count++ }   // 🔴 this 是 undefined
},
watch: {
  query: (val) => { this.search(val) }  // 🔴 同病
}
```

原因：Vue 调用这些函数时用 `fn.call(vm)` 绑定实例，但**箭头函数没有自己的 this、call 绑不动**（机制见 [[1.04 this 与 call、apply、bind]]），this 沿词法作用域拿到模块顶层的 undefined。规则：**methods/watch/computed/生命周期一律普通函数；它们内部的回调（setTimeout、数组方法）才用箭头函数保留 this**——内外正好相反。

## 3. 组件的 data 为什么必须是函数

组件会被**多处复用**：构造器（Vue.extend 产出的 VueComponent，俗称 vc）只有一份，data 若是对象，会挂在构造器层被**所有实例共享**——A 实例改计数，B 实例跟着变。函数形式让每个实例调用时**生成独立副本**。根实例（vm）不复用所以允许对象。原型链彩蛋：`VueComponent.prototype.__proto__ === Vue.prototype`——组件实例因此能用 Vue 原型上的 $nextTick 等方法（原型链机制见 [[1.05 原型与原型链]]）。

## 4. 强制刷新组件的三种方法（按优先级倒序讲）

1. **改 key**（最推荐）：`<Comp :key="version" />`，key 变化触发销毁重建，状态彻底重置——利用 diff 的身份判定（见 [[1.04 Vue 的 Diff 算法与 key]]）；
2. **v-if 开关**：`v-if="show"` 置 false 再 true（配合 nextTick），同样是重建；
3. **$forceUpdate()**：只强制当前组件重新 render（不重建、不动子组件），**用到它通常说明响应式链路有 bug**（该用 Vue.set / 正确的 ref 写法解决）——答题时点出这层反思是加分项。

## 5. 错误处理体系

| 钩子 | 范围 | 特点 |
|---|---|---|
| `errorCaptured` | 组件内钩子，捕获**后代组件**错误 | 收 (err, vm, info)；`return false` 阻止继续上抛——可做局部兜底 UI（类比 React 错误边界，见 [[1.06 生命周期与类组件遗产]]） |
| `app.config.errorHandler` | 全局（Vue 2 是 Vue.config.errorHandler） | 统一上报监控；2.6+/Vue 3 可捕获 v-on 回调与 Promise 链错误 |

传播链：后代抛错 → 沿组件链逐层 errorCaptured → 全局 errorHandler。配套：`warnHandler`（开发警告）、window 层的 `unhandledrejection` 兜住框架外的漏网之鱼。

## 6. Vue SSR 原理概览

**双入口双产物**：server 入口导出「每请求创建新 Vue 实例」的工厂函数（防跨请求状态污染），经 vue-server-renderer 的 `renderToString` 产出 HTML 插入模板占位符；client 入口正常 `$mount`。**服务端产出静态 HTML（快速首屏 + SEO），客户端 bundle 加载后执行「注水」（hydration）**——不重建 DOM，而是将事件与响应式状态**挂接到已有节点**上，从此接管交互。

必答要点：注水失败（服务端与客户端渲染结果不一致）会警告并降级重渲染；服务端只执行到 created（没有 DOM，mounted 不跑），副作用要防泄漏；数据预取需要「服务端取完 → 序列化进 HTML → 客户端接着用」的同构约定。现代实践直接上 **Nuxt**（Vue 的 Next.js）。

## 面试问答

### Q: v-if 和 v-for 能一起用吗？

满分答案：不建议，且两版行为相反——Vue 2 中 v-for 优先，先循环后逐项判断，浪费遍历；Vue 3 中 v-if 优先，且访问不到 v-for 变量会直接报错。正解：过滤用 computed 预筛列表，条件显隐把 v-if 提到外层 template。这题答出「版本差异 + 替代方案」才完整。

### Q: 为什么组件的 data 必须是函数，根实例却可以是对象？

满分答案：组件构造器全局只有一份、实例有无数个——data 若是对象则被所有实例共享，一处修改全体污染；函数保证每次实例化产出独立数据副本。根实例（new Vue/createApp）不存在复用，所以没这个约束。可加原型链细节：VueComponent.prototype.__proto__ === Vue.prototype，组件实例由此继承 Vue 原型方法。

### Q: Vue 的错误处理机制？

满分答案：两级——组件级 errorCaptured 捕获后代组件错误，可 return false 截断上抛、渲染局部兜底 UI（等价 React 错误边界）；全局 errorHandler 做统一上报，覆盖渲染、watcher、v-on 回调和 Promise 链错误。传播顺序是后代到祖先的 errorCaptured 链再到全局。工程配套：接监控平台、warnHandler 治开发警告、unhandledrejection 兜框架外部。

### Q: 说说 Vue SSR 的原理？

满分答案：构建双入口——服务端入口导出工厂函数每请求新建实例（防状态串请求），renderToString 产出首屏 HTML；客户端 bundle 到达后执行 hydration：不重建 DOM，把事件监听和响应式绑定挂接到服务端渲染的节点上接管页面。收益是首屏与 SEO；代价是服务端负载、只跑到 created 的生命周期约束、需保证两端渲染一致否则注水失败降级。生产直接用 Nuxt 这类元框架。
