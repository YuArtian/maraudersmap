# 大模型如何训练：猜下一个词

> 亿万个参数从随机数到智能：自动生成的填空题库 + 打分 + 亿万次微调

## TL;DR

- **题库自造**：任何文本遮住后面、露出前面就是一道题，全网文本 = 近乎无限的题库，无需人工标注
- **猜 = 输出整张概率表**：对词表里几万个 token 各给一个概率
- **损失函数**：看正确答案分到多少概率，越低罚分越重
- **反向传播 + 梯度下降**：一次性算出每个参数该往哪拧，所有参数同时挪一小步
- **副产品**：意思相近的词，向量被逼得相近（embedding 表的含义就是这么长出来的）
- 这就是 [[机器学习基础概念]] 里"学习 = 调整所有权重，让损失函数最小"的展开

---

## 1. 题库自造：文本本身就是题

"猜下一个词"最妙的地方是**不需要人出题**：

```text
原文: "我 今天 去 超市 买了 菜"

题1: "我"             → 猜: 今天
题2: "我 今天"         → 猜: 去
题3: "我 今天 去"      → 猜: 超市
题4: "我 今天 去 超市"  → 猜: 买了
...
```

一句话出好几道题，每道题自带标准答案。这就是大模型能"吃"下万亿级数据的原因——没有人工标注的瓶颈。

---

## 2. "猜"是怎么猜的：一张概率表

模型不是吐出一个词，而是**对词表里全部几万个 token 各打一个分**，softmax 压成概率：

```text
做题 "我 今天 去 →？"

模型输出:
  超市: 21%   学校: 15%   公司: 12%   医院: 6%   ...
  火锅: 0.3%  ...  函数: 0.001%  ...
```

这张表是整条流水线算出来的：查 embedding 表 → 注意力层 → 前馈层 → … → 输出打分（见 [[Transformer]]、[[Token 与 Embedding 表]]）。

流水线里所有数字——embedding 表、W_Q/W_K/W_V、前馈层权重——统称**参数**。所谓 7B、70B 模型，就是 70 亿、700 亿个这样的数字。

---

## 3. 打分：损失函数

看**正确答案分到了多少概率**。标准答案"超市"拿了 21%——不算差但不完美（理想 100%）。损失函数（交叉熵）把它换算成罚分：正确答案概率越高罚分越接近 0，越低罚分越大。

训练前参数全是随机数，正确答案只能分到几万分之一的概率，损失巨大。

---

## 4. 改进：亿万个旋钮，每个都问同一个问题

把每个参数想象成一个**旋钮**，整个模型是一台 700 亿个旋钮的机器。每做完一道题，对每个旋钮问：

> "把你拧大一点点，罚分会变大还是变小？"

**反向传播**（本质是链式求导）能**一次性高效算出全部旋钮各自的答案**——"往左拧""往右拧""不用动"。然后所有旋钮**同时朝罚分变小的方向挪极小一步**——这就是**梯度下降**。

> 类比：蒙眼下山。看不见全景，但脚能感觉到坡度（梯度），每次朝下坡方向迈一小步，迈几万亿步就走到了很低的地方。

```text
一次训练步骤的完整循环:

  出题 "我 今天 去 →?"
    → 模型猜（前向计算，得概率表）
    → 对答案算损失（"超市"只有 21%，罚分）
    → 反向传播（算出每个旋钮该往哪拧）
    → 所有旋钮各挪一小步
    → 下一道题，重复亿万次
```

---

## 5. 副产品：意思相近的词，向量被逼得相近

没有任何代码规定这一点，它是**被逼出来的**："猫"和"狗"出现的语境高度相似（"我家的__很可爱"、"带__去打疫苗"），模型要在相同语境里都猜得准，最省力的方案就是把两者的向量调得很像。亿万道题下来，语境相似的词被推到向量空间的同一片区域——embedding 表里数字的"含义"就是这么长出来的。

---

## 6. 训练和使用的关系

GPT 生成文字 = 把训练时做的事原样重放：猜一个词 → 写下来 → 拼回输入 → 再猜下一个。训练任务和使用方式完全同构，这是 GPT 流派（见 [[Transformer]] 三大流派）能靠堆规模取胜的原因之一。

> 注：以上是**预训练**（pre-training）。实际产品还有后续阶段（指令微调、人类反馈强化学习等），让模型从"会接龙"变成"会对话、听指挥"。**关键是这些阶段用的还是本文这一套动作**（猜下一个词 + 梯度下降），只是换了喂进去的数据——具体在动哪批参数、LoRA 怎么只训 0.1% 就够，见 [[微调与 LoRA]]。
