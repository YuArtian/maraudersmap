# Token 与 Embedding 表

> 文字进入大模型前的两次翻译：字节 →（查词表）→ token →（查 embedding 表）→ 向量

## TL;DR

- 模型不认识"字"，只认识 **token**：词表像一盒乐高，常见词整块、生僻词拆碎、256 个字节 token 兜底——**编码层面不存在"不认识"**
- **Embedding 表 = 词表行数 × 维度的巨大数字表格**，是模型参数的一部分，存在权重文件里，训练学出来的
- 每家模型的词表和 embedding 表都不同 → **不同模型的向量互不通用**（RAG 换 embedding 模型必须整库重灌）
- **token 数 ≠ 字数**：常见字一块搞定，生僻字退化成 2~3 个字节 token，同一句话里混着来
- 完整链条：字符 →(UTF-8)→ 字节 →(分词器)→ token →(查表)→ 向量（序列长度 × 维度的矩阵）→(注意力层)→ …

---

## 1. 分词器与词表：一盒乐高积木

词表（vocabulary）里的一行不是一个"词"，而是一个 **token（词元）**——可以是完整的词、词的碎片，最小到单个字节：

```text
常见词   → 有整块积木:  "the"、"我" 各占一行，1 个 token 搞定
次常见词 → 拆成几块:    "internationalization"
                       → "intern" + "ational" + "ization"（3 个 token）
生造词   → 拆得更碎:    "blorptastic"
                       → "bl" + "orp" + "tast" + "ic"（4 个 token）
```

分词器（tokenizer）的策略：**尽量用大块，不够就用小块**。

### 字节兜底：永远拼得出来

词表专门留 256 行对应所有字节值（0~255），长相就是 `<0x00>` ~ `<0xFF>`。任何字符终归是几个字节（见 [[1.05 字符编码]]），最坏情况退化到按字节切：

```text
"我" UTF-8 = E6 88 91 → 词表里有专属行 → 1 个 token
"藜" UTF-8 = E8 97 9C → 没有专属行   → <0xE8> <0x97> <0x9C> 3 个 token
```

两个字在 UTF-8 层面都是 3 字节、待遇平等，差别只在词表里有没有专属行（"我"太常见，配了整块积木）。字节级 token 和普通 token 待遇完全相同：各有 embedding 行、各变向量，靠注意力层融合出含义——类比人逐字母拼读生词 quinoa，结合上下文猜出是种吃的。

### 分词的现实影响

- API 按 token 计费、上下文窗口按 token 算长度——模型眼里的世界就是按积木块切的
- LLaMA-2 词表以英文为主，汉字大量被拆成 2~3 个字节 token → **同样内容中文比英文费 token**
- 所以中文模型（Qwen、DeepSeek 等）把词表扩到十几万行，给常用汉字配整块积木

## 2. Embedding 表是什么

一张真实存在的**二维数字表格**：每行一个 token，每列是向量的一个格子。

```text
              第1列   第2列   第3列  ...  第4096列
token "我"     0.12   -0.83   0.45  ...   0.07
token "你"     0.15   -0.79   0.41  ...   0.11
token <0xE8>  -0.52    0.33   1.20  ...  -0.64
...
```

以 LLaMA-2 7B 为例：32000 行 × 4096 列 ≈ **1.3 亿个数字**（fp16 约 260MB，只占 14GB 模型的 2%，大头是注意力和前馈层的权重）。

**"查表" = 取出第 N 行**，没有任何计算。它是模型的第一层，文字进模型的第一站。

### 存在哪、谁生成的

- 存在**模型权重文件**里（`.safetensors` / `.gguf`），和 W_Q、前馈层权重打包在一起；运行时加载进显存
- **没有人编写它**：训练前是随机数，跟着"猜下一个词"的亿万次练习被梯度下降调出来（见 [[大模型如何训练]]）——是训练的产物，像肌肉是健身的产物

### 大家的表一样吗？完全不一样

| 差异层 | 说明 |
|---|---|
| 行数 | 各家分词器不同：LLaMA-2 32000 行，GPT-4 约 10 万行 |
| 列数（维度） | 768 / 4096 / 12288，各家自选 |
| 数值 | 训练数据、初始随机数都不同，练出来必然不同 |

有意思的是**相对关系会重现**："猫"和"狗"在每家的表里都互相靠近——好比两次城市规划，饭店都挨着商圈建，只是门牌号不同。

**推论（RAG 铁律）**：不同模型的向量是两个互不相通的坐标系，点积毫无意义 → 换 embedding 模型必须整库重灌（[[Vector Database]] 建库要指定维度的根源）。

## 3. 词级 embedding vs 句级 embedding

容易混淆的两个东西：

```text
词级: embedding 表查一行 → 一个 token 的向量（纯查表，无计算）
句级: 整句话送进完整模型（通常是 BERT 后代），词向量经过层层注意力
      互相融合 → 汇总成一个代表全句语义的向量
```

[[Embedding Service]] 提供的"文字进、向量出"是句级服务——查表只是它流水线的第一步。

## 4. 完整链条

用一整句话走一遍：**"我爱吃藜麦"**。

### 第一步：字符 → 字节（UTF-8）

```text
我  U+6211  →  E6 88 91
爱  U+7231  →  E7 88 B1
吃  U+5403  →  E5 90 83
藜  U+85DC  →  E8 97 9C
麦  U+9EA6  →  E9 BA A6
```

这一层与模型无关，是通用的字符编码（见 [[1.05 字符编码]]）。

### 第二步：字节 → token（分词器查词表）

分词器的策略是**尽量用大块，不够就用小块**，所以同一句话里不同的字待遇不同：

```text
"我"  →  常用字，词表里有专属行     →  1 个 token
"爱"  →  常用字，有专属行           →  1 个 token
"吃"  →  常用字，有专属行           →  1 个 token
"藜"  →  生僻字，词表里没有         →  退化到字节级：<0xE8> <0x97> <0x9C>  3 个 token
"麦"  →  常用字，有专属行           →  1 个 token

────────────────────────────────────────────────
5 个汉字  →  7 个 token
```

**这是单字例子看不出来的最重要一点：token 数不等于字数。** 常见词一块搞定，生僻字被拆成几块，两者混在同一个序列里，待遇完全平等。

真实的分词器还会在开头补一个特殊 token（如 `<s>` / `<BOS>`）标记序列起点，这里为清晰起见略去。

英文同理，只是切的是词根词缀而非字节：

```text
"tokenization"  →  "token" + "ization"       2 个 token
"cat"           →  "cat"                     1 个 token
"blorptastic"   →  "bl"+"orp"+"tast"+"ic"    4 个 token
```

这也是 API 按 token 计费、上下文窗口按 token 计长度的直接后果——**同样内容，中文往往比英文费 token**（LLaMA 系词表以英文为主，汉字大量退化到字节级）。

### 第三步：token → 向量（查 embedding 表）

7 个 token 各查一行，得到 7 个 4096 维向量，堆起来就是一个矩阵：

```text
token 序列              查表取出的行（各 4096 维）
────────────────────────────────────────────────
[我]         →  [ 0.12, -0.83,  0.45, ... ,  0.07]
[爱]         →  [-0.31,  0.55, -0.02, ... ,  0.88]
[吃]         →  [ 0.64,  0.19, -0.77, ... , -0.23]
[<0xE8>]     →  [-0.52,  0.33,  1.20, ... , -0.64]
[<0x97>]     →  [ 0.08, -0.41,  0.16, ... ,  0.92]
[<0x9C>]     →  [-0.19,  0.72, -0.35, ... ,  0.11]
[麦]         →  [ 0.47, -0.06,  0.83, ... , -0.50]

数据形状：7 × 4096  =  序列长度 × 维度
```

**行数随句子长短变，列数永远固定**（见 [[向量与点积]] 关于维度的规矩）。千字文就是一千多行 × 4096 列。

### 第四步：进入注意力层

这个 7×4096 的矩阵整体送进第一层，token 之间开始互相"看"对方（[[Transformer]]）。`<0xE8><0x97><0x9C>` 这三个字节 token 单看毫无意义，但它们夹在"吃"和"麦"中间，注意力层能从上下文推出这是某种可吃的东西——**类比人逐字母拼读生词 quinoa，结合上下文猜出是种粮食**。

### 一图总览

```text
"我爱吃藜麦"
   ↓ UTF-8 编码                    ← 与模型无关的通用编码
E6 88 91 | E7 88 B1 | ... 共 15 字节
   ↓ 分词器查词表（贪心匹配大块）      ← 每家模型的词表都不同
7 个 token（5 个字 → 7 个 token）
   ↓ 查 embedding 表（取行，零计算）  ← 模型参数的一部分
7 × 4096 的矩阵
   ↓ 32 层注意力 + 前馈              ← 真正的计算从这里开始
7 × 4096 的矩阵（含义已被上下文重塑）
   ↓ 取最后一个位置 × 输出矩阵 + Softmax
32000 维概率分布 → 采样出下一个 token
```

三层查表 + 一路矩阵运算——这就是文字进入神经网络并变回文字的全部路径。本文详述的是前两步；**后面每一步（位置编码、32 层里发生了什么、输出头、采样、自回归循环）的完整展开见 [[AI/Map|AI 知识地图]]**，整体图景见 [[大语言模型]]。

## 附：LLaMA 是什么

Meta（Facebook）出的大语言模型系列，**L**arge **La**nguage Model **M**eta **AI**，拼出来正好是"llama（大羊驼）"，读作"拉玛"。特殊地位在于**开放权重**——可以下载到自己机器上跑和微调，是开源社区的地基（llama.cpp 及各种微调模型都源于此）。本文用 LLaMA-2 举例因为它的参数配置（32000 词表、4096 维）经典好记。
