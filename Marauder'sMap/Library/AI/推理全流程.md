# 推理全流程：从一句话到一句话

> 一次调用里，数据每一步长什么样、经过了什么运算——全程可追踪的机械过程

> [!note] 定位
> 本文只讲**推理**（用现成模型生成文字）的完整链路，是把散在各篇里的环节串成一条线。每个单点概念只做够用的说明，细节链接到对应笔记：[[Token 与 Embedding 表]]（前两步）、[[Transformer]]（层内部）、[[矩阵与线性变换]]（运算）、[[大语言模型]]（它是什么、怎么训出来的）。

## TL;DR

- 全程只有两类操作：**查表**（零计算）和**矩阵乘法 + 非线性**
- 数据在中间层的形状始终是 **序列长度 × 维度**，一路不变，直到最后一步才变成词表大小
- **输出层只取最后一个位置**，前面所有位置算出来的结果在生成时被丢弃（但训练时全都要用）
- **采样**才是随机性的唯一来源：模型本身完全确定，同样输入必得同样的概率分布
- **自回归**：生成 n 个 token 就要跑 n 次前向，靠 KV 缓存避免重复计算
- 注意力的代价是 $O(n^2)$ —— 这是上下文越长越慢越贵的根源

---

## 0. 贯穿全文的例子

输入 **"我爱吃藜麦"**，让模型续写下一个字。模型配置取 LLaMA-2 7B 的经典参数：

```text
词表大小 V = 32000     隐藏维度 d = 4096     层数 L = 32
```

---

## 1. 全流程一张图

```text
输入文字 "我爱吃藜麦"
   │
   │ ① 分词器查词表                      查表，零计算
   ↓
7 个 token id：[1, 1234, 5678, 910, 31234, 31567, 4321]
   │
   │ ② 查 embedding 表（取行）           查表，零计算
   ↓
形状 7 × 4096          ← 从这里开始，形状一路不变
   │
   │ ③ 加位置信息
   ↓
形状 7 × 4096
   │
   │ ④ 第 1 层：注意力 → 前馈（各带残差与归一化）
   ↓
形状 7 × 4096
   │
   │   ⋮  重复 32 层，每层结构相同、参数不同
   ↓
形状 7 × 4096          ← 每一行的含义已被上下文彻底重塑
   │
   │ ⑤ 只取最后一行（第 7 个位置）
   ↓
形状 4096
   │
   │ ⑥ 乘输出矩阵 4096 × 32000
   ↓
形状 32000（logits，任意实数）
   │
   │ ⑦ 除以温度 → Softmax
   ↓
形状 32000（概率，和为 1）
   │
   │ ⑧ 按概率采样
   ↓
一个 token → 拼回输入末尾 → 回到 ①    ← 自回归循环
```

**整个过程只有两类操作**：前两步是查表（按下标取数，没有任何计算），从第 ③ 步开始全是矩阵乘法和逐元素的非线性函数。

---

## 2. 第 ①② 步：文字变成矩阵

这两步在 [[Token 与 Embedding 表]] 里有完整走查，此处只记结论：

```text
"我爱吃藜麦"
  → UTF-8 编码 → 15 个字节
  → 分词器切分 → 7 个 token（"藜"生僻，退化成 3 个字节 token）
  → 查 embedding 表，每个 token 取出一行 4096 维向量
  → 得到 7 × 4096 的矩阵
```

要记住的两点：**token 数不等于字数**；**行数随输入长短变，列数永远是 4096**。

---

## 3. 第 ③ 步：加位置信息

这一步容易被漏掉，但不可缺少。

**问题在于：注意力机制本身对顺序完全无感。** 它只是让每个 token 去看别的 token，如果不额外告知位置，"我爱吃藜麦"和"藜麦吃爱我"在它眼里是同一堆东西。

解决办法是给每个位置的向量再叠加一份"位置信号"：

```text
第 1 个 token 的向量  +  代表"第 1 位"的信息
第 2 个 token 的向量  +  代表"第 2 位"的信息
   ⋮
形状仍是 7 × 4096（加法不改变形状）
```

具体怎么编码有好几种做法（原始 Transformer 用正弦函数，现代模型多用 RoPE 旋转位置编码），细节见 [[Transformer]]。这里只需知道：**位置不是天然存在的，是被人为加进去的**。

---

## 4. 第 ④ 步：一层里面发生了什么

这是全流程中最实质的一步，也是之前最语焉不详的一环。**一层由两个子层组成**：注意力和前馈，各自外面包一层残差与归一化。

```text
输入 7×4096
   ↓
┌─ 子层一：自注意力 ──────────────┐
│  归一化 → 注意力 → 加回输入（残差）│
└────────────────────────────────┘
   ↓ 7×4096
┌─ 子层二：前馈网络 ──────────────┐
│  归一化 → 前馈 → 加回输入（残差） │
└────────────────────────────────┘
   ↓ 7×4096
```

### 子层一：自注意力——让 token 互相看

每个 token 的向量先分别乘三个权重矩阵，得到三个新向量：

```text
Q（Query，查询）  = 我要找什么样的信息
K（Key，键）      = 我能提供什么样的信息
V（Value，值）    = 我实际携带的内容

形状：7×4096 各乘一个 4096×4096 矩阵 → 三个 7×4096
```

然后**用 Q 和 K 做点积算匹配分**——这正是 [[向量与点积]] 里"点积衡量像不像"的直接应用。以最后那个 token "麦" 为例，它的 Q 和前面每个 token 的 K 分别做点积：

```text
麦 的 Q  ·  我 的 K  =  1.2
麦 的 Q  ·  爱 的 K  =  0.4
麦 的 Q  ·  吃 的 K  =  3.1     ← 匹配度最高
麦 的 Q  ·  麦 的 K  =  2.0     ← 也看自己

过 Softmax 变成权重（和为 1）：
   我 9.7%    爱 4.3%    吃 64.5%    麦 21.5%
```

**"麦"最关注"吃"**，于是它按这个权重把各个 token 的 V 加权求和，得到自己的新向量——**"吃"的含义被大量混进了"麦"里**。这就是"上下文重塑含义"的具体机制。

同样的道理，那三个孤立的字节 token `<0xE8><0x97><0x9C>`（"藜"）单看毫无意义，但它们夹在"吃"和"麦"之间，加权求和之后自然带上了"可食用的粮食"这层意思。

两个必须知道的约束：

**因果掩码**：生成模型里每个位置**只能看自己和前面**，不能看后面。否则训练时就等于提前看到了答案。做法是把指向未来位置的分数强行设成负无穷，softmax 之后权重为 0。

**多头**：上面那套 Q/K/V 不是只做一遍，而是把 4096 维切成若干组（如 32 组各 128 维）**并行做 32 套**，最后拼回 4096 维再过一个输出矩阵。不同的头可以关注不同类型的关系（语法搭配、指代、远距离依赖）。

### 子层二：前馈网络——逐个位置加工

注意力负责 token 之间交换信息，前馈负责**每个位置各自把信息加工一遍**，彼此不交流：

$$\text{FFN}(x) = W_2 \cdot \text{ReLU}(W_1 x + b_1) + b_2$$

**这就是 [[神经网络]] 里那个两层网络，一字不差**，只是尺寸大：$W_1$ 是 4096×16384（先扩宽），$W_2$ 是 16384×4096（再压回）。7 个位置各过一遍，互不影响。

参数量上前馈其实比注意力还大——每层前馈约 1.34 亿参数，注意力约 6700 万。

### 残差与归一化：让深度可行

**残差连接**：每个子层的输出要加回它的输入，即 $x + F(x)$ 而不是 $F(x)$。这样梯度在反向传播时有一条"直通车道"，几十层也不会衰减消失。这也是 [[向量与点积]] 里说"向量长度必须一致"的一个硬性理由——要相加就必须同形。

**层归一化**：把每个位置的 4096 个数调整成均值 0、方差 1 的分布，防止数值在几十层里越滚越大或越缩越小。

这两样都不改变形状，也不改变"每层在算什么"，纯粹是**让深层网络训得动的工程手段**（见 [[大语言模型]] 关于深度学习配套技术的说明）。

---

## 5. 第 ④ 步（续）：重复 32 层

上面那一整块原样重复 32 次，**结构完全相同，参数各不相同**（每层有自己的 Q/K/V/O 和前馈权重）。

```text
输入 7×4096 → 第1层 → 7×4096 → 第2层 → 7×4096 → … → 第32层 → 7×4096
```

形状全程不变，变的是每一行里那 4096 个数的含义——从"孤立的词义"逐层变成"融合了整句上下文的语义"。这和 [[神经网络]] 里"浅层学边缘、深层学整张脸"是同一种逐层抽象，只是对象从像素换成了词。

---

## 6. 第 ⑤⑥ 步：从矩阵到 logits

跑完 32 层拿到的还是 7×4096。要预测下一个 token，**只取最后一行**：

```text
7 × 4096  →  取第 7 行  →  4096 维向量
```

为什么只取最后一个？因为要预测的是"第 7 个 token 之后是什么"，而由于因果掩码，**只有最后那一行融合了全部 7 个 token 的信息**。前六行算出来的东西在生成时直接丢弃。

（训练时不一样：七行全都要用，因为一句话能同时提供 7 个"猜下一个词"的训练样本，这正是自监督高效的原因，见 [[大语言模型]]。）

然后乘输出矩阵，把 4096 维映射到词表大小：

```text
(4096,) × (4096 × 32000) → (32000,)
```

得到的 32000 个数叫 **logits**，是任意实数，可正可负，还不是概率。

---

## 7. 第 ⑦ 步：logits 变成概率

先除以**温度** $T$，再过 Softmax：

$$p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$

Softmax 做两件事：把任意实数压成正数，再归一化使总和为 1。温度则控制分布的"尖锐程度"：

```text
logits = [3.2, 1.8, 1.1, 0.4]（只看前 4 个）

T = 0.2  →  [0.999, 0.001, 0.000, 0.000]   ← 几乎必选第一个，极度保守
T = 1.0  →  [0.699, 0.172, 0.086, 0.043]   ← 原始分布
T = 1.5  →  [0.557, 0.219, 0.137, 0.086]   ← 抹平差距，更容易选到冷门
```

**温度不改变排序，只改变差距**。低温更确定、更重复；高温更多样、也更容易胡说。

---

## 8. 第 ⑧ 步：采样

拿到 32000 个概率后，怎么挑出一个 token，有几种策略：

| 策略 | 做法 | 特点 |
|---|---|---|
| 贪心 greedy | 永远选概率最大的 | 完全确定，但容易重复啰嗦 |
| 纯采样 | 严格按概率随机抽 | 多样，但偶尔抽到极低概率的怪词 |
| Top-k | 只在概率最高的 k 个里抽 | 掐掉长尾 |
| Top-p（核采样） | 按概率从高到低累加到 p（如 0.9），只在这些里抽 | 候选数量随分布自动调整，最常用 |

**这一步是整个流程中唯一的随机性来源。** 模型本身是完全确定的函数——同样的输入必然产生同样的 logits。所以"同一个问题两次回答不一样"不是模型不稳定，是采样掷了骰子；把温度设成 0（等价于贪心）就能复现。

---

## 9. 第 ⑨ 步：自回归循环

采样出的 token 拼回输入末尾，整个流程从头再跑一遍：

```text
第 1 轮：输入 7 个 token  → 输出 "是"
第 2 轮：输入 8 个 token（"我爱吃藜麦是"）→ 输出 "一"
第 3 轮：输入 9 个 token → 输出 "种"
   ⋮
直到采样出结束符 <EOS>，或达到设定的最大长度
```

**生成 n 个 token 就要完整跑 n 次前向。** 你看到的逐字蹦出来，就是这个循环在转。

### KV 缓存：为什么第一个字慢、后面快

朴素做法每轮都把整个序列重算一遍，极其浪费——因为前面那些 token 的 K 和 V 每轮算出来都一样。

于是把它们**缓存**起来，每轮只算新增那一个 token 的 Q/K/V，和缓存里的 K/V 拼一起用。这带来了推理的两个阶段：

```text
Prefill（预填充）：把整个提示词一次性跑完，填满 KV 缓存
                  → 计算量大，所以"第一个字"等得久

Decode（解码）：  之后每轮只算一个新 token
                  → 快得多，所以后面刷刷往外冒
```

代价是显存：缓存大小正比于上下文长度，长上下文很吃显存。

### 为什么上下文越长越慢越贵

注意力要算"每个 token 对每个 token"的分数，是一个 $n \times n$ 的矩阵：

```text
序列长     10 → 分数矩阵    10×10 =         100 个数
序列长    100 → 分数矩阵  100×100 =      10,000 个数
序列长  1,000 → 分数矩阵  1000×1000 =  1,000,000 个数
序列长 10,000 → 分数矩阵 10000×10000 = 100,000,000 个数
```

**长度翻倍，注意力的计算量变四倍**——这个 $O(n^2)$ 是长上下文昂贵的根本原因，也是各种"高效注意力"研究要攻克的目标。

## 10. 数据形状总表

| 阶段 | 形状 | 说明 |
|---|---|---|
| 输入文字 | — | "我爱吃藜麦" |
| token id | 7 | 5 个字 → 7 个 token |
| embedding 后 | 7 × 4096 | 序列长度 × 维度 |
| 加位置信息 | 7 × 4096 | 加法不改形状 |
| 每层 Q / K / V | 7 × 4096（各） | 三个投影矩阵 |
| 注意力分数 | 7 × 7 | 每个 token 对每个 token |
| 每层输出 | 7 × 4096 | **32 层全程不变** |
| 取最后一行 | 4096 | 只有它融合了全文 |
| logits | 32000 | 乘 4096×32000 输出矩阵 |
| 概率 | 32000 | Softmax 之后和为 1 |
| 采样结果 | 1 | 一个 token |

**中间层的形状一路不变，只在最后一步跳到词表大小**——这是整条链路最值得记住的结构特征。

## 11. 计算量花在哪

一次前向的大头（按 7B 模型的量级）：

```text
① 分词、② 查表        几乎为零（按下标取数）
③ 位置编码            可忽略
④ 32 层 × (注意力 ≈ 0.67 亿参数 + 前馈 ≈ 1.34 亿参数)   ← 99% 以上在这里
⑤⑥ 输出投影 4096×32000 ≈ 1.3 亿参数                    ← 单次不小，但只做一次
⑦⑧ Softmax 与采样      可忽略
```

**前馈层比注意力还费参数**，这点常被忽略——注意力更出名，但每层的算力大头其实在那两个大矩阵上。至于为什么这些矩阵乘法非要 GPU 才跑得动，见 [[矩阵与线性变换]] 第 7 节。

## 12. 常见困惑对照

| 现象 | 原因 |
|---|---|
| 同样的问题，两次回答不一样 | 第 ⑧ 步采样掷骰子；温度设 0 即可复现 |
| 第一个字要等，后面刷刷出 | Prefill 要算完整个提示词，Decode 每轮只算一个 token |
| 上下文越长越慢、越贵 | 注意力的 $O(n^2)$，加上 KV 缓存吃显存 |
| 有长度上限（上下文窗口） | 位置编码的训练范围有限，且 $n^2$ 的开销扛不住 |
| 模型"记得"上文 | 不是真的记住——每轮都把完整上下文重新喂了一遍 |
| 一本正经地说错事实 | 优化目标里只有"下一个 token 概率高"，没有"说真话"（见 [[大语言模型]]） |
| 中文比英文费 token | 词表以英文为主，汉字常退化到字节级（见 [[Token 与 Embedding 表]]） |
