# 对象属性与属性描述符

## TL;DR

**对象的每个属性背后都有一份「属性描述符」，分两种：数据描述符（value + writable）和存取描述符（get + set），两者互斥，公共开关是 configurable 和 enumerable**。`Object.defineProperty` 就是操作这份描述符的入口，Vue 2 响应式、对象冻结、只读属性全是它的应用。

---

## 1. 两种属性描述符

```js
const obj = {};
// 数据属性：直接存值
Object.defineProperty(obj, 'a', {
  value: 1,
  writable: false,      // 不可写
  enumerable: false,    // 不可枚举
  configurable: false,  // 不可再配置、不可 delete
});

// 存取属性：读写走函数
Object.defineProperty(obj, 'b', {
  get() { return this._b; },
  set(v) { this._b = v * 2; },
});
```

| 键 | 含义 | 用 defineProperty 定义时的默认值 |
|---|---|---|
| `value` | 属性值 | undefined |
| `writable` | 能否赋值修改 | **false** |
| `get` / `set` | 读写拦截函数 | undefined |
| `enumerable` | for...in / Object.keys / 展开运算符是否可见 | **false** |
| `configurable` | 能否改描述符、能否 delete | **false** |

两个易错点：

- **`value/writable` 与 `get/set` 不能混用**，同时给会 TypeError；
- 字面量赋值 `obj.x = 1` 创建的属性三个开关全是 **true**，而 `defineProperty` 不写就全是 **false**——「默认值相反」是经典细节题。

查看描述符：`Object.getOwnPropertyDescriptor(obj, 'a')` / `Object.getOwnPropertyDescriptors(obj)`。

---

## 2. defineProperty 的典型应用

- **Vue 2 响应式**：遍历 data 的每个属性，用 get 收集依赖（Dep 收集 Watcher）、set 通知更新。局限也在此：新增/删除属性拦截不到（要 `Vue.set`），数组下标赋值拦截不到（重写了 7 个数组方法），初始化要递归整棵对象树。对比 Proxy 方案见 [[1.08 Proxy 与 Reflect]]。
- **只读常量属性**：`writable: false + configurable: false`。
- **隐藏内部字段**：`enumerable: false`，遍历和 JSON.stringify 都看不见。
- **惰性求值属性**：get 里第一次算完后用 defineProperty 把自己替换成数据属性。

## 3. 对象的三级封印

| 方法 | 加属性 | 删属性 | 改值 | 检测 |
|---|---|---|---|---|
| `Object.preventExtensions(o)` | ✗ | ✓ | ✓ | `Object.isExtensible` |
| `Object.seal(o)` | ✗ | ✗ | ✓ | `Object.isSealed` |
| `Object.freeze(o)` | ✗ | ✗ | ✗ | `Object.isFrozen` |

都是**浅层**的：`freeze` 只冻第一层，嵌套对象要递归冻结（深冻结是常见手写题）。

## 4. valueOf、toString 与类型转换协议

对象转原始值时，引擎按「hint」调用这三样（优先级从高到低）：

1. `[Symbol.toPrimitive](hint)` —— 一票定乾坤，hint 是 'number' | 'string' | 'default'
2. hint 为 number/default：先 `valueOf()` 后 `toString()`
3. hint 为 string：先 `toString()` 后 `valueOf()`

```js
const money = {
  amount: 100,
  [Symbol.toPrimitive](hint) {
    return hint === 'string' ? '¥100' : 100;
  },
};
money + 1        // 101（hint: default → number）
`${money}`       // '¥100'（hint: string）
```

经典面试题「让 `a == 1 && a == 2 && a == 3` 为 true」就是利用 valueOf/toPrimitive 每次返回递增值。

**`Symbol.toStringTag`**：定制 `Object.prototype.toString` 的输出标签：

```js
class Collection { get [Symbol.toStringTag]() { return 'Collection'; } }
Object.prototype.toString.call(new Collection()); // '[object Collection]'
```

## 5. Object.is 的手写实现

React 源码 shallowEqual 的底层就是它，只修补 === 的两个偏差（±0 与 NaN）：

```js
function is(x, y) {
  if (x === y) {
    // 排除 +0 === -0：1/+0 = Infinity, 1/-0 = -Infinity
    return x !== 0 || y !== 0 || 1 / x === 1 / y;
  }
  // 只有 NaN !== NaN，利用自身不等于自身识别 NaN
  return x !== x && y !== y;
}
```

## 6. Symbol 的要点（含 polyfill 思路）

- 每次调用 `Symbol(desc)` 产生**全局唯一**值；`Symbol.for(key)` 走全局注册表可复用。
- **不能 new**（内部检查 this，polyfill 里 `if (this instanceof Symbol) throw`）。
- 作为对象 key 时：for...in、Object.keys、JSON.stringify 都**忽略**它，需要 `Object.getOwnPropertySymbols` 或 `Reflect.ownKeys` 才能拿到——适合挂「不想被业务代码碰到」的元数据。
- polyfill 只能模拟到「引用唯一」（返回带描述的空原型对象），模拟不了 `typeof x === 'symbol'` 和字面量行为——这也是「Symbol 为什么难 polyfill」的答案。

## 面试问答

### Q: 属性描述符有哪几种？各字段什么含义？

满分答案：数据描述符（value、writable）和存取描述符（get、set），互斥，共用 enumerable（枚举可见性）和 configurable（能否重定义/删除）。关键细节：字面量创建的属性三开关全 true，defineProperty 创建的默认全 false。查看用 Object.getOwnPropertyDescriptor。

### Q: Vue 2 为什么用 defineProperty？有什么局限？

满分答案：用 get/set 劫持属性实现依赖收集与派发更新。局限：只能劫持已存在的属性——新增/删除要 Vue.set/delete，数组下标与 length 变化拦不到（Vue 重写了 push 等 7 个方法），且初始化需递归遍历整个 data，深对象开销大。Vue 3 换 Proxy 整体代理，天然覆盖新增属性、delete、数组操作，并且是惰性代理。

### Q: Object.freeze 和 const 的区别？深冻结怎么做？

满分答案：const 锁的是变量绑定（不能重新赋值），freeze 锁的是对象内容（不能增删改属性），两者正交。freeze 是浅层的，深冻结需递归：对每个属性值先递归 freeze 再 freeze 自身。补充三级封印：preventExtensions 禁增、seal 再禁删、freeze 再禁改。

### Q: 对象转原始值的规则？如何让 a == 1 && a == 2 成立？

满分答案：按 Symbol.toPrimitive → valueOf/toString 的顺序（hint 为 string 时 toString 优先）。宽松相等时对象转原始值走 default hint，所以给对象定义 valueOf（或 Symbol.toPrimitive）让它每次返回自增值即可让 a == 1 && a == 2 && a == 3 为 true。这题考察点就是类型转换协议。

### Q: Symbol 有什么用？为什么难以 polyfill？

满分答案：用途——唯一 key 防属性冲突、隐藏元数据（各类遍历都忽略 symbol 键）、内置协议挂载点（Symbol.iterator、Symbol.toPrimitive、Symbol.toStringTag）。难 polyfill 因为唯一性可以用对象引用模拟，但 typeof 返回 'symbol' 和语言层的不可 new、隐式转字符串报错等行为，ES5 无法完全模拟。
