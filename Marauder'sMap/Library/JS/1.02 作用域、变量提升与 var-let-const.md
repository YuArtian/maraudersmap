# 作用域、变量提升与 var-let-const

## TL;DR

**JS 是词法作用域（静态作用域）：函数能访问哪些变量，在代码写下的那一刻就定了，与在哪调用无关**。var 有变量提升、无块级作用域；let/const 有块级作用域和暂时性死区。理解这三件事，能解掉一大类「输出题」。

---

## 1. 作用域与作用域链

作用域 = 变量的可访问范围。JS 有三级：**全局作用域、函数作用域、块级作用域**（ES6 起，`{}` + let/const）。

查找变量时，先找当前作用域，找不到就沿**作用域链**逐层向外，直到全局，再没有就 `ReferenceError`。关键点：

- 作用域链在**函数定义时**就确定了（词法作用域），保存在函数的内部属性 `[[Scopes]]` 上，与调用位置无关。
- 这正是闭包的基础：函数带着它定义处的作用域链走天下（详见 [[1.03 执行上下文、调用栈与闭包]]）。

```js
let x = 'global';
function outer() {
  let x = 'outer';
  function inner() { console.log(x); }
  return inner;
}
outer()();  // 'outer' —— 看定义位置，不看调用位置
```

## 2. 变量提升

引擎执行代码前有一个「编译」阶段，会先把声明登记到作用域里，这就是提升（hoisting）：

- **var**：声明提升，赋值不提升——提升后的初值是 `undefined`
- **函数声明**：整体提升（函数体一起），且**优先级高于同名 var 变量**
- **函数表达式**：只提升变量名，函数体不提升

经典输出题：

```js
function fn(a) {
  console.log(a);   // ƒ a() {}  ← 函数声明提升，覆盖了形参 1
  var a = 2;        // var a 与形参同名，编译阶段被忽略；这里只执行赋值
  function a() {}
  console.log(a);   // 2
}
fn(1);
```

理解口径：进入函数时按「形参 → 函数声明 → var 声明」的顺序登记，同名时函数声明胜出；执行阶段再按代码顺序赋值。

## 3. let、const 与暂时性死区（TDZ）

let/const 声明的变量其实**也会被登记**（所以块内声明会屏蔽外层同名变量），但在声明语句执行前处于**暂时性死区**，访问就抛 `ReferenceError`：

```js
let a = 1;
{
  console.log(a);  // ReferenceError！不是 1
  let a = 2;       // 块内的 let a 屏蔽了外层，但此刻还在 TDZ
}
```

连 `typeof` 也不再安全：`typeof x` 在 x 的 TDZ 内同样报错。

const 的「不可变」指**绑定不可变**：不能重新赋值，但对象内容可以改。

```js
const obj = { a: 1 };
obj.a = 2;    // OK
obj = {};     // TypeError
```

## 4. var / let / const 对比

| 维度 | var | let | const |
|---|---|---|---|
| 作用域 | 函数级 | 块级 | 块级 |
| 变量提升 | 提升，初值 undefined | 登记但有 TDZ | 登记但有 TDZ |
| 重复声明 | 允许（覆盖） | 报错 | 报错 |
| 重新赋值 | 允许 | 允许 | 报错 |
| 声明时必须赋值 | 否 | 否 | 是 |
| 全局声明挂到 globalThis | 是 | 否 | 否 |

实践准则：**默认 const，需要重新赋值才用 let，不写 var**。

## 5. 经典题：for 循环 + setTimeout

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));   // 3 3 3
}
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j));   // 0 1 2
}
```

- var：整个循环共享同一个 `i`，回调执行时循环早已结束，`i` 已是 3。
- let：**每轮迭代创建一个新的块级绑定**（规范规定），每个回调闭包捕获的是各自那一轮的 `j`。

ES5 时代的等价解法就是用 IIFE 手工制造一层作用域：

```js
for (var i = 0; i < 3; i++) {
  (function (k) {
    setTimeout(() => console.log(k));  // 0 1 2
  })(i);
}
```

## 6. IIFE：块级作用域出现前的私有化手段

立即调用函数表达式（IIFE）：把函数定义放进圆括号使其成为**表达式**，随即调用。

```js
const counter = (function () {
  let count = 0;                     // 外部无法访问
  return { inc: () => ++count };
})();
```

作用：制造私有作用域、避免变量污染全局——这是 ES6 模块和块级作用域普及前，模块模式的标准写法。现在的主要遗产是：理解它才能看懂老代码和 bundler 的输出产物。

## 面试问答

### Q: 说说 var、let、const 的区别？

满分答案：三个维度。作用域——var 是函数级，let/const 是块级；提升——var 声明提升且初值 undefined，let/const 存在暂时性死区，声明前访问抛 ReferenceError；约束——var 可重复声明，let/const 不可，const 还必须声明时赋值且不可重新绑定（但对象内容可改）。另外全局的 var 会成为 globalThis 属性，let/const 不会。实践中默认 const、需要重赋值用 let。

### Q: 什么是变量提升？函数声明和变量声明谁优先？

满分答案：执行前的编译阶段会把声明先登记进作用域：var 提升且初值为 undefined，函数声明整体提升（含函数体），函数表达式只提升变量名。同名时函数声明优先级高于 var 变量声明；执行阶段的赋值再按代码顺序覆盖。加分点：形参先于函数体内声明登记，同名 var 声明会被忽略、但同名函数声明会覆盖形参。

### Q: 什么是暂时性死区？

满分答案：块级作用域内 let/const 声明的变量，从块开始到声明语句执行之间的区域。变量已被登记（会屏蔽外层同名变量），但未初始化，访问抛 ReferenceError，typeof 也不例外。它的意义是把「先使用后声明」这种隐患变成显式错误。

### Q: for 循环里用 var 和 let 定时器输出为什么不同？

满分答案：var 时整个循环共享一个变量，回调是宏任务，执行时循环已结束，全部输出终值；let 时规范规定每轮迭代创建新的块级绑定，每个闭包捕获各自轮次的值，按 0、1、2 输出。ES5 的解法是用 IIFE 传参制造一层函数作用域。

### Q: IIFE 有什么用？

满分答案：立即调用函数表达式，用圆括号把函数变成表达式后立刻执行。核心价值是制造私有作用域：内部变量外部不可见，避免全局污染，是 ES6 之前实现模块模式的标准手段；也常用来在循环中固定变量值。
