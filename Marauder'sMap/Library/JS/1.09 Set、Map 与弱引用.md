# Set、Map 与弱引用

## TL;DR

**Set 存唯一值，Map 存任意类型 key 的键值对，两者都记住插入顺序、可遍历；Weak 版本只收对象、是弱引用、不可遍历**。选型口诀：要去重用 Set，key 不是字符串用 Map，想让缓存不阻碍垃圾回收用 WeakMap。

> Python set 与 JS Set 的跨语言对比见 [[1.06 Set 集合]]（Python 系列）。

---

## 1. Set：值的集合

```js
const s = new Set([1, 2, 2, NaN, NaN]);
s.size          // 3 —— 去重了，且 NaN 被认为等于自身
s.add(3).add(3) // add 返回 Set 本身，可链式
s.has(2)        // true
s.delete(2)     // true
```

判等规则是 **SameValueZero**：与 `===` 的唯一区别是 `NaN` 等于自身（`+0` 与 `-0` 仍相等）。所以 Set 能给 NaN 去重，但**对象按引用判断**——内容相同的两个对象不算重复。

集合运算（ES2025 已入标准，现代浏览器可用）：

```js
a.union(b)         a.intersection(b)      a.difference(b)
a.isSubsetOf(b)    a.isSupersetOf(b)      a.symmetricDifference(b)
```

老环境用展开 + filter 手写即可。

## 2. Map：真正的键值对

Object 当字典的三大痛点：key 只能是字符串/Symbol、有原型链干扰（`constructor` 等键名可能撞车）、没有可靠的 size。Map 全部解决：

```js
const m = new Map([['a', 1]]);
m.set(obj, 'v');       // 任意类型做 key，包括对象、NaN
m.get(obj);            // 'v'
m.size;                // 2
[...m];                // 可展开、可 for...of，顺序 = 插入顺序
```

| | Map | Object |
|---|---|---|
| key 类型 | 任意（对象、NaN 都行） | 字符串 / Symbol |
| 顺序 | 严格按插入顺序 | 整数键会被提前排序 |
| size | `.size` | 手动 `Object.keys().length` |
| 原型干扰 | 无 | 有（除非 `Object.create(null)`） |
| JSON | 不能直接序列化 | 原生支持 |
| 频繁增删性能 | 更优 | 一般 |

经验法则：**结构固定、要序列化 → Object；当字典频繁增删查、key 类型复杂 → Map**。

## 3. WeakMap / WeakSet：弱引用版本

「弱引用」= **不阻止垃圾回收**。普通 Map 用对象做 key 时，Map 会拽着这个对象不放，对象哪怕别处都不用了也回收不掉；WeakMap 的 key 是弱引用，对象没人用了就连同关联值一起被回收。

代价换来的限制：

- key 只能是对象（WeakSet 成员只能是对象）；
- **不可遍历、没有 size**——因为成员随时可能被 GC 掉，遍历结果无法保证一致；
- 只有 get/set/has/delete 四个方法。

三大典型用途：

```js
// ① 给 DOM 节点挂元数据：节点移除后数据自动回收
const meta = new WeakMap();
meta.set(dom, { clicks: 0 });

// ② 缓存计算结果：对象在则缓存在，对象亡则缓存亡
const cache = new WeakMap();
function process(obj) {
  if (!cache.has(obj)) cache.set(obj, heavyCompute(obj));
  return cache.get(obj);
}

// ③ 实现真私有属性（ES2022 #字段普及前的方案）
const privates = new WeakMap();
class A {
  constructor() { privates.set(this, { secret: 1 }); }
}
```

Vue 3 的 `reactiveMap`（见 [[1.08 Proxy 与 Reflect]]）就是 WeakMap：组件销毁、原对象失去引用后，对应的 Proxy 自动可回收。

---

## 4. 遍历接口

Set 和 Map 都实现了 `Symbol.iterator`，四件套一致：`keys()` / `values()` / `entries()` / `forEach()`。Set 的 keys 和 values 相同（键值同体）；Map 默认迭代 entries，配合解构很顺手：

```js
for (const [k, v] of map) { ... }
```

## 面试问答

### Q: Set、Map、WeakSet、WeakMap 的区别？

满分答案：Set 存唯一值，判等用 SameValueZero（NaN 等于自身）；Map 是键值对集合，key 可以是任意类型且严格保持插入顺序；两者都可遍历。Weak 版本三个特点——只接受对象（作为成员/key）、弱引用不阻止垃圾回收、不可遍历没有 size。典型应用：Set 去重、Map 做复杂 key 字典、WeakMap 给 DOM 挂数据和做对象级缓存防内存泄漏。

### Q: Map 和 Object 怎么选？

满分答案：Object 适合结构固定的「记录」，字面量方便、可 JSON 序列化；Map 适合当「字典」——key 类型任意、无原型链干扰、有 size、插入顺序稳定、频繁增删性能更好。补充细节：Object 的整数型键会被引擎重排到前面，Map 不会；防原型污染场景下 Map 或 Object.create(null) 都是答案。

### Q: WeakMap 为什么不能遍历？

满分答案：因为 key 是弱引用，成员随时可能被垃圾回收，遍历中集合内容都可能变化，规范干脆不提供遍历和 size，只留 get/set/has/delete。这不是缺陷而是设计契约：它的定位就是「不影响对象生命周期的关联表」。

### Q: 用 Set 给对象数组去重行吗？

满分答案：不行，Set 按引用判等，内容相同的两个对象不重复。对象去重要自定义判等：浅层的可以 JSON.stringify 后比对（注意 key 顺序问题），严谨做法是递归比较（长度 + 逐 key 深比较，原始值用 Object.is 处理 NaN），或者按业务唯一键（如 id）用 Map 去重——`new Map(arr.map(o => [o.id, o])).values()`。
