# 柯里化、偏函数与 compose

## TL;DR

**柯里化：把 f(a,b,c) 变成 f(a)(b)(c)，参数攒够了才执行——靠闭包记参数、靠 fn.length 知道「够没够」**。偏函数是它的简化版（一次固定部分参数）。compose 把多个单参函数串成流水线，`reduce` 一行实现，是 Redux 中间件和管道思想的地基。

---

## 1. 柯里化（curry）

```js
function curry(fn, saved = []) {
  return (...args) => {
    const all = [...saved, ...args];
    return all.length >= fn.length     // fn.length = 形参个数
      ? fn(...all)                     // 攒够了，执行
      : curry(fn, all);                // 没够，继续收集
  };
}

const add = (a, b, c) => a + b + c;
const cAdd = curry(add);
cAdd(1)(2)(3)   // 6
cAdd(1, 2)(3)   // 6 —— 支持一次传多个
```

原理拆解：**闭包保存已收参数 + 递归返回收集函数 + fn.length 做完成判定**。注意 fn.length 不计默认参数和 rest 参数，所以被柯里化的函数别用默认值。

实际用途（别只会背实现）：

```js
// 参数复用：造一批「特化」函数
const isType = curry((type, val) =>
  Object.prototype.toString.call(val) === `[object ${type}]`);
const isArray = isType('Array');
const isDate = isType('Date');

// 延迟执行：事件绑定时先固定配置
const log = curry((level, msg) => console[level](msg));
button.onclick = () => log('warn')('clicked');
```

经典变体题「实现 add(1)(2)(3)() 或 add(1)(2)(3) 打印结果」：参数不定长时没有 fn.length 可判，改用**空调用触发**或重写 `toString/valueOf`（隐式转换时求值）——考的是 [[1.07 对象属性与属性描述符]] 里的类型转换协议。

## 2. 偏函数（partial）

一次性固定前几个参数，返回等待剩余参数的函数——不像柯里化那样层层单收：

```js
const partial = (fn, ...preset) => (...later) => fn(...preset, ...later);

const double = partial((x, y) => x * y, 2);
double(5)   // 10
```

`bind` 天生就是偏函数工具：`fn.bind(null, 1, 2)`。柯里化 vs 偏函数一句话：**柯里化是「分多次、每次可少给」的自动挡，偏函数是「一次固定、剩下一把给」的手动挡**。

---

## 3. compose 与 pipe

把 n 个函数串成一个：`compose(f, g, h)(x) === f(g(h(x)))`（从右往左），pipe 反向（从左往右，更符合阅读顺序）：

```js
const compose = (...fns) =>
  fns.reduce((a, b) => (...args) => a(b(...args)));

const pipe = (...fns) =>
  fns.reduce((a, b) => (...args) => b(a(...args)));

const addOne = x => x + 1;
const square = x => x * x;
compose(square, addOne)(2)  // (2+1)² = 9
pipe(addOne, square)(2)     // 同样 9，但书写顺序即执行顺序
```

reduce 版的精妙处：每次合并两个函数为一个新函数，最终折叠成单函数；只有最右（pipe 是最左）的函数可以接多参，其余必须单进单出。

**Redux 的 compose 就是这一行**，`applyMiddleware` 用它把中间件层层包裹：`compose(mw1, mw2, mw3)(store.dispatch)` 产出增强版 dispatch——洋葱模型的函数式表达。Koa 的 compose 是它的异步版（支持 await next()）。

---

## 4. 反柯里化（了解即可）

方向相反：把「对象的方法」提取成「接收对象为首参的通用函数」，本质是借方法：

```js
const uncurry = fn => (obj, ...args) => fn.call(obj, ...args);

const toString = uncurry(Object.prototype.toString);
toString([]);      // '[object Array]' —— 任何对象都能用了
const push = uncurry(Array.prototype.push);
push(arrayLike, 4); // 类数组也能 push
```

## 面试问答

### Q: 什么是柯里化？手写一个 curry？

满分答案：把多参函数转化为逐次接收参数的函数序列，参数集齐才执行。实现三要素：闭包数组累积参数、每次返回继续收集的函数、用 fn.length 判断是否够数，够则展开执行。价值在参数复用（批量生成特化函数）和延迟执行。注意 fn.length 不含默认参数与 rest 参数。

### Q: 柯里化和偏函数的区别？

满分答案：柯里化把 f(a,b,c) 拆成可以 f(a)(b)(c) 逐步喂参的形式，每步可给任意个数、自动判断何时执行；偏函数只做一次参数固定，返回的函数一口气接收剩余参数，bind 就是内置的偏函数工具。柯里化是更彻底的抽象，偏函数是它的常用特例。

### Q: 手写 compose？它在哪些框架里出现？

满分答案：fns.reduce((a, b) => (...args) => a(b(...args)))，从右向左执行；pipe 调换 a、b 即从左向右。应用：Redux 的 applyMiddleware 用 compose 把中间件包裹成增强 dispatch；Koa 的洋葱模型是异步版 compose；lodash/fp 和 RxJS 的 pipe 是同一思想。追问点：除首个被调函数外，其余函数必须单参单返回，这正是柯里化在函数式管道里的意义——把多参函数变成单参才能入管道。

### Q: 实现 add(1)(2)(3) 可以无限调用、参数不定长怎么办？

满分答案：不定长意味着永远「没够」，无法用 fn.length 判定，改成惰性求值：返回的函数持续收集参数，同时重写其 toString/valueOf（或 Symbol.toPrimitive），在被隐式转换（打印、参与运算）时汇总求和。这题实际考类型转换协议 + 闭包，回答时点破考点。
