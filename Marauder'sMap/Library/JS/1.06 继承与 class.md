# 继承与 class

## TL;DR

**ES5 继承的最优解是寄生组合式继承：`Parent.call(this)` 继承实例属性 + `Object.create(Parent.prototype)` 继承原型方法**。ES6 class 是它的语法糖但不完全等价——class 必须 new、内部严格模式、方法不可枚举、子类 this 由父类构造，static 也能继承。

---

## 1. ES5 继承的演进（为什么最终是寄生组合式）

| 方案 | 做法 | 缺陷 |
|---|---|---|
| 原型链继承 | `Child.prototype = new Parent()` | 引用类型属性被所有实例共享；无法向父类传参 |
| 借用构造函数 | `Parent.call(this)` | 只继承实例属性，拿不到原型方法 |
| 组合继承 | 上面两个都做 | 父类构造函数被调用两次，子类原型上多一份无用的实例属性 |
| **寄生组合式** | call + Object.create | 无缺陷，ES5 最优解 |

寄生组合式继承完整写法（手写高频）：

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red'];        // 引用类型属性，各实例独立
}
Parent.prototype.getName = function () { return this.name; };

function Child(name, age) {
  Parent.call(this, name);      // ① 继承实例属性（可传参）
  this.age = age;
}
Child.prototype = Object.create(Parent.prototype);  // ② 继承原型方法
Child.prototype.constructor = Child;                // ③ 修正 constructor
```

三个判分点：`call` 传参、`Object.create` 而不是 `new Parent()`、修正 `constructor`。

## 2. ES6 class 写法

```js
class Parent {
  constructor(name) { this.name = name; }
  getName() { return this.name; }            // 原型方法
  static isParent(o) { return o instanceof Parent; }  // 静态方法
  #secret = 42;                               // 私有字段（ES2022）
  get info() { return this.name; }            // 访问器
}

class Child extends Parent {
  constructor(name, age) {
    super(name);      // 必须先 super 才能用 this
    this.age = age;
  }
}
```

super 的两副面孔：

- **构造函数里 `super(args)`**：调用父类构造函数，生成 this——所以子类 constructor 里 super 之前不能碰 this；
- **方法里 `super.method()`**：沿原型找父类方法，调用时 this 仍是当前实例。

## 3. class 和 ES5 构造函数的区别（高频对比题）

1. **必须 new**：直接调用抛 `TypeError: Class constructor cannot be invoked without 'new'`；ES5 构造函数可以直接调用。
2. **内部默认严格模式**。
3. **方法不可枚举**：`for...in` 遍历不到 class 的方法，ES5 原型方法可以。
4. **没有提升的可用性**：class 声明有暂时性死区，必须先定义后使用（父类必须写在子类前）。
5. **this 的来路不同**：ES5 里 this 由子类创建、再借父类构造函数装饰；ES6 里 this 由父类（super）创建、子类再加工——这就是 class 能正确继承内置类型（Array、Error）而 ES5 不行的原因。
6. **静态属性可继承**：`extends` 会同时设置 `Child.__proto__ = Parent`，静态成员沿这条链查找；ES5 需要手动 `Object.setPrototypeOf(Child, Parent)`。

Babel 把 class 编译成什么（体现「语法糖」的本质）：

```js
// 只保留骨架：与寄生组合式继承一一对应
function _inherits(sub, sup) {
  sub.prototype = Object.create(sup.prototype, {
    constructor: { value: sub, writable: true, configurable: true },
  });
  Object.setPrototypeOf(sub, sup);   // 静态继承，比手写 ES5 多的一步
}
function _classCallCheck(inst, Ctor) {
  if (!(inst instanceof Ctor)) throw new TypeError('Cannot call a class as a function');
}
```

## 4. 私有字段与装饰器（新特性加分项）

**私有字段 `#x`**（ES2022，已进正式标准）：真私有，类外访问直接语法错误，比闭包方案和 `_x` 约定都强；`#x in obj` 可用来做品牌检查。

```js
class Counter {
  #count = 0;
  inc() { return ++this.#count; }
  static isCounter(o) { return #count in o; }
}
```

**装饰器 `@decorator`**：给类和类成员做包装增强的语法。注意现状（面试别说错）：**TC39 提案处于 Stage 3，截至 2026 年初浏览器尚未原生支持，生产中依赖 TypeScript 5+ 或 Babel 编译**；只能装饰类和类成员，不能装饰普通函数（函数提升会破坏装饰时机）。Angular/NestJS/MobX 是重度使用者。

## 面试问答

### Q: ES5 有哪些继承方式？为什么寄生组合式最优？

满分答案：原型链继承共享引用属性且无法传参；借用构造函数拿不到原型方法；组合继承两者兼得但父类构造函数执行两次，子类原型上残留一份多余实例属性。寄生组合式用 Parent.call(this) 继承实例属性、Object.create(Parent.prototype) 接原型链、修正 constructor，父类构造只跑一次、原型干净，是 ES5 最优解，也是 Babel 编译 class 的实现基础。

### Q: class 继承和 ES5 继承有什么区别？

满分答案：核心区别是 this 的产生顺序——ES5 先创建子类 this 再用父类构造函数装饰；class 是 super() 调用父类先造出 this，子类再加工，所以 class 能正确继承 Array、Error 等内置类型。其他区别：class 必须 new、内部严格模式、方法不可枚举、有暂时性死区、extends 自动继承静态成员（Child.__proto__ === Parent）。

### Q: super 是什么？为什么子类 constructor 必须先调 super？

满分答案：constructor 里 super 是父类构造函数，方法里 super 是父类原型的引用（调用时 this 仍是当前实例）。必须先调是因为子类的 this 由父类构造产生，super() 执行前 this 根本不存在，访问会抛 ReferenceError；不写 constructor 时引擎会自动补 `constructor(...args) { super(...args); }`。

### Q: 如何实现类的私有属性？

满分答案：按时代排——约定下划线前缀（无强制力）；闭包 + WeakMap（真私有但写法繁琐）；ES2022 私有字段 #x，语言级私有，类外访问是语法错误，还支持 #x in obj 做品牌检查，是当前标准方案。

### Q: 装饰器是什么？现在能用吗？

满分答案：用 @ 函数对类和类成员做声明式包装增强的语法，常见于依赖注入（NestJS/Angular）和响应式（MobX）。现状要说准：TC39 Stage 3，浏览器未原生支持，生产靠 TypeScript 5+（已实现标准版装饰器）或 Babel 编译；只能装饰类和类成员、不能装饰普通函数。
