# 执行上下文、调用栈与闭包

## TL;DR

**闭包 = 函数 + 它定义时的词法环境引用**。函数被调用时创建执行上下文并压入调用栈；即使外层函数出栈了，只要内部函数还活着，它引用的外层变量就跟着活着——这就是闭包。好处是私有状态，代价是内存占用。

> 引擎架构层面的堆、栈、队列全景见 [[JS执行模型]]。

---

## 1. 执行上下文

执行上下文（Execution Context）是代码运行的环境，共三类：**全局上下文**（程序启动创建一次）、**函数上下文**（每次调用创建）、eval 上下文（不用管）。

每个上下文创建时确定三样东西：

1. **变量环境**：var 声明和函数声明（对应变量提升）
2. **词法环境**：let/const 声明、对外层环境的引用（对应作用域链）
3. **this 绑定**（详见 [[1.04 this 与 call、apply、bind]]）

---

## 2. 调用栈

函数调用创建上下文并**压栈**，执行完**出栈**，栈底永远是全局上下文。

```mermaid
flowchart LR
    subgraph 调用栈（后进先出）
        direction TB
        C["inner() 的上下文（栈顶，执行中）"] --> B["outer() 的上下文"] --> A["全局上下文（栈底）"]
    end
```

栈的容量有限，递归太深就会爆栈：

```js
let depth = 0;
function probe() { depth++; return probe(); }
probe();  // RangeError: Maximum call stack size exceeded（Chrome 大约 1 万多层）
```

规避思路是**把递归拆到异步任务里**——每次调用在新的宏/微任务中执行，调用栈每轮都清空：

```js
async function safe(n) {
  await undefined;          // 让后续代码进微任务，当前栈帧先退出
  if (n <= 0) return;
  return safe(n - 1);       // 永远不会爆栈
}
```

**堆和栈的分工**：栈存原始值和对象引用，函数调用结束自动回收；堆存对象本体，靠垃圾回收器管理。

## 3. 闭包是什么

MDN 定义：**闭包是函数与其词法环境的组合**——函数「记住」了自己定义时能访问的变量。

```js
function counter() {
  let count = 0;            // 被闭包捕获，counter 返回后依然存活
  return () => ++count;
}
const inc = counter();
inc(); // 1
inc(); // 2 —— count 的状态被保住了
```

**V8 层面的实现细节**（面试深度加分）：函数预编译时，引擎会扫描其内部函数引用了哪些外部变量，把这些变量收进一个 `Closure` 闭包对象，挂到内部函数的作用域链上。两个要点：

- 只有**被内部函数引用的变量**才进闭包对象，没被引用的照常随栈回收（引擎优化）；
- 同一个外层函数的**所有内部函数共享同一个闭包对象**——只要还有一个内部函数活着，整个闭包对象都不能回收。

在 DevTools 里断点观察作用域面板的 Closure 项，就能直接看到这个对象。

## 4. 闭包的应用场景

| 场景 | 用法 |
|---|---|
| 私有状态 | 计数器、单例、工厂函数里的私有变量 |
| 防抖节流 | 用闭包保存 timer（见 [[3.02 防抖与节流]]） |
| 柯里化 / 偏函数 | 闭包缓存已传入的参数（见 [[3.03 柯里化、偏函数与 compose]]） |
| 模块模式 | IIFE + 闭包 = ES6 模块之前的模块方案 |
| 回调保存上下文 | 事件处理器、定时器回调记住定义时的数据 |

---

## 5. 闭包与内存泄漏

闭包本身不是泄漏，**「用完了却还被引用着」才是泄漏**。根因就是上面的共享机制：闭包对象被所有内部函数的作用域链共同引用，只要有一个内部函数没被释放（比如挂在全局、挂在 DOM 事件上没解绑），整个闭包对象里的变量全部无法回收。

```js
function heavy() {
  const bigData = new Array(1e6).fill('x');
  const leak = () => bigData.length;   // bigData 进了闭包对象
  window.handler = leak;               // leak 永远活着 → bigData 永远不释放
}
```

对策：不再需要时解除引用（`window.handler = null`、`removeEventListener`）；避免在闭包里长期持有大对象，必要时用完置 null。

## 6. 尾调用与尾递归

尾调用：函数的**最后一步**是调用另一个函数且无后续操作。理论上可以做尾调用优化（TCO）——外层栈帧直接被内层复用，递归再深也只占一个栈帧：

```js
function factorial(n, total = 1) {
  if (n <= 1) return total;
  return factorial(n - 1, n * total);  // 尾递归：把中间结果收进参数
}
```

现实注意：**TCO 虽写进了 ES6 规范（严格模式下），但主流引擎中只有 Safari 的 JavaScriptCore 实现了，V8 没有**。所以在 Chrome/Node 里尾递归照样爆栈——面试说到这一点很加分；工程上防爆栈还是靠改循环或异步化。

## 面试问答

### Q: 什么是闭包？有什么作用和缺点？

满分答案：闭包是函数与其定义时词法环境的组合——内部函数可以访问外层函数的变量，即使外层函数已经返回。作用：创建私有状态（计数器、模块模式）、在回调中保存上下文，防抖节流和柯里化都靠它。缺点：被捕获的变量无法随栈回收，滥用会增大内存占用甚至泄漏。加分点：V8 中闭包变量收在 Closure 对象里，同一外层函数的所有内部函数共享一个闭包对象，且只收内部函数真正引用到的变量。

### Q: 执行上下文是什么？创建时发生了什么？

满分答案：代码运行的环境，分全局上下文和函数上下文（每次调用新建），由调用栈管理。创建阶段确定三件事：变量环境（var 与函数声明，即变量提升）、词法环境（let/const 与外层引用，即作用域链）、this 绑定。执行阶段再逐行赋值和运行。

### Q: 闭包为什么可能内存泄漏？如何避免？

满分答案：闭包对象被外层函数所有内部函数的作用域链共享，只要任何一个内部函数还被引用（全局变量、未解绑的事件监听、定时器），整个闭包对象里的变量都无法回收。避免：及时解绑事件和定时器、不用的引用置 null、不在闭包里长期持有大对象。定位手段：DevTools 内存快照对比，看 Closure 的 retained size。

### Q: 调用栈深度大概多少？如何写一个不爆栈的无限递归？

满分答案：栈容量有限，Chrome 下普通递归约一万多层就抛 RangeError。规避方法是让每次「递归」发生在新的任务里：比如 async 函数中先 await 一次再调用自身，后续逻辑进了微任务队列，当前栈帧已退出，调用栈不累积。同理也可用 setTimeout 宏任务实现。本质是把「深栈」摊平成「多任务」。

### Q: 什么是尾递归优化？JS 里能用吗？

满分答案：函数最后一步仅调用自身且不依赖当前栈帧时，引擎可复用栈帧，使递归只占 O(1) 栈空间；改写手法是把中间结果收进参数。但要指出现状：ES6 规范要求严格模式下支持，实际只有 Safari 的 JavaScriptCore 实现，V8（Chrome/Node）没有，所以工程上不能依赖，防爆栈应改写为循环或异步化。
