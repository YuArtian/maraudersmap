# Proxy 与 Reflect

## TL;DR

**Proxy 在目标对象前架一层拦截，13 种 trap 覆盖属性读写、in、delete、遍历、new 等几乎所有对象操作；Reflect 提供与 trap 一一对应的默认行为**。在 trap 里用 `Reflect.xxx` 转发并透传 `receiver`，是保证 this 正确、getter 不失真的标准姿势——这就是 Vue 3 响应式的地基。

---

## 1. Proxy 基本用法

```js
const proxy = new Proxy(target, {
  get(target, key, receiver) {
    console.log(`读 ${String(key)}`);
    return Reflect.get(target, key, receiver);
  },
  set(target, key, value, receiver) {
    console.log(`写 ${String(key)} = ${value}`);
    return Reflect.set(target, key, value, receiver);  // 返回布尔值
  },
});
```

13 种 trap 按用途分组记：

| 组 | trap | 拦截的操作 |
|---|---|---|
| 读写 | `get` / `set` | `p.x`、`p.x = v` |
| 存在性 | `has` / `deleteProperty` | `'x' in p`、`delete p.x` |
| 枚举 | `ownKeys` | Object.keys、for...in、getOwnPropertyNames/Symbols |
| 描述符 | `getOwnPropertyDescriptor` / `defineProperty` | 对应同名 Object 方法 |
| 原型 | `getPrototypeOf` / `setPrototypeOf` | 对应同名 Object 方法 |
| 扩展 | `isExtensible` / `preventExtensions` | 对应同名 Object 方法 |
| 函数 | `apply` / `construct` | `p(...)`、`new p(...)`（目标是函数时） |

对比 `Object.defineProperty`：Proxy 代理**整个对象**而非单个属性——新增属性、delete、数组下标和 length、in 操作全都拦得住，且不需要初始化时递归遍历。

---

## 2. 为什么 trap 里要用 Reflect（高频深挖题）

Reflect 的方法与 Proxy trap **一一对应、签名相同**，在 trap 里调用它等于执行「默认行为」。不用 `target[key]` 而用 `Reflect.get(target, key, receiver)`，核心原因是 **receiver 保住了 this**：

```js
const parent = {
  _name: 'parent',
  get name() { return this._name; },   // getter 里有 this
};
const proxy = new Proxy(parent, {
  get(target, key, receiver) {
    return Reflect.get(target, key, receiver);
  },
});
const child = Object.create(proxy);
child._name = 'child';

child.name  // 'child' ✔ receiver 是 child，getter 的 this 指向 child
// 若 trap 里写 target[key]：getter 的 this 是 parent，错误地返回 'parent'
```

对响应式库的实际意义：访问继承属性、getter 计算属性时，依赖必须收集到**真正发起访问的对象**上，receiver 丢了依赖就挂错了地方。

Reflect 的另外两个卖点：

- **操作函数化**：`in`/`delete` 等语法操作变成 `Reflect.has`/`Reflect.deleteProperty`，可组合、可传递；
- **失败返回布尔而不抛错**：`Reflect.defineProperty` 失败返回 false，代替 try/catch。

## 3. 手写响应式：defineProperty 版 vs Proxy 版

Vue 2 思路（defineProperty，逐属性劫持 + 递归）：

```js
function defineReactive(obj, key, value) {
  observe(value);                      // 递归劫持嵌套对象
  const dep = new Dep();
  Object.defineProperty(obj, key, {
    get() {
      if (Dep.target) dep.depend();    // 依赖收集：记录当前 Watcher
      return value;
    },
    set(newVal) {
      if (newVal === value) return;
      observe(newVal);
      value = newVal;
      dep.notify();                    // 派发更新
    },
  });
}
```

Vue 3 思路（Proxy，整体代理 + 惰性递归 + WeakMap 缓存）：

```js
const reactiveMap = new WeakMap();

function reactive(target) {
  if (typeof target !== 'object' || target === null) return target;
  const existing = reactiveMap.get(target);
  if (existing) return existing;       // 同一对象只代理一次

  const proxy = new Proxy(target, {
    get(target, key, receiver) {
      track(target, key);              // 依赖收集
      const res = Reflect.get(target, key, receiver);
      return typeof res === 'object' && res !== null
        ? reactive(res)                // 惰性：访问到才代理子对象
        : res;
    },
    set(target, key, value, receiver) {
      const ok = Reflect.set(target, key, value, receiver);
      trigger(target, key);            // 派发更新
      return ok;
    },
  });
  reactiveMap.set(target, proxy);
  return proxy;
}
```

两版对比（也是 Vue 2/3 响应式区别的标准答案）：

| | defineProperty（Vue 2） | Proxy（Vue 3） |
|---|---|---|
| 劫持粒度 | 逐属性 | 整个对象 |
| 新增/删除属性 | 拦不到（Vue.set） | 拦得到 |
| 数组下标 / length | 拦不到（重写 7 方法） | 拦得到 |
| 初始化开销 | 递归整棵树 | 惰性，访问到才代理 |
| 兼容性 | IE9+ | 不支持 IE，无法完整 polyfill |

## 4. Proxy 的其他实用场景

- **数据校验**：set 里校验类型/范围，非法直接 throw；
- **负索引数组**：get 里把 `arr[-1]` 映射成 `arr[len-1]`；
- **默认值 / 防御式访问**：get 里对不存在的 key 返回默认值或警告；
- **API 记录与埋点**：apply trap 统计函数调用；
- **只读视图**：set/deleteProperty 一律返回 false（Vue 3 的 readonly）。

注意事项：目标对象上**不可配置且不可写**的属性，Proxy 必须如实返回，篡改会 TypeError（不变量约束）；Proxy 自身有一层调用开销，热路径慎用。

## 面试问答

### Q: Proxy 相比 Object.defineProperty 强在哪？

满分答案：defineProperty 只能劫持「已知的、单个的」属性，新增/删除属性、数组下标和 length 都拦不到，还得初始化递归整棵对象树；Proxy 代理整个对象，13 种 trap 覆盖读写、in、delete、遍历、new 等几乎全部操作，天然支持数组和动态属性，且可以惰性代理。代价是无法被完整 polyfill、不兼容 IE。这就是 Vue 3 从 defineProperty 切换到 Proxy 的原因。

### Q: 为什么 Proxy 的 trap 里要配合 Reflect 使用？

满分答案：三层原因。第一，Reflect 方法与 trap 一一对应，是「默认行为」的标准实现，语义清晰；第二，也是关键——receiver 参数：目标对象的 getter/setter 里若有 this，用 target[key] 转发 this 会错误地指向原对象，Reflect.get(target, key, receiver) 能让 this 指向实际发起操作的对象，继承场景下依赖才能收集到正确的对象上；第三，Reflect 把命令式语法变成函数调用、失败返回布尔值，更适合在 trap 里做转发和判断。

### Q: 手写一个简易 reactive？

满分答案要点：入口判断非对象直接返回；WeakMap 缓存避免重复代理同一目标；get 里 track 收集依赖、Reflect.get 取值、若值是对象则递归 reactive（惰性代理）；set 里 Reflect.set 后 trigger 派发更新并返回布尔值。加分点：用 WeakMap 而非 Map 是为了目标对象可被垃圾回收；再提一句 ref 用于原始值（对象包一层 .value）。

### Q: Proxy 有哪些实际应用场景？

满分答案：框架响应式（Vue 3 reactive/readonly）、数据校验与只读视图、负索引等语法增强、函数调用埋点（apply trap）、单测中的 mock 对象。同时指出限制：不变量约束（不可配置不可写属性必须如实返回）、每次操作多一层函数调用的性能开销、无法 polyfill 到 ES5 环境。
