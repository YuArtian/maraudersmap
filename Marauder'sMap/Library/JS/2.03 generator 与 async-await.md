# generator 与 async-await

## TL;DR

**generator 是可以暂停/恢复的函数（yield 暂停、next 恢复），async/await 就是「generator + 自动执行器」的语法糖**。手写一个 co 执行器（next 拿到 Promise → then 里再 next）就能把这层糖亲手还原出来，这是本主题面试的终极题。

---

## 1. generator 基础

```js
function* gen() {
  const a = yield 1;   // ① 暂停，向外抛出 1
  console.log(a);      // ③ 恢复时，next 的参数变成 yield 的返回值
  const b = yield 2;
  return 'done';
}

const it = gen();       // 只拿到迭代器，函数体一行都没执行
it.next();              // { value: 1, done: false }  执行到第一个 yield
it.next('A');           // 打印 'A'；{ value: 2, done: false }
it.next('B');           // { value: 'done', done: true }
it.next();              // { value: undefined, done: true }
```

三条铁律：

1. 调用 generator 函数**不执行函数体**，只返回迭代器；
2. `next(arg)` 的参数是**上一个 yield 表达式的返回值**——所以第一次 next 传参无意义；
3. `value` 是 yield 后面表达式的值，`done` 在 return 后变 true（return 值只出现这一次）。

配套能力：`it.throw(err)` 把错误注入到 yield 处（可被函数内 try/catch 捕获）、`it.return(v)` 提前终结；`yield* 另一个generator` 委托执行。generator 天然实现了迭代器协议，可以 for...of / 展开（此时忽略 return 值）。

---

## 2. 用 generator 写「同步风格」的异步

yield 一个 Promise，把「等待」表达出来，但需要有人在 then 里帮我们调 next——这个「有人」就是执行器：

```js
function* readFlow() {
  const user = yield fetchUser();        // 暂停，等 Promise
  const posts = yield fetchPosts(user.id);
  return posts.length;
}
```

---

## 3. 手写 co 执行器（本主题核心考题）

```js
function co(it) {
  return new Promise((resolve, reject) => {
    function next(prev) {
      let result;
      try {
        result = it.next(prev);          // 恢复执行，拿到 { value, done }
      } catch (e) { return reject(e); }  // 函数体内同步抛错
      if (result.done) return resolve(result.value);
      Promise.resolve(result.value)      // 兼容 yield 普通值
        .then(next, (err) => {
          try { next(it.throw(err)); }   // 把异步错误注回 generator
          catch (e) { reject(e); }
        });
    }
    next();
  });
}

co(readFlow()).then(console.log);
```

流程：**next 拿到 yield 出来的 Promise → then 里把结果传回 next → 循环往复直到 done**。错误处理是判分点：异步失败要用 `it.throw` 注回去，让 generator 内部的 try/catch 有机会接住。

## 4. async/await = generator + 内置执行器

```js
async function readFlow() {
  const user = await fetchUser();
  const posts = await fetchPosts(user.id);
  return posts.length;
}
```

与 co 版逐行对应：`async function` ≈ `function*` 外包 co，`await` ≈ `yield`。async/await 的额外规则：

- async 函数**必然返回 Promise**（return 值被 Promise.resolve 包装，抛错变 rejection）；
- await 后面的代码进微任务（时序分析见 [[2.01 事件循环与宏微任务]]）；
- 错误用 try/catch 捕获，或在调用侧 .catch()。

**串行 vs 并行**——最常见的 await 性能反模式：

```js
// ✗ 串行：总耗时 = a + b
const a = await fetchA();
const b = await fetchB();

// ✓ 并行：总耗时 = max(a, b)
const [a2, b2] = await Promise.all([fetchA(), fetchB()]);
```

循环中的规则同理：`for...of + await` 串行（需要顺序依赖时用）；`map 出 Promise 数组 + Promise.all` 并行；**forEach + await 是错的**——forEach 不等待，循环「秒完」而任务还在飞。

## 面试问答

### Q: generator 是什么？next 的参数和返回值怎么理解？

满分答案：带 * 的函数，调用时不执行函数体只返回迭代器；yield 暂停并向外抛值，next 恢复执行。next 返回 { value, done }，value 是当前 yield 后表达式的值；next(arg) 的 arg 是上一个 yield 表达式的返回值，因此第一次 next 的参数无意义。补充：it.throw 可把错误注入 yield 处，yield* 委托给另一个可迭代对象，generator 本身实现了迭代器协议。

### Q: async/await 的原理？

满分答案：generator + 自动执行器的语法糖。执行器逻辑：调 next 得到 yield 出的 Promise，在其 then 里把结果作为参数再调 next，循环到 done 后 resolve；异步错误通过 it.throw 注回 generator 使内部 try/catch 生效——这就是 co 库约 20 行的核心。Babel 编译 async 函数的产物正是 generator + 类似执行器（regenerator-runtime）。加分点：async 函数必返回 Promise，await 之后的代码在微任务中执行。

### Q: await 在循环里怎么用才对？

满分答案：看依赖关系。有顺序依赖用 for...of + await 串行；相互独立则先 map 成 Promise 数组再 Promise.all 并行，耗时从求和变为取最大。绝不能用 forEach + await——forEach 不等待异步回调，循环立即结束、错误也丢失。需要「并行但限流」时用并发池（见 [[2.04 并发控制与耗时任务优化]]）。

### Q: generator 有什么实际应用？

满分答案：三类——异步流程控制（co/redux-saga 的基础，saga 用 yield 描述副作用便于测试）；惰性序列与无限序列（按需生成，配合 for...of）；自定义迭代器（给对象实现 Symbol.iterator 最省事的方式就是写个 generator）。如今业务代码多被 async/await 覆盖，但理解它是理解 async 原理和读懂 saga 类库的前提。
