# this 与 call、apply、bind

## TL;DR

**this 在函数被调用时才确定，看的是「怎么调」而不是「在哪定义」**。四条绑定规则的优先级：`new` > `bind`/`call`/`apply` 显式绑定 > `obj.fn()` 隐式绑定 > 默认绑定（全局对象，严格模式 undefined）。唯一例外是箭头函数——它没有自己的 this，用的是定义处外层的 this。

---

## 1. 四条绑定规则

```js
function show() { console.log(this); }
const obj = { name: 'obj', show };

show();            // ① 默认绑定：全局对象；严格模式下 undefined
obj.show();        // ② 隐式绑定：谁调用指向谁 → obj
show.call(obj);    // ③ 显式绑定：指定谁就是谁 → obj
new obj.show();    // ④ new 绑定：指向新创建的实例
```

优先级从高到低：**new > 显式绑定 > 隐式绑定 > 默认绑定**。

隐式绑定最常见的坑是**丢失**：方法一旦被单独取出来，就退化成默认绑定。

```js
const fn = obj.show;
fn();              // 全局对象，不是 obj —— 引用断了
setTimeout(obj.show, 0);  // 同理丢失
```

---

## 2. 容易被问的特殊场景

- **回调函数**：this 取决于调用方怎么调它。`[1,2,3].forEach(fn)` 里 fn 的 this 是全局对象（严格模式 undefined）；forEach 等方法支持第二个参数指定 thisArg：`arr.forEach(fn, obj)`。
- **DOM 事件处理器**：`el.addEventListener('click', handler)` 中 handler 的 this 是 `el`（箭头函数除外）。
- **class 中**：实例方法的 this 指向实例，静态方法的 this 指向类本身；**class 体内默认就是严格模式**，方法单独取出后调用 this 是 undefined 而非全局对象——这是 React 类组件时代要 bind(this) 的原因。

---

## 3. 箭头函数：没有自己的 this

箭头函数不创建 this 绑定，**像普通变量一样沿词法作用域向外找 this**，定义时就锁定了：

```js
const timer = {
  count: 0,
  start() {
    setInterval(() => {
      this.count++;        // this 是 start 调用时的 this → timer
    }, 1000);
  },
};
```

三个推论：

1. `call`/`apply`/`bind` 改不动箭头函数的 this（参数照传，this 忽略）；
2. 箭头函数**不能被 new**（没有 [[Construct]] 内部方法），`new (() => {})` 抛 TypeError；
3. 也没有 `arguments`、`prototype`。

---

## 4. call、apply、bind 的区别

| | 执行时机 | 传参方式 | 返回 |
|---|---|---|---|
| `fn.call(ctx, a, b)` | 立即执行 | 逐个传 | 函数返回值 |
| `fn.apply(ctx, [a, b])` | 立即执行 | 数组 | 函数返回值 |
| `fn.bind(ctx, a)` | 不执行 | 逐个传（支持分批预置） | 绑定后的新函数 |

细节：非严格模式下传原始值会被包装成对象（`call(1)` → Number 实例），传 null/undefined 会落到全局对象；严格模式则原样使用。

---

## 5. 手写实现（面试高频）

核心思路：**把函数临时挂到目标对象上，用隐式绑定完成 this 指向**。用 Symbol 做属性名避免覆盖已有属性：

```js
Function.prototype.myCall = function (context, ...args) {
  context = context == null ? globalThis : Object(context);
  const key = Symbol('fn');
  context[key] = this;             // this 就是被调用的那个函数
  const result = context[key](...args);
  delete context[key];
  return result;
};

// apply 只差在参数形态
Function.prototype.myApply = function (context, args = []) {
  return this.myCall(context, ...args);
};

Function.prototype.myBind = function (context, ...preset) {
  const self = this;
  function Bound(...args) {
    // 关键：bind 返回的函数被 new 时，绑定的 this 被忽略，指向新实例
    return self.apply(
      this instanceof Bound ? this : context,
      [...preset, ...args],
    );
  }
  // 维持原型链，让 new Bound() 的实例能访问原函数原型上的方法
  Bound.prototype = Object.create(self.prototype ?? null);
  return Bound;
};
```

手写 bind 的两个判分点：

1. **支持 new**：用 `this instanceof Bound` 判断是否 new 调用（常见错误是写成 `self instanceof Bound`，永远为 false）；
2. **参数合并**：bind 时预置的参数与调用时的参数拼接（这也是偏函数的实现基础）。

## 面试问答

### Q: this 的指向规则是什么？

满分答案：this 在调用时确定，按优先级四条规则——new 调用指向新实例；call/apply/bind 显式指定；obj.fn() 隐式指向调用者；直接调用走默认绑定，指向全局对象、严格模式下是 undefined。箭头函数例外：没有自己的 this，取定义处外层作用域的 this，且无法被 call/bind 修改。加分点：隐式绑定容易丢失——方法赋值给变量或作为回调传递后就退化为默认绑定，class 体内是严格模式所以丢失后是 undefined。

### Q: call、apply、bind 的区别？

满分答案：call 和 apply 都立即执行，区别只在传参——call 逐个传、apply 传数组；bind 不执行，返回永久绑定 this 的新函数，还能预置参数实现偏函数。补充：bind 返回的函数若被 new，绑定的 this 会被忽略，this 指向新实例。

### Q: 手写 bind 要注意什么？

满分答案：三点——返回的新函数要合并预置参数和调用参数；要支持 new：内部用 this instanceof 判断是否构造调用，是则把 this 交给新实例；要接好原型链，用 Object.create(原函数.prototype) 作为返回函数的 prototype，保证 new 出的实例能访问原型方法。

### Q: 箭头函数和普通函数的区别？

满分答案：箭头函数没有自己的 this、arguments、prototype；this 沿词法作用域取外层，定义时锁定，call/apply/bind 无法修改；不能作构造函数被 new（没有 [[Construct]]），也不能用作 generator。适合回调和需要保留外层 this 的场景，不适合做对象方法（this 不会指向对象）和需要动态 this 的 DOM 事件处理器。

### Q: 输出题——对象方法里的定时器

```js
var name = 'global';
const obj = {
  name: 'obj',
  a() { setTimeout(function () { console.log(this.name); }, 0); },
  b() { setTimeout(() => console.log(this.name), 0); },
};
obj.a();  // ?
obj.b();  // ?
```

满分答案：a 输出 'global'——普通函数回调由定时器直接调用，走默认绑定指向全局对象（var 声明的 name 挂在全局）；b 输出 'obj'——箭头函数取定义处外层 b 的 this，b 是 obj 调用的。
