# Loader 与 Plugin 开发

## TL;DR

**Loader 是「翻译器」：把某类文件转成 webpack 认识的模块，本质是接收源码字符串返回新字符串的函数，链式从右到左执行**。**Plugin 是「监听者」：在 Compiler/Compilation 的 Tapable 钩子上注册回调，能介入构建全流程做任何事**。一句话分界：Loader 管单文件转换，Plugin 管全局过程。

---

## 1. 手写一个 Loader

webpack 只认 JS/JSON，其他文件全靠 loader 转换：

```js
// simple-loader.js —— 本质：source in, source out
module.exports = function (source) {
  const options = this.getOptions();          // 取 rule 里的 options
  // this 是 loaderContext：resourcePath、emitFile、async 都在上面
  return source.replace(/__VERSION__/g, options.version);
};

// 异步 loader：调用 this.async() 拿回调
module.exports = function (source) {
  const callback = this.async();
  compileSomething(source).then(res => callback(null, res));
};
```

规则要点：

- **链式执行，从右到左（从下到上）**：`['style-loader', 'css-loader', 'less-loader']`——less 先编译成 css，css-loader 解析 @import/url 转成 JS 模块，style-loader 最后生成注入 style 标签的代码。记忆法：像函数组合 `style(css(less(source)))`（compose 的思想，见 [[3.03 柯里化、偏函数与 compose]]）；
- pitch 阶段从左到右先跑一遍，可短路后续（style-loader 就靠 pitch 实现）；
- 保持**单一职责 + 无状态**，组合而非全能；
- 产出应是 JS 模块代码（`export default …`）或交给下一个 loader 的中间格式。

常用 loader 心里要有账：babel-loader（JS 降级）、ts-loader、css/style/postcss-loader、vue-loader；webpack 5 的 **asset modules 已内置取代 file/url/raw-loader**（`type: 'asset'` 按大小自动选内联或落盘）——答出这条说明知识不停在 webpack 4。

## 2. 手写一个 Plugin

```js
class FileListPlugin {
  apply(compiler) {                    // webpack 启动时调用，注入 compiler
    compiler.hooks.thisCompilation.tap('FileListPlugin', (compilation) => {
      // 在 processAssets 阶段加工产物（webpack 5 推荐的产物操作点）
      compilation.hooks.processAssets.tap(
        { name: 'FileListPlugin', stage: compilation.constructor.PROCESS_ASSETS_STAGE_SUMMARIZE },
        (assets) => {
          const list = Object.keys(assets).map(n => `- ${n}`).join('\n');
          const { RawSource } = compiler.webpack.sources;
          compilation.emitAsset('filelist.md', new RawSource(list));  // 新增一个产物
        },
      );
    });
  }
}
```

结构三件套：**有 apply(compiler) 方法的类** → 在钩子上 `tap/tapAsync/tapPromise` 注册 → 通过 compilation 读写模块与 assets。钩子体系与 Compiler/Compilation 的分工见 [[2.01 Webpack 核心流程]]。

常用 plugin 清单（配一句用途）：HtmlWebpackPlugin（生成注入产物的 HTML）、MiniCssExtractPlugin（css 抽独立文件配合缓存）、TerserPlugin（JS 压缩，production 内置）、DefinePlugin（编译期常量替换）、CopyWebpackPlugin、BundleAnalyzerPlugin（体积分析，优化第一步）。splitChunks 是 optimization 配置而非独立插件（详见 [[2.04 代码分割与构建优化实战]]）。

## 3. Loader vs Plugin 总结表

| | Loader | Plugin |
|---|---|---|
| 定位 | 单文件的内容转换 | 构建全流程的事件介入 |
| 形态 | 函数（source → source） | 带 apply 方法的类 |
| 执行 | 模块解析时按 rule 匹配、链式右到左 | 各阶段钩子触发 |
| 能力边界 | 只见当前文件 | 能见 compilation 全局（模块图、chunk、assets） |
| 例子 | babel-loader、css-loader | HtmlWebpackPlugin、MiniCssExtract |

## 面试问答

### Q: Loader 和 Plugin 的区别？

满分答案：Loader 是文件级翻译器——webpack 只认 JS/JSON，其他类型经 loader 链转成模块，本质是 source 进 source 出的函数，按 rule 匹配、从右到左执行，只关心当前文件；Plugin 是流程级监听者——基于 Tapable 在 Compiler/Compilation 的钩子上注册回调，能访问整个编译上下文（模块图、chunk、assets），做生成 HTML、抽 CSS、产物分析这类全局工作。转换用 Loader，干预流程用 Plugin。

### Q: 手写过 Loader 吗？要注意什么？

满分答案：核心是导出一个接收 source 返回处理结果的函数——this 上是 loaderContext（getOptions 取参、async() 支持异步、resourcePath、emitFile）。注意点：链式从右到左所以要明确自己在链中的位置和输入格式；保持单一职责无状态；异步务必用 this.async 而不是直接返回 Promise 之外的东西；可提 pitch 阶段（左到右预跑、可短路，style-loader 的实现基础）。举例说明 less→css→js 的链最有说服力。

### Q: 手写过 Plugin 吗？流程是什么？

满分答案：写一个带 apply(compiler) 的类，webpack 初始化时调用 apply；在 compiler.hooks（如 thisCompilation、emit、done）上 tap 注册，需要操作产物时进入 compilation 的 processAssets 阶段（webpack 5 的推荐位），通过 compilation.assets / emitAsset 读写产物，异步逻辑用 tapAsync/tapPromise。举例：输出产物清单、注入版本信息、上传 sourcemap 到监控平台。原理支点是 Tapable 事件系统贯穿 Compiler 与 Compilation。

### Q: css 相关的 loader 各自干什么？顺序为什么是那样？

满分答案：less/sass-loader 把预处理语言编译成 CSS；css-loader 解析 CSS 里的 @import 和 url()，把 CSS 变成 JS 模块（可选 CSS Modules）；style-loader 生成运行时代码把 CSS 注入 style 标签——生产环境换 MiniCssExtractPlugin.loader 抽成独立文件利于缓存与并行加载。顺序从右到左执行，配置里写 [style, css, less] 正是执行的逆序，本质是函数组合的嵌套关系。
