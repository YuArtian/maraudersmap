# JS 模块化演进：CommonJS 与 ESM

## TL;DR

**模块化演进主线：IIFE 手工隔离 → AMD/CMD 浏览器异步加载 → CommonJS 统治 Node → ESM 语言标准一统天下**。CJS 与 ESM 的三大本质区别：**运行时加载 vs 编译期静态分析、导出值拷贝 vs 只读实时绑定、同步 vs 异步**——静态结构正是 Tree Shaking 可行的前提。

---

## 1. 演进脉络（一分钟讲完历史）

| 阶段 | 方案 | 一句话 |
|---|---|---|
| 无模块 | 全局函数 / 命名空间对象 | 变量冲突、依赖靠注释 |
| 手工隔离 | IIFE + 闭包（见 [[1.02 作用域、变量提升与 var-let-const]]） | jQuery 时代的模块模式 |
| 浏览器异步 | **AMD**（RequireJS）：`define(deps, cb)` 依赖前置、提前执行 | 动态建 script 标签 + onload 收集依赖 |
| | CMD（SeaJS）：依赖就近、延迟执行 | 国产方案，已淡出 |
| 兼容包装 | **UMD** | 一段判断代码：有 define 走 AMD、有 module 走 CJS、否则挂全局——老库发布格式 |
| 服务端 | **CommonJS**：require / module.exports | Node 默认（至今） |
| 语言标准 | **ESM**：import / export | 浏览器原生 `<script type="module">`、Node 12+ 支持，唯一有官方标准的方案 |

SystemJS 一句话：能在旧浏览器里加载 ESM 语义模块的运行时 loader，如今主要活在微前端（qiankun 的 JS 沙箱配套）里。

## 2. CommonJS 要点

```js
// 导出：module.exports 才是真正的出口，exports 只是它的引用
module.exports = { add };
exports.sub = sub;        // ✔ 等价于 module.exports.sub
exports = { mul };        // ✘ 断开引用，导出无效——经典陷阱

// 导入：运行时执行，路径可以动态拼
const utils = require(flag ? './a' : './b');
```

三个特性：**运行时加载**（require 就是函数调用，执行到才加载）；**首次加载后缓存**（多次 require 返回同一结果，模块代码只跑一次）；**导出的是值的浅拷贝**——模块内后续修改原始值导出方感知不到（对象属性除外，因为拷的是引用）。

循环依赖的行为：返回「**已执行部分**的导出」——A require B、B 又 require A 时，B 拿到的是 A 当时已导出的半成品，不报错但容易踩 undefined。

## 3. ESM 要点

```js
export const a = 1;            // 命名导出
export default fn;             // 默认导出
import { a } from './m.js';    // 静态：必须在顶层、路径必须是字符串字面量
import('./m.js').then(...)     // 动态 import()：返回 Promise，代码分割的基础
```

三个特性：**编译期静态结构**——import/export 在解析阶段确定依赖图，未执行就知道谁用了谁（Tree Shaking 的前提，见 [[2.03 Tree Shaking 与按需引入]]）；**导出是只读的实时绑定（live binding）**——模块内变量变化，导入方看到最新值，但导入方不能改写；**天生异步 + 严格模式**，顶层还支持 top-level await。

循环依赖的行为：靠实时绑定 + 变量提升，函数声明类的循环引用大多能工作；访问未初始化的 let/const 绑定则抛 TDZ 错误。

## 4. CJS vs ESM 对比总表（背这张）

| 维度 | CommonJS | ESM |
|---|---|---|
| 加载时机 | 运行时，同步 | 编译期建图，异步加载 |
| 路径 | 可动态计算 | 静态字符串（动态用 import()） |
| 导出语义 | 值拷贝（对象拷引用） | **只读实时绑定** |
| this（模块顶层） | 指向 module.exports | undefined |
| Tree Shaking | 不可靠 | 天然支持 |
| Node 识别 | `.cjs` / 默认 | `.mjs` 或 package.json `"type": "module"` |
| 互操作 | — | ESM 可 import CJS（默认导出整体）；CJS 里 require ESM 长期不行，**Node 22+ 起支持同步 require(ESM)**（无顶层 await 时） |

实时绑定的验证题：

```js
// counter.mjs
export let count = 0;
export const inc = () => count++;
// main.mjs
import { count, inc } from './counter.mjs';
inc();
console.log(count);   // 1 —— ESM 是绑定；CJS 同款代码输出 0（拷贝）
```

## 5. 工程语境补充

- package.json 的 `main` / `module` / `exports` 字段决定包以哪种格式被解析（详见 [[1.02 package.json 与依赖管理]]）；
- 双格式发包（dual package）是库作者的现实：构建产出 ESM + CJS 两份，exports 字段按条件分发；
- 浏览器里 `<script type="module">` 自带 defer 行为、同源策略约束（见 [[2.04 script 加载与资源提示]]）；
- Vite 的 dev 模式直接吃原生 ESM——按需编译的地基（见 [[2.05 Vite 原理]]）。

## 面试问答

### Q: CommonJS 和 ESM 的区别？

满分答案：三条主线——时机：CJS 运行时同步加载、路径可动态；ESM 编译期静态分析建依赖图、异步加载，动态场景用 import()。语义：CJS 导出值拷贝，模块内后续变化不反映；ESM 是只读实时绑定，导入方永远看到最新值。生态：ESM 的静态结构使 Tree Shaking 成为可能，是语言标准、浏览器原生支持。补充互操作：ESM 可导入 CJS，反向长期不行、Node 22 起有条件支持同步 require ESM。

### Q: exports 和 module.exports 的关系？

满分答案：Node 在每个模块开头注入 `var exports = module.exports`，两者指向同一对象——挂属性等价；但 require 返回的永远是 module.exports，所以 `exports = 新值` 只是让局部变量改指别处，导出的仍是原对象，静默失效。导出单一值必须写 module.exports = value。这题考引用赋值的理解。

### Q: AMD、CMD、UMD 是什么？现在还有用吗？

满分答案：浏览器无模块时代的社区方案——AMD（RequireJS）依赖前置、define 声明，用动态 script 标签加载；CMD（SeaJS）依赖就近、延迟执行；UMD 是兼容三种环境的包装样板（判断 define/module 逐级回退）。现状：新项目一律 ESM，AMD/CMD 已淘汰；UMD 还作为老库的发布格式存在（CDN 直接 script 引入的场景），了解其判断逻辑即可。

### Q: 两种模块的循环依赖各会发生什么？

满分答案：CJS——require 遇到正在加载中的模块直接返回其「当前已执行部分」的 exports，不报错但可能拿到不完整对象，问题延迟暴露；ESM——依赖图先建立、绑定提升，函数声明互引通常没事，但初始化前访问 let/const 绑定抛 ReferenceError（TDZ），错误更早更明确。工程上真正的解法是重构：抽公共依赖、依赖倒置或延迟到使用时再取。
