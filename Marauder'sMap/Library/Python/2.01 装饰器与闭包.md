# 装饰器与闭包

## TL;DR

**装饰器本质上是"返回函数的高阶函数"，靠闭包记住被包装的原函数。** 核心要点：

- 闭包 = 内层函数引用外层局部变量；外层返回后，这些变量依然存活
- 装饰器是两层嵌套（无参）或三层嵌套（带参）的高阶函数，`@deco` 等价于 `f = deco(f)`
- 装饰后 `__name__` 会变成 `wrapper`，用 `@functools.wraps(func)` 保留原函数元信息
- 闭包里**不要引用循环变量**，因为闭包记的是"变量本身"，不是当时的值
- `functools.partial` 把函数的部分参数固定，得到一个简化版的新函数

---

## 1. 闭包：内层函数记得外层变量

函数里再定义函数，并把内层函数**返回出去**，就形成闭包：

```python
def lazy_sum(*args):
    def sum():
        ax = 0
        for n in args:
            ax = ax + n
        return ax
    return sum    # 返回内层函数本身，没有调用

f = lazy_sum(1, 3, 5, 7, 9)   # f 是一个函数，求和并没有发生
f()                            # 25，调用时才真正求和
```

```text
lazy_sum(1,3,5,7,9)
        │
        ▼
   ┌─────────────┐
   │ args=(1,..) │  外层局部变量
   │             │
   │  def sum:   │  内层函数引用 args
   │    用 args  │
   │             │
   │  return sum │  返回内层函数
   └─────────────┘
        │
        ▼
        f  ─────► 即使 lazy_sum 已经返回，args 也活着，因为 f 还在引用它
```

每次调用 `lazy_sum()` 返回的都是**新的函数对象**，即使参数相同：

```python
f1 = lazy_sum(1, 3, 5)
f2 = lazy_sum(1, 3, 5)
f1 == f2                       # False
```

类比 JS：

| Python | JavaScript |
|---|---|
| `def outer(): def inner(): ... return inner` | `function outer() { return function inner() {...} }` |
| 内层函数自动捕获外层变量 | 同 |
| `nonlocal x` 显式声明要改外层变量 | 直接赋值即可（除非有同名变量遮蔽） |

## 2. 闭包陷阱：不要引用循环变量

经典坑：循环里返回闭包，看起来每个闭包记的是不同的 `i`，其实记的是**同一个变量**：

```python
def count():
    fs = []
    for i in range(1, 4):
        def f():
            return i * i
        fs.append(f)
    return fs

f1, f2, f3 = count()
f1(), f2(), f3()    # (9, 9, 9) — 不是预期的 (1, 4, 9)!
```

原因：3 个 `f` 都引用同一个 `i`。循环结束时 `i = 3`，所以三个调用都返回 9。

**修正方法**：用函数参数把当前值"绑定"住：

```python
def count():
    def f(j):
        def g():
            return j * j
        return g
    fs = []
    for i in range(1, 4):
        fs.append(f(i))   # f(i) 立刻执行，i 的当前值被绑定为 f 的参数 j
    return fs

f1, f2, f3 = count()
f1(), f2(), f3()    # (1, 4, 9) ✓
```

记住：**返回函数中不要引用任何会变化的变量。**

## 3. nonlocal：在闭包里修改外层变量

只**读**外层变量不需要任何声明：

```python
def inc():
    x = 0
    def fn():
        return x + 1    # 只读
    return fn
```

但是要**赋值**外层变量，Python 默认会把它当作内层函数的局部变量，导致报错：

```python
def inc():
    x = 0
    def fn():
        x = x + 1       # UnboundLocalError: 把 x 当成 fn 的局部变量了
        return x
    return fn
```

加 `nonlocal` 声明告诉解释器"这个变量是外层的"：

```python
def inc():
    x = 0
    def fn():
        nonlocal x      # 关键
        x = x + 1
        return x
    return fn

f = inc()
f(), f()                # 1, 2
```

| 关键字 | 作用 |
|---|---|
| `global x` | x 是模块级（最外层）变量 |
| `nonlocal x` | x 是外层函数的局部变量，不是当前函数的 |
| 都不加 | 赋值时新建局部变量，仅读取时按作用域链查找 |

## 4. 装饰器：动态给函数加功能

装饰器本质是**接收函数、返回函数的高阶函数**。`@deco` 是语法糖：

```python
@log
def now():
    print('2024-6-1')

# 完全等价于：
def now():
    print('2024-6-1')
now = log(now)
```

### 标准两层装饰器

```python
def log(func):
    def wrapper(*args, **kw):           # 接收任意参数
        print('call %s():' % func.__name__)
        return func(*args, **kw)        # 转发给原函数
    return wrapper

@log
def now():
    print('2024-6-1')

now()
# call now():
# 2024-6-1
```

```text
@log
def now():        ─► now = log(now)
    ...
                        │
                        ▼
                  wrapper 函数      ← 外面看到的 now 现在是这个
                  ┌────────────┐
                  │ 打印日志    │
                  │ 调用 func() │  ← func 通过闭包记住了原始的 now
                  └────────────┘
```

## 5. 带参数的装饰器：三层嵌套

如果装饰器本身要接受参数，再套一层：

```python
def log(text):                           # 最外层接收装饰器参数
    def decorator(func):                 # 中间层接收被装饰函数
        def wrapper(*args, **kw):        # 内层是实际包装
            print('%s %s():' % (text, func.__name__))
            return func(*args, **kw)
        return wrapper
    return decorator

@log('execute')
def now():
    print('2024-6-1')

now()
# execute now():
# 2024-6-1
```

执行顺序：

```text
@log('execute')   →   now = log('execute')(now)
                            └─────┬─────┘
                                  ▼
                              decorator    ← 第一层调用返回这个
                              └──(now)──► wrapper   ← 第二层调用返回这个
```

| 嵌套层 | 闭包记住的变量 |
|---|---|
| 外层 `log` | `text` |
| 中层 `decorator` | `func`、`text` |
| 内层 `wrapper` | `args`、`kw`、`func`、`text` |

## 6. `@functools.wraps`：保留原函数信息

装饰后函数的 `__name__` 会变成 `'wrapper'`，因为外面看到的就是 wrapper：

```python
@log
def now(): pass

now.__name__    # 'wrapper'  -- 原来叫 'now'，被改了
```

依赖 `__name__` 的代码（如某些日志库、ORM、序列化框架）会出错。用 `functools.wraps` 修复：

```python
import functools

def log(func):
    @functools.wraps(func)        # 把 func 的元信息复制到 wrapper 上
    def wrapper(*args, **kw):
        print('call %s():' % func.__name__)
        return func(*args, **kw)
    return wrapper
```

`functools.wraps` 本身就是个装饰器，写装饰器时基本是固定动作。带参装饰器同样要在最内层 wrapper 上加：

```python
def log(text):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kw):
            ...
        return wrapper
    return decorator
```

## 7. 偏函数 `functools.partial`

把函数的某些参数**固定下来**，得到一个新函数：

```python
import functools

int('1000000', base=2)               # 64 -- 但每次都要写 base=2 很烦

int2 = functools.partial(int, base=2)  # 固定 base=2
int2('1000000')                       # 64
int2('1010101')                       # 85
```

被固定的值仍然可以在调用时覆盖：

```python
int2('1000000', base=10)              # 1000000 -- 临时覆盖默认值
```

`partial` 既可以固定关键字参数，也可以追加位置参数：

```python
max2 = functools.partial(max, 10)
max2(5, 6, 7)
# 等价于 max(10, 5, 6, 7) -> 10
```

| 用法 | 效果 |
|---|---|
| `partial(f, x=1)` | 固定 `x` 为 1，调用时可覆盖 |
| `partial(f, 10)` | 把 10 加到位置参数最左边 |

`partial` 适合：参数多但每次只变其中几个的场景，比简单写默认值更灵活。
