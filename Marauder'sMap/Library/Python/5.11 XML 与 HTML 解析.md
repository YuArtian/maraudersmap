# XML 与 HTML 解析

## TL;DR

**Python stdlib 提供 `xml.parsers.expat`（SAX 流式）、`html.parser.HTMLParser`（HTML 事件回调）两套基础解析器。** 核心要点：

- **SAX**：边读边触发事件（`start_element` / `char_data` / `end_element`）；省内存
- **DOM**：整个文档读进内存变成树；省心但耗内存
- HTML 比 XML 宽松（语法不严格），用专门的 `html.parser`，不能用 XML 解析器
- **现代实战**：XML 用 `lxml`，HTML 用 `BeautifulSoup` + `lxml` 后端——stdlib 内置的版本能用，但生态更强的是第三方
- 生成 XML 简单时直接拼字符串；复杂时改用 JSON 比挣扎着用 XML 强

---

## 1. XML 与 HTML 的区别

```text
XML                           HTML
────────────────────────      ───────────────────────────
严格自闭合                       <br>, <img> 可以不闭合
区分大小写                       <P> 和 <p> 一样
未声明实体报错                    保留 &nbsp; 等命名实体
关注数据结构                     关注展示
```

**关键结论**：HTML 不是 XML 的子集——不要用 XML 解析器解析 HTML，会因为不规范报错。Python 给了**两套**工具：

| 输入 | stdlib 工具 | 推荐第三方 |
|---|---|---|
| 严格的 XML | `xml.parsers.expat`（SAX）, `xml.etree.ElementTree`（DOM）| `lxml` |
| HTML / "脏" XML | `html.parser.HTMLParser` | `beautifulsoup4` |

---

## 2. SAX vs DOM：两种解析模型

```text
SAX 流式：
   ┌── start <ol>  事件
   ├── start <li>  事件
   ├── chars 'Python'
   ├── end </li>
   └── ... 不断触发回调，处理完就丢

DOM 树式：
   <ol>
   ├─ <li>Python</li>      整棵树都在内存里
   └─ <li>Ruby</li>        随便遍历、修改
```

| 维度 | SAX | DOM |
|---|---|---|
| 内存占用 | 极小（O(深度)） | 大（O(整个文档)） |
| 速度 | 快 | 慢 |
| 编程复杂度 | 高（要自己维护状态） | 低（树随便遍）|
| 修改文档 | ✗ | ✓ |
| 多次访问 | ✗（流是一次性的）| ✓ |
| 大文件（几百 MB） | **必用** | 不行 |

## 3. SAX 解析 XML（stdlib）

`xml.parsers.expat` 是 stdlib 的 SAX 解析器。注册三个事件回调：

```python
from xml.parsers.expat import ParserCreate

class DefaultSaxHandler:
    def start_element(self, name, attrs):
        print(f'<{name}> attrs={attrs}')

    def end_element(self, name):
        print(f'</{name}>')

    def char_data(self, text):
        print(f'  text: {text!r}')

xml_str = r'''<?xml version="1.0"?>
<ol>
    <li><a href="/python">Python</a></li>
    <li><a href="/ruby">Ruby</a></li>
</ol>
'''

handler = DefaultSaxHandler()
parser = ParserCreate()
parser.StartElementHandler = handler.start_element
parser.EndElementHandler = handler.end_element
parser.CharacterDataHandler = handler.char_data
parser.Parse(xml_str)
```

事件顺序：

```text
<ol>          → start_element('ol', {})
              → char_data('\n    ')
<li>          → start_element('li', {})
<a href=...>  → start_element('a', {'href': '/python'})
'Python'      → char_data('Python')
</a>          → end_element('a')
...
```

**注意**：`char_data` 可能被多次调用——读大段文本时 expat 会分块给你，要自己拼接：

```python
class Handler:
    def __init__(self):
        self.buf = []
    def char_data(self, text):
        self.buf.append(text)
    def end_element(self, name):
        text = ''.join(self.buf)
        self.buf = []
        # 处理 text
```

## 4. DOM 风格：`ElementTree`

stdlib 推荐用 `xml.etree.ElementTree`（DOM 风格但比 SAX 简单）：

```python
import xml.etree.ElementTree as ET

xml_str = '''<root>
    <user id="1"><name>Alice</name></user>
    <user id="2"><name>Bob</name></user>
</root>'''

root = ET.fromstring(xml_str)

for user in root.findall('user'):
    uid = user.get('id')
    name = user.find('name').text
    print(uid, name)
# 1 Alice
# 2 Bob
```

| 方法 | 作用 |
|---|---|
| `ET.fromstring(s)` | 字符串解析 |
| `ET.parse(file)` | 文件解析 |
| `root.find(tag)` | 找第一个匹配的子元素 |
| `root.findall(tag)` | 找所有匹配的子元素 |
| `el.text` | 元素内的文本 |
| `el.get(attr)` | 属性 |
| `el.attrib` | 所有属性 dict |
| `ET.tostring(el)` | 序列化回字符串 |

支持 XPath 子集：

```python
root.findall('.//user[@id="1"]/name')   # 任意深度找 id=1 的 user 下的 name
```

ElementTree 是**最实用的 stdlib XML 工具**——比 expat 高层，但不像 `xml.dom.minidom` 那么啰嗦。

## 5. HTMLParser：解析 HTML

HTML 不规范——空标签 `<br>` 不闭合、属性可以不带引号、大小写混用。**不能**用 XML 解析器。stdlib 给了 `HTMLParser`：

```python
from html.parser import HTMLParser

class MyHTMLParser(HTMLParser):
    def handle_starttag(self, tag, attrs):
        print(f'<{tag}>')

    def handle_endtag(self, tag):
        print(f'</{tag}>')

    def handle_startendtag(self, tag, attrs):
        print(f'<{tag}/>')        # 自闭合，如 <br/>

    def handle_data(self, data):
        print(f'  data: {data!r}')

    def handle_comment(self, data):
        print(f'<!--{data}-->')

    def handle_entityref(self, name):
        print(f'&{name};')         # &nbsp;

    def handle_charref(self, name):
        print(f'&#{name};')        # &#1234;

parser = MyHTMLParser()
parser.feed('''<html>
<head></head>
<body>
<!-- test -->
<p>Some <a href="#">html</a> tutorial...<br>END</p>
</body>
</html>''')
```

`feed()` 可以**多次调用**——支持流式喂数据，不必一次性加载：

```python
parser = MyHTMLParser()
for chunk in stream_html():
    parser.feed(chunk)
parser.close()
```

## 6. 生成 XML：拼字符串就够

99% 的场景 XML 生成结构简单，**直接拼字符串**最快最易读：

```python
parts = [r'<?xml version="1.0"?>', '<root>']
for item in items:
    parts.append(f'<item id="{item.id}">{escape(item.name)}</item>')
parts.append('</root>')
xml = '\n'.join(parts)
```

**重要**：要 `xml.sax.saxutils.escape` 转义 `<` `>` `&` `'` `"`，否则用户数据可能破坏 XML 结构。

复杂的就用 `ElementTree.tostring`：

```python
import xml.etree.ElementTree as ET

root = ET.Element('root')
for item in items:
    el = ET.SubElement(root, 'item', id=str(item.id))
    el.text = item.name

xml_bytes = ET.tostring(root, encoding='utf-8', xml_declaration=True)
```

> 廖雪峰原话："如果要生成复杂的 XML 呢？建议你不要用 XML，改成 JSON。"——现代项目几乎都是这个共识。

## 7. 现代实战：lxml + BeautifulSoup

```python
# pip install lxml beautifulsoup4

# 解析 HTML（容错强、API 友好）
from bs4 import BeautifulSoup
soup = BeautifulSoup(html, 'lxml')

soup.title.text                    # '页面标题'
soup.find_all('a', class_='link')  # 所有 <a class="link">
soup.select('div.main > p')         # CSS 选择器
for a in soup.select('a[href]'):
    print(a['href'], a.text)

# 解析 XML（比 stdlib 快很多）
from lxml import etree
root = etree.fromstring(xml_bytes)
root.xpath('//user[@id="1"]/name/text()')   # 完整 XPath 支持
```

| 库 | 何时用 |
|---|---|
| `xml.etree.ElementTree` | 小到中型 XML，不想加依赖 |
| `lxml` | 任何严肃 XML 处理，速度快、XPath 全 |
| `html.parser.HTMLParser` | 仅在不能装包时 |
| `BeautifulSoup` | **任何 HTML 解析**——容错好、API 直观 |
| `selectolax` | 性能敏感 HTML，比 BS4 快 10 倍 |

**经验**：

- 内部小工具，怕加依赖 → stdlib
- 任何对外项目 / 爬虫 / 数据抓取 → BeautifulSoup + lxml

## 8. 安全警告：XML 攻击

XML 解析有几个**安全坑**：

| 攻击 | 后果 |
|---|---|
| Billion Laughs | 嵌套实体引用让解析器内存爆炸 |
| XXE (XML External Entity) | 引用外部文件 → 读敏感数据 |
| Decompression bomb | 压缩比极高的 XML → DoS |

stdlib 的 `xml` 模块**默认不安全**——处理不可信 XML 必须用 [`defusedxml`](https://pypi.org/project/defusedxml/)：

```python
# pip install defusedxml
import defusedxml.ElementTree as ET
root = ET.fromstring(untrusted_xml)
```

接口和 stdlib 一致，但拦截了所有已知 XML 攻击。**用户上传 / 外部 API 来的 XML 都要走 defusedxml。**

## 9. 速查表

| 任务 | stdlib | 推荐 |
|---|---|---|
| 解析小 XML | `xml.etree.ElementTree` | 同 |
| 解析大 XML（流式）| `xml.parsers.expat` 或 `ET.iterparse` | `lxml.etree.iterparse` |
| 解析 HTML | `html.parser.HTMLParser` | **`BeautifulSoup`** |
| XPath 查询 | `ET` 支持子集 | **`lxml`**（完整支持） |
| CSS 选择器 | ✗ | `BeautifulSoup.select` |
| 生成 XML | `ET.tostring` | 同 |
| 不可信 XML | ⚠️ 不安全 | **`defusedxml`** |
| HTML 容错 | `HTMLParser` 一般 | `BeautifulSoup` 极强 |

## 10. 何时该用 XML（与不该用）

| 该用 | 不该用 |
|---|---|
| 必须兼容旧系统（SOAP / RSS / OPDS）| 全新设计的 API |
| 配置文件需要注释 + 严格 schema | 简单配置（用 TOML / YAML）|
| 文档型数据（DocBook, OOXML）| 一般数据传输（用 JSON）|
| 跨语言的复杂数据，且生态成熟 | 移动端 / Web 前端通信 |

**默认选择是 JSON**——更短、可读、所有语言原生支持。XML 几乎只剩"遗留系统兼容"这一个用例。
