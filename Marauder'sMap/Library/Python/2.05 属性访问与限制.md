# 属性访问与限制

## TL;DR

**Python 没有真正的 private，但用下划线约定和 `@property` 装饰器实现"看起来像属性、实际有逻辑"的封装。** 核心要点：

- `_name` 是约定的私有变量，外部可访问但不应访问
- `__name` 会被 Python 自动改名为 `_ClassName__name`（name mangling）
- `@property` 把 getter 方法变成属性访问，配合 `@xxx.setter` 实现校验
- 只定义 getter 不定义 setter，就得到**只读属性**
- 属性方法名不能和实例变量同名，否则会无限递归

---

## 1. 访问限制：靠下划线命名约定

Python 没有 `private` 关键字。三种命名习惯表达不同访问级别：

| 命名 | 含义 | 示例 |
|---|---|---|
| `name` | 公开 (public) | `self.name`，谁都能用 |
| `_name` | 约定的私有 (protected) | `self._score`，能访问但请别访问 |
| `__name` | 强私有，会被改名 | `self.__name`，外部很难直接拿到 |
| `__name__` | Python 特殊变量，**不要**这样命名自己的属性 | `__init__`、`__name__` |

```python
class Student:
    def __init__(self, name, score):
        self.__name = name      # 强私有
        self._score = score     # 约定私有
        self.year = 2024        # 公开

    def get_name(self):
        return self.__name      # 内部访问没问题
```

```python
s = Student('Bob', 90)
s.year                # 2024 ✓
s._score              # 90 ✓ 但应该当作私有，不要直接读
s.__name              # AttributeError! 找不到这个属性
```

## 2. Name mangling：`__name` 到底去哪了

`__name` 不是被"隐藏"了，而是 Python 把名字**改写**了：

```python
class Student:
    def __init__(self, name):
        self.__name = name

s = Student('Bart')
s.__name                # AttributeError
s._Student__name        # 'Bart' ✓ -- Python 自动改成了这个名字
```

```text
class 内部写:    self.__name
                     │
                     ▼ Python 解释器自动改写
实际存储为:      self._ClassName__name
```

**为什么这样设计？** 防止子类不小心覆盖父类的私有属性。`A.__x` 和 `B.__x` 改写后分别是 `_A__x` 和 `_B__x`，不冲突。

**强烈建议不要**通过 `_Student__name` 去访问私有属性，因为不同 Python 版本的改名规则可能变。

### 一个常见的坑

```python
class Student:
    def __init__(self, name):
        self.__name = name
    def get_name(self):
        return self.__name

bart = Student('Bart')
bart.__name = 'NEW'      # 看起来"设置了" __name
bart.__name              # 'NEW'  -- 表面成功
bart.get_name()          # 'Bart' -- 但内部的 self.__name 没变!
```

外面的 `bart.__name` 和类内的 `self.__name` 根本是两个不同的变量（一个叫 `__name`，一个被改成了 `_Student__name`）。

## 3. 朴素的 getter/setter

要在赋值时做校验，传统写法是定义 `get_xxx` / `set_xxx` 方法：

```python
class Student:
    def get_score(self):
        return self._score

    def set_score(self, value):
        if not isinstance(value, int):
            raise ValueError('score must be an integer!')
        if value < 0 or value > 100:
            raise ValueError('score must between 0 ~ 100!')
        self._score = value
```

```python
s = Student()
s.set_score(60)         # OK
s.set_score(9999)       # ValueError
```

问题：调用方要写 `s.set_score(60)` 而不是更直观的 `s.score = 60`。

---

## 4. `@property`：让方法变成属性

`@property` 装饰器把一个方法变成属性访问，配套的 `@xxx.setter` 把另一个方法变成属性赋值：

```python
class Student:
    @property
    def score(self):                   # getter，方法名就是属性名
        return self._score

    @score.setter
    def score(self, value):            # setter，自动校验
        if not isinstance(value, int):
            raise ValueError('score must be an integer!')
        if value < 0 or value > 100:
            raise ValueError('score must between 0 ~ 100!')
        self._score = value
```

调用方现在可以像访问普通属性一样使用，但实际走的是方法：

```python
s = Student()
s.score = 60         # 实际调用 s.score(60) → setter
s.score              # 60  实际调用 s.score() → getter
s.score = 9999       # ValueError -- setter 拦截
```

| 写法 | 实际发生什么 |
|---|---|
| `s.score` | 调用 `@property` 装饰的 getter |
| `s.score = 60` | 调用 `@score.setter` 装饰的 setter |
| 只定义 getter | 只读属性，赋值会报错 |

## 5. 只读属性：只定义 getter

不写 `@xxx.setter`，属性就是**只读**的——只能读，不能写：

```python
class Student:
    @property
    def birth(self):           # 可读写：定义了 setter
        return self._birth

    @birth.setter
    def birth(self, value):
        self._birth = value

    @property
    def age(self):             # 只读：没定义 setter
        return 2024 - self._birth
```

```python
s = Student()
s.birth = 2000      # OK
s.age               # 24 -- 由 birth 算出来
s.age = 30          # AttributeError: can't set attribute
```

**只读属性的典型用途**：派生属性（由其他字段计算出来），不应该被直接设置。

## 6. 致命陷阱：方法名不能和实例变量同名

下面这段代码看起来没问题，运行会**栈溢出**：

```python
class Student:
    @property
    def birth(self):
        return self.birth      # 不是 self._birth!

s = Student()
s.birth                        # RecursionError: maximum recursion depth
```

```text
访问 s.birth
  → 调用 @property 的 birth() 方法
    → 方法里 return self.birth
      → 又是 @property，再次调用 birth() 方法
        → ... 无限递归
```

**规则**：

| ✓ 正确 | ✗ 错误 |
|---|---|
| `@property def birth: return self._birth` | `@property def birth: return self.birth` |
| 属性方法叫 `birth`，背后存储用 `_birth` | 属性方法和存储变量同名 |

## 7. 完整示例

```python
class Screen:
    @property
    def width(self):
        return self._width

    @width.setter
    def width(self, value):
        if not isinstance(value, int) or value <= 0:
            raise ValueError('width must be a positive int')
        self._width = value

    @property
    def height(self):
        return self._height

    @height.setter
    def height(self, value):
        if not isinstance(value, int) or value <= 0:
            raise ValueError('height must be a positive int')
        self._height = value

    @property
    def resolution(self):              # 只读，自动算
        return self._width * self._height

s = Screen()
s.width = 1024
s.height = 768
s.resolution         # 786432
s.resolution = 0     # AttributeError
```

## 8. 和 JavaScript 对比

| 功能 | Python | JavaScript |
|---|---|---|
| getter | `@property def x(self): ...` | `get x() { ... }` |
| setter | `@x.setter def x(self, v): ...` | `set x(v) { ... }` |
| 私有 | `_x` 约定 / `__x` 改名 | `#x` 真私有（ES2022+）|
| 只读 | 不定义 setter | 只定义 `get x()`，不定义 `set x()` |

Python 的 `__name` 不是真私有（只是改名），JS 的 `#name` 是真的访问不到。但 Python 的 `@property` 写法比 JS 的 `get/set` 灵活——可以后期"升级"普通属性为 property，调用方代码不用改。
