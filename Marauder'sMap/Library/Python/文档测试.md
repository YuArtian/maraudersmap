# 文档测试

## TL;DR

**doctest 让你"在 docstring 里写例子"，然后这些例子既是用法说明，又是可执行的测试。** 核心要点：

- 在函数/类的 docstring 里写 `>>> 表达式` 和**期望输出**，doctest 会跑
- 文档示例不再"过时"——一旦改动让示例失效，跑测试立刻报错
- 测异常用 `Traceback (most recent call last):` 加 `...` 省略中间，最后写异常类型和消息
- 触发方式：`python -m doctest mymod.py` 或在文件末尾 `doctest.testmod()`
- 适合**简单函数**的"自带示例"；复杂业务逻辑还是用 `unittest` / `pytest`

---

## 1. 核心想法：把 REPL 演示放进文档

Python 官方文档里很多函数的 docstring 都长这样：

```python
def search(pattern, string):
    """
    Search for pattern in string.

    Example:
        >>> import re
        >>> m = re.search('(?<=abc)def', 'abcdef')
        >>> m.group(0)
        'def'
    """
```

读文档的人能直接复制到 REPL 跑——**示例和实现绝不会脱节**，因为 doctest 会执行这些 `>>>` 行并对照预期输出。

## 2. 第一个 doctest

```python
def abs(n):
    '''
    Function to get absolute value of number.

    Example:

    >>> abs(1)
    1
    >>> abs(-1)
    1
    >>> abs(0)
    0
    '''
    return n if n >= 0 else (-n)

if __name__ == '__main__':
    import doctest
    doctest.testmod()
```

跑：

```bash
python my_module.py
# 什么输出都没有 = 全部通过
```

如果改坏代码（比如让 `abs(-1)` 返回 `-1`），再跑会报错：

```text
**********************************************************************
File "my_module.py", line 5, in __main__.abs
Failed example:
    abs(-1)
Expected:
    1
Got:
    -1
**********************************************************************
```

## 3. doctest 的语法规则

### 基本格式

```text
>>> 表达式
期望的输出
```

- `>>>` 前面**必须**有一个空格（如果在 docstring 缩进里）
- 期望输出和实际输出**逐字符比对**（包括引号风格、空格）

### 多行表达式用 `...`

```python
def add(a, b):
    """
    >>> add(
    ...     1,
    ...     2,
    ... )
    3
    """
    return a + b
```

### 测异常输出

异常的格式比较特殊：

```python
def divide(a, b):
    """
    >>> divide(10, 0)
    Traceback (most recent call last):
        ...
    ZeroDivisionError: division by zero
    """
    return a / b
```

- 必须以 `Traceback (most recent call last):` 开头
- 中间用 `...` 省略文件路径、行号等无关信息
- 最后一行写**异常类名 + 冒号 + 消息**，doctest 只比对这一行的开头

### 输出里有不稳定的内容

像内存地址 `<__main__.Student object at 0x10abc>` 这种每次运行都变——用 `# doctest: +ELLIPSIS` 启用省略：

```python
def make_student():
    """
    >>> s = make_student()
    >>> repr(s)            # doctest: +ELLIPSIS
    '<Student object at 0x...>'
    """
```

| 指令 | 作用 |
|---|---|
| `+ELLIPSIS` | 允许用 `...` 匹配任意内容 |
| `+NORMALIZE_WHITESPACE` | 忽略空格数量差异 |
| `+SKIP` | 跳过这行（不执行也不比对）|
| `+IGNORE_EXCEPTION_DETAIL` | 异常消息不严格匹配 |

## 4. 完整示例

```python
# mydict2.py
class Dict(dict):
    '''
    Simple dict but also support access as x.y style.

    >>> d1 = Dict()
    >>> d1['x'] = 100
    >>> d1.x
    100
    >>> d1.y = 200
    >>> d1['y']
    200
    >>> d2 = Dict(a=1, b=2, c='3')
    >>> d2.c
    '3'
    >>> d2['empty']
    Traceback (most recent call last):
        ...
    KeyError: 'empty'
    >>> d2.empty
    Traceback (most recent call last):
        ...
    AttributeError: 'Dict' object has no attribute 'empty'
    '''
    def __init__(self, **kw):
        super().__init__(**kw)

    def __getattr__(self, key):
        try:
            return self[key]
        except KeyError:
            raise AttributeError(f"'Dict' object has no attribute '{key}'")

    def __setattr__(self, key, value):
        self[key] = value

if __name__ == '__main__':
    import doctest
    doctest.testmod()
```

跑 `python mydict2.py` 没输出 = 全部通过；某个示例失败会打出**具体哪一行的期望和实际**。

## 5. 触发 doctest 的几种方式

### 方式一：在文件里加触发块

```python
if __name__ == '__main__':
    import doctest
    doctest.testmod()
```

- `import mydict2` 时**不会**跑 doctest（`__main__` 不成立）
- 直接 `python mydict2.py` 才跑

### 方式二：命令行

```bash
python -m doctest mymod.py             # 跑所有 doctest
python -m doctest -v mymod.py          # verbose，输出每个测试
```

### 方式三：用 pytest 自动跑

```bash
pytest --doctest-modules               # 自动收集所有 doctest
```

实际项目通常用这种——一条命令把 unittest、pytest 风格测试、doctest 全跑了。

## 6. doctest vs unittest 怎么选

| 维度 | doctest | unittest |
|---|---|---|
| 编写位置 | docstring 里 | 单独的 test 文件 |
| 主要目的 | 文档（"看怎么用"）+ 顺便测 | 完整测试套件 |
| 适合的代码 | 简单函数、API 示例 | 复杂业务、状态机 |
| 测试复杂场景 | 难（不能 mock，没 setUp）| 容易 |
| 阅读体验 | 用户和测试者看的是同一份 | 测试代码用户看不到 |
| 维护成本 | 低 | 较高 |

**实战策略**：

- **公共 API、简单工具函数** → doctest，让用户看文档直接懂用法
- **业务逻辑、需要 mock、需要 setUp** → unittest / pytest
- **同一个项目可以两者并用**——doctest 当快速示例，unittest 做严格测试

## 7. 易踩的坑

### 坑 1：输出格式必须一字不差

```python
def f():
    """
    >>> f()
    'hello'
    """
    return "hello"      # 不行!
```

`"hello"`（双引号）和 `'hello'`（单引号）虽然是同一个字符串，但 doctest 比的是 `repr()`——Python 的 repr 默认用单引号，期望写单引号才对。

### 坑 2：字典顺序问题

Python 3.7+ dict 保持插入顺序，但 doctest 比对字符串，**顺序变化导致测试失败**：

```python
def stats(words):
    """
    >>> stats(['a', 'b'])
    {'a': 1, 'b': 1}      # 但 Counter 内部顺序可能不一样
    """
```

解决：用 `sorted(d.items())` 这种确定性输出，或者用 `+NORMALIZE_WHITESPACE` / `+ELLIPSIS`。

### 坑 3：浮点数

```python
def f():
    """
    >>> f()
    0.30000000000000004    # 1/10 + 2/10 实际是这个
    """
    return 1/10 + 2/10
```

要么写出确切的浮点表示，要么用 `round()`：

```python
"""
>>> round(f(), 6)
0.3
"""
```

## 8. 速查表

| 想做 | 写法 |
|---|---|
| 普通断言 | `>>> expr` 下一行写期望输出 |
| 多行表达式 | 续行用 `...` |
| 测异常 | `Traceback ...` + `...` + `ExcType: msg` |
| 省略不稳定输出 | 在末尾加 `# doctest: +ELLIPSIS`，输出用 `...` |
| 触发执行 | `python -m doctest mod.py` 或 `doctest.testmod()` |
| pytest 集成 | `pytest --doctest-modules` |
