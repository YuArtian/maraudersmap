# 数据库访问

## TL;DR

**Python 通过 DB-API 2.0 标准让所有数据库的代码长得几乎一样**——换数据库只需换驱动 + 改连接串。三个层次：

| 层次 | 工具 | 何时用 |
|---|---|---|
| **内置** | `sqlite3`（stdlib）| 单机、轻量、文件级——本地缓存、原型、嵌入式 |
| **驱动** | `mysql-connector-python` / `psycopg2` / `pymysql` | 连服务器型数据库，写原生 SQL |
| **ORM** | `SQLAlchemy` | 把表行 ↔ Python 类自动映射，省去手写 SQL |

核心套路（DB-API 标准）：

```text
connect(...) ─► conn (连接)
                  │
                  ▼
              conn.cursor() ─► cursor (游标)
                                 │
                                 ▼
              execute(sql, params)  → 执行
              fetchone/fetchall/rowcount → 拿结果
                                 │
              cursor.close()        ▼
              conn.commit() / rollback()
              conn.close()
```

**绝对要记的 3 条**：

1. **永远用参数化查询** `execute(sql, params)`，**绝不**字符串拼接——SQL 注入是最常见的 Web 漏洞
2. **写操作后必须 `commit()`** —— DB-API 默认开启事务，不提交 = 没生效
3. **生产用连接池**（参考 [[4.04 资源池与连接池]]），不要每个请求开新连接

## 1. DB-API：所有数据库的统一接口

Python 的 [PEP 249](https://peps.python.org/pep-0249/) 定义了 DB-API 2.0 标准，**所有**主流数据库驱动都遵守同一套接口：

```python
# 不管底层是 sqlite / mysql / postgres，代码结构都长这样
conn = driver.connect(...)        # 1. 建立连接
cur = conn.cursor()                # 2. 获取游标
cur.execute('SELECT ...', params)  # 3. 执行 SQL
rows = cur.fetchall()              # 4. 取结果
cur.close()                        # 5. 关游标
conn.commit()                      # 6. 提交事务（写操作）
conn.close()                       # 7. 关连接
```

| 驱动 | 数据库 | 占位符 |
|---|---|---|
| `sqlite3` | SQLite | `?` |
| `mysql-connector-python` / `pymysql` | MySQL | `%s` |
| `psycopg2` | PostgreSQL | `%s` |
| `pyodbc` | SQL Server / ODBC | `?` |
| `oracledb` | Oracle | `:1`, `:2` |

> ⚠️ **占位符不是字符串格式化**——不要因为是 `%s` 就用 `%` 拼接。它是驱动负责安全转义的"参数槽"。

## 2. SQLite：内置、零依赖、单文件

SQLite 是个**嵌入式**数据库——整个数据库就是一个 `.db` 文件，不需要服务进程。Python 标准库直接内置 `sqlite3`。

### 基本用法

```python
import sqlite3

# 连接（文件不存在会自动创建）
conn = sqlite3.connect('test.db')
cur = conn.cursor()

# 建表
cur.execute('''
    CREATE TABLE IF NOT EXISTS user (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        score INTEGER
    )
''')

# 插入：用 ? 占位
cur.execute('INSERT INTO user (name, score) VALUES (?, ?)', ('Bob', 90))
cur.execute('INSERT INTO user (name, score) VALUES (?, ?)', ('Alice', 85))

# 提交事务
conn.commit()

# 查询
cur.execute('SELECT * FROM user WHERE score > ?', (80,))
print(cur.fetchall())
# [(1, 'Bob', 90), (2, 'Alice', 85)]

cur.close()
conn.close()
```

### 用 `with` 自动管理

```python
with sqlite3.connect('test.db') as conn:
    cur = conn.cursor()
    cur.execute('INSERT INTO user (name, score) VALUES (?, ?)', ('Tom', 70))
    # with 块结束时自动 commit（出异常则 rollback）
```

但**不会自动 close `conn`**——SQLite 的 with 只管事务，得自己关连接。

### 内存数据库

```python
conn = sqlite3.connect(':memory:')   # 数据在内存，进程退出消失
```

适合单元测试——飞快，每个测试一个干净数据库。

### 行变成 dict / namedtuple

默认 `fetchall()` 返回 tuple。让它返回类 dict 对象：

```python
conn.row_factory = sqlite3.Row
cur = conn.cursor()
cur.execute('SELECT * FROM user')
row = cur.fetchone()
print(row['name'])      # 像 dict 一样按列名访问
print(row[0])           # 也兼容下标
```

### 什么时候用 SQLite，什么时候不用

| 适合 SQLite | 不适合 |
|---|---|
| 本地缓存、配置存储 | 高并发写（同一时间只能一个写者）|
| 单机桌面应用、移动 App | 多机分布式 |
| 嵌入式设备 | 数据量超 TB |
| 单元测试 | 需要细粒度权限管理 |
| 中小型 Web 应用（读多写少）| 跨进程频繁并发写 |

Python `sqlite3` 默认不允许跨线程共享连接——多线程要 `check_same_thread=False`，但也要自己加锁。

## 3. MySQL：服务器型数据库

MySQL 适合 **Web 应用的服务器端**——能承受高并发，但需要单独安装服务进程。

### 安装与配置

```bash
# 方式 1：直接装
brew install mysql          # mac
sudo apt install mysql-server # ubuntu

# 方式 2：Docker（推荐做开发）
docker run -e MYSQL_ROOT_PASSWORD=password -p 3306:3306 \
           --name mysql -v ./mysql-data:/var/lib/mysql \
           mysql:8.4 --character-set-server=utf8mb4 \
                     --collation-server=utf8mb4_unicode_ci
```

`/etc/my.cnf` 配置编码（避免中文乱码）：

```ini
[client]
default-character-set = utf8mb4

[mysqld]
default-storage-engine = INNODB
character-set-server = utf8mb4
collation-server = utf8_general_ci
```

> 用 `utf8mb4` 不是 `utf8`——前者支持 emoji，后者只支持 BMP 字符。MySQL `utf8` 是个历史坑。

### 装驱动

```bash
pip install mysql-connector-python   # 官方驱动
# 或
pip install pymysql                   # 第三方，纯 Python，更轻
```

### 基本用法（注意占位符是 `%s`）

```python
import mysql.connector

conn = mysql.connector.connect(
    host='localhost',
    port=3306,
    user='root',
    password='password',
    database='test',
)
cur = conn.cursor()

# 建表
cur.execute('CREATE TABLE IF NOT EXISTS user (id VARCHAR(20) PRIMARY KEY, name VARCHAR(20))')

# 插入：注意占位符是 %s（不是 SQLite 的 ?）
cur.execute('INSERT INTO user (id, name) VALUES (%s, %s)', ['1', 'Michael'])
print(cur.rowcount)   # 1

conn.commit()
cur.close()

# 查询
cur = conn.cursor()
cur.execute('SELECT * FROM user WHERE id = %s', ('1',))
rows = cur.fetchall()
print(rows)           # [('1', 'Michael')]

cur.close()
conn.close()
```

### 几个关键差异

| | SQLite | MySQL |
|---|---|---|
| 占位符 | `?` | `%s` |
| 服务进程 | 无（嵌入）| 必须 |
| 并发写 | 一次一个 | 真并发 |
| 用户/权限 | 无 | 完整 |
| 数据类型 | 弱类型（任何列存什么都行） | 强类型 |
| 默认开启事务 | 是 | 是 |
| 端口 | 无 | 3306 |

DB-API 代码 90% 一样——换数据库主要是改 import、connect 参数、占位符。

### PostgreSQL（书没讲但生产更推荐）

```bash
pip install psycopg2-binary
```

```python
import psycopg2

conn = psycopg2.connect(host='localhost', dbname='test',
                        user='postgres', password='password')
cur = conn.cursor()
cur.execute('SELECT * FROM users WHERE id = %s', (1,))   # %s 占位符
```

PostgreSQL 比 MySQL 标准更严格、功能更强（JSONB、窗口函数、CTE 都更好）——新项目首选 Postgres。

## 4. 参数化查询：永远不要拼字符串

```python
# ❌ 极度危险，SQL 注入漏洞
user_input = "Bob' OR '1'='1"
cur.execute(f"SELECT * FROM user WHERE name = '{user_input}'")
# 实际执行: SELECT * FROM user WHERE name = 'Bob' OR '1'='1'
# → 返回所有用户！

# ❌ 同样危险，% 格式化也是字符串拼接
cur.execute("SELECT * FROM user WHERE name = '%s'" % user_input)

# ✓ 安全的参数化查询
cur.execute("SELECT * FROM user WHERE name = ?", (user_input,))   # SQLite
cur.execute("SELECT * FROM user WHERE name = %s", (user_input,))   # MySQL/PG
```

```text
参数化的工作原理:

代码:   execute("SELECT * WHERE name = ?", ("Bob' OR 1=1",))
              ↓
驱动:   把 SQL 和参数分开发给数据库
              ↓
数据库:  把 "Bob' OR 1=1" 当作整个字符串字面量处理
              不会被解释成 SQL 语法
```

**这条规则不打折扣**——只要变量来自用户/外部，**必须**走参数化。表名/列名不能参数化时，用白名单校验。

## 5. SQLAlchemy：ORM 框架

写一堆 SQL 字符串又啰嗦又容易出错——**ORM (Object-Relational Mapping)** 把表的行映射成 Python 对象，把 SQL 变成方法调用。

```text
数据库表 ─── ORM ───► Python 类
                       │
   user 表              ├── User 类
   ┌─────┬──────┐      │   ├── id 属性
   │ id  │ name │      │   └── name 属性
   ├─────┼──────┤      │
   │ 1   │ Bob  │      └── 一行 = 一个 User 实例
   │ 2   │ Tom  │
   └─────┴──────┘
```

### 安装与最小例子

```bash
pip install sqlalchemy
```

```python
from sqlalchemy import Column, String, create_engine
from sqlalchemy.orm import sessionmaker, declarative_base

# 1. 声明基类
Base = declarative_base()

# 2. 定义模型（= 表 = Python 类）
class User(Base):
    __tablename__ = 'user'

    id = Column(String(20), primary_key=True)
    name = Column(String(20))

# 3. 初始化引擎（连接字符串：dialect+driver://user:pwd@host:port/db）
engine = create_engine('mysql+mysqlconnector://root:password@localhost:3306/test')

# 4. 创建表（如果不存在）
Base.metadata.create_all(engine)

# 5. 工厂：以后所有 session 都从这里来
DBSession = sessionmaker(bind=engine)
```

### CRUD 操作

```python
# === 创建 ===
session = DBSession()
new_user = User(id='5', name='Bob')
session.add(new_user)
session.commit()                                 # 必须 commit
session.close()

# === 查询 ===
session = DBSession()
user = session.query(User).filter(User.id == '5').one()
print(type(user), user.name)
# <class 'User'> Bob

# 多种查询方式
all_users = session.query(User).all()
user_by_id = session.query(User).get('5')
filter_chain = session.query(User).filter(User.name.like('B%')).order_by(User.id).limit(10).all()
session.close()

# === 更新 ===
session = DBSession()
user = session.query(User).filter(User.id == '5').one()
user.name = 'Robert'                             # 改属性即可
session.commit()
session.close()

# === 删除 ===
session = DBSession()
session.query(User).filter(User.id == '5').delete()
session.commit()
session.close()
```

### 关系映射：一对多 / 多对一

```python
from sqlalchemy import ForeignKey
from sqlalchemy.orm import relationship

class User(Base):
    __tablename__ = 'user'
    id = Column(String(20), primary_key=True)
    name = Column(String(20))
    books = relationship('Book')                  # 一对多：一个 User 有多个 Book

class Book(Base):
    __tablename__ = 'book'
    id = Column(String(20), primary_key=True)
    name = Column(String(20))
    user_id = Column(String(20), ForeignKey('user.id'))   # 外键

# 用起来像访问 Python 属性
user = session.query(User).get('5')
for book in user.books:                          # 自动 join 关联表
    print(book.name)
```

### Session 是事务作用域，永远 `try/finally close`

```python
from contextlib import contextmanager

@contextmanager
def session_scope():
    session = DBSession()
    try:
        yield session
        session.commit()
    except Exception:
        session.rollback()
        raise
    finally:
        session.close()

# 调用方
with session_scope() as session:
    session.add(User(id='6', name='Charlie'))
# 自动提交 + 关闭；出错自动回滚
```

参考 [[2.03 contextlib 上下文管理]] 里的 `@contextmanager`。

### 常用连接字符串

| 数据库 | 字符串 |
|---|---|
| SQLite 文件 | `sqlite:///path/to/file.db` |
| SQLite 内存 | `sqlite:///:memory:` |
| MySQL | `mysql+mysqlconnector://user:pwd@host:3306/db` |
| MySQL (PyMySQL) | `mysql+pymysql://user:pwd@host:3306/db` |
| PostgreSQL | `postgresql+psycopg2://user:pwd@host:5432/db` |
| SQL Server | `mssql+pyodbc://user:pwd@dsn` |

只换连接字符串就能换数据库——这是 ORM 最大的便利。

## 6. ORM 用还是不用：取舍

| 维度 | 原生 SQL + DB-API | ORM (SQLAlchemy) |
|---|---|---|
| 学习曲线 | 会 SQL 就行 | 还要学 ORM 自己一套 API |
| 性能 | 完全可控 | 多一层抽象，复杂查询可能生成低效 SQL |
| 业务代码 | 大量字符串、易出错 | 类型友好、IDE 补全 |
| 数据库切换 | 改 SQL 方言 | 改连接串即可 |
| 复杂查询（JOIN/CTE/窗口）| 直接写 SQL 简洁 | 复杂时 ORM 反而别扭 |
| 适合 | 数据分析、报表、批处理 | Web 应用、CRUD 主导的系统 |

**实战经验**：

- 简单 CRUD 用 ORM 爽
- 复杂查询、性能敏感的地方走原生 SQL（SQLAlchemy 也支持 `session.execute(text("..."))`）
- 不二之选：**SQLAlchemy Core** 介于两者之间——表达式语法构造 SQL，不映射对象

## 7. 工程实践清单

| 实践 | 原因 |
|---|---|
| **永远参数化查询** | 防 SQL 注入 |
| **永远 `commit` 或 `rollback`** | DB-API 默认事务，不显式提交=未生效 |
| **永远在 `finally` 里 close** | 不关连接 = 资源泄漏 → 连接池耗尽 |
| **生产用连接池** | 见 [[4.04 资源池与连接池]]，SQLAlchemy 默认带池 |
| **超时设置** | 卡在数据库上能让整个服务挂死 |
| **migrations 工具** | Alembic（SQLAlchemy 配套）管理 schema 演进 |
| **测试用 SQLite `:memory:`** | 比开 MySQL 容器快得多 |
| **凭据走环境变量** | 别把密码写代码里，见 [[0.02 环境变量与配置]] |
| **logging 打开 SQL** | 排查慢查询：`echo=True` 或配 logger |

### 最小生产模板

```python
import os
from contextlib import contextmanager
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

DATABASE_URL = os.environ['DATABASE_URL']   # 从环境变量读

engine = create_engine(
    DATABASE_URL,
    pool_size=10,           # 连接池
    max_overflow=20,
    pool_pre_ping=True,     # 自动剔除死连接
    pool_recycle=3600,      # 1 小时回收，避免 MySQL 8 小时断连
)

SessionLocal = sessionmaker(bind=engine, autocommit=False, autoflush=False)

@contextmanager
def db_session():
    session = SessionLocal()
    try:
        yield session
        session.commit()
    except Exception:
        session.rollback()
        raise
    finally:
        session.close()
```

## 8. 速查表

### DB-API 通用

| 操作 | 写法 |
|---|---|
| 连接 | `conn = driver.connect(...)` |
| 游标 | `cur = conn.cursor()` |
| 执行 | `cur.execute(sql, params)` |
| 批量执行 | `cur.executemany(sql, params_list)` |
| 取一行 | `cur.fetchone()` |
| 取所有 | `cur.fetchall()` |
| 取 N 行 | `cur.fetchmany(n)` |
| 受影响行数 | `cur.rowcount` |
| 自增 ID | `cur.lastrowid` (SQLite) / `cur.lastrowid` (MySQL) |
| 提交 | `conn.commit()` |
| 回滚 | `conn.rollback()` |

### SQLAlchemy

| 操作 | 写法 |
|---|---|
| 创建引擎 | `create_engine('mysql://...')` |
| 创建模型 | `class User(Base): __tablename__ = ...` |
| 建表 | `Base.metadata.create_all(engine)` |
| 开 Session | `session = SessionLocal()` |
| 插入 | `session.add(obj); session.commit()` |
| 查一行 | `session.query(User).get(id)` 或 `.filter(...).one()` |
| 查多行 | `session.query(User).filter(...).all()` |
| 更新 | 改属性 + `session.commit()` |
| 删除 | `session.query(User).filter(...).delete()` |
| 原生 SQL | `session.execute(text("SELECT ..."))` |

## 9. 与其他语言对比

| | Python | Node.js | Go |
|---|---|---|---|
| 标准接口 | DB-API (PEP 249) | 无（各驱动 API 不同） | `database/sql` 标准接口 |
| SQLite 内置 | ✓ `sqlite3` | 需 `better-sqlite3` | 需 `mattn/go-sqlite3` |
| ORM 主流 | SQLAlchemy | Prisma / TypeORM | GORM / ent |
| 异步 | `asyncpg` / `aiomysql` | 原生 Promise | 无显式异步 |

Python 的 DB-API 是各语言里最早的标准化尝试之一，跨数据库代码可移植性最好。
