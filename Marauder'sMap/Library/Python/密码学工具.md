# 密码学工具

## TL;DR

**Python stdlib 提供三个相关但不同的工具：base64 编码、hashlib 哈希、hmac 带 key 的哈希。** 千万**别混淆**：

| 工具 | 类别 | 用途 | 关键性质 |
|---|---|---|---|
| `base64` | **编码** | 二进制 → 文本（URL/Cookie 友好）| **可逆**，**不是加密** |
| `hashlib` | **哈希** | 任意数据 → 固定长度摘要 | **单向**，防篡改 |
| `hmac` | **带 key 哈希** | 哈希 + 防彩虹表 | 验签、消息认证 |

**最常踩的坑**：

- base64 ≠ 加密——只是编码，**任何人都能解码**
- 哈希 ≠ 加密——不能"反推"原文，但**不能加密**（不能解密）
- 存密码用 hashlib 直接算 MD5/SHA 是**不够的**——必须加 salt，更好是用专门的 `bcrypt` / `argon2`

---

## 1. base64：二进制 ↔ 文本

很多文件（exe / jpg / pdf）含有不可打印字符，邮件正文、URL、Cookie 这些"只能装文本"的地方传不了。base64 用 64 个字符（`A-Z` `a-z` `0-9` `+` `/`）表达任意字节。

### 编码原理

```text
每 3 字节 = 24 bit → 划成 4 组每组 6 bit → 查表得 4 个字符

3 字节二进制  →  4 字节文本
长度变 4/3 倍（多 33%）
```

不足 3 字节用 `\x00` 补齐，末尾加 `=` 表示补了多少：

```text
'abc'     → 'YWJj'      (3 字节正好)
'ab'      → 'YWI='      (补 1 字节，加 1 个 =)
'a'       → 'YQ=='      (补 2 字节，加 2 个 =)
```

### Python 用法

```python
import base64

base64.b64encode(b'binary\x00string')
# b'YmluYXJ5AHN0cmluZw=='

base64.b64decode(b'YmluYXJ5AHN0cmluZw==')
# b'binary\x00string'
```

### URL safe 变体

标准 base64 含 `+` 和 `/`，在 URL 里会被解释为别的意思。`urlsafe_b64encode` 把它们换成 `-` 和 `_`：

```python
base64.b64encode(b'i\xb7\x1d\xfb\xef\xff')          # b'abcd++//'   ← URL 不友好
base64.urlsafe_b64encode(b'i\xb7\x1d\xfb\xef\xff')  # b'abcd--__'   ← URL 友好
```

### 去掉末尾 `=` 的实战技巧

JWT、Cookie 这些地方常把 `=` 去掉省字符。解码时需要补回 4 的倍数：

```python
def safe_b64decode(s):
    # 补齐 =
    s += '=' * (4 - len(s) % 4) if len(s) % 4 else ''
    return base64.b64decode(s)
```

### **核心警告：base64 不是加密**

```text
'password' → base64 → 'cGFzc3dvcmQ='

任何拿到 'cGFzc3dvcmQ=' 的人:
   base64.b64decode('cGFzc3dvcmQ=') → b'password'  ← 一秒还原
```

**用途**：让二进制能塞进文本通道（邮件附件、API JSON、Cookie、Data URL）。**别用它存敏感信息**。

## 2. hashlib：单向哈希

哈希函数 = 任意长度数据 → **固定长度**指纹（digest）。

```text
hash('how to use python hashlib')
                ↓
'2d73d4f15c0db7f5ecb321b6a65e5d6d'    ← 32 字符 16 进制
```

### 三大性质

1. **确定性**：相同输入 → 相同输出
2. **雪崩效应**：输入改一个 bit → 输出完全不同
3. **单向性**：能算 `hash(x)`，几乎**不能从 hash 反推 x**

### Python 用法

```python
import hashlib

md5 = hashlib.md5()
md5.update('how to use md5 in python hashlib?'.encode('utf-8'))
print(md5.hexdigest())
# d26a53750bc40b38b65a520292f69306
```

数据量大可以分块多次 `update`，结果完全一样：

```python
md5 = hashlib.md5()
md5.update('how to use md5 in '.encode('utf-8'))
md5.update('python hashlib?'.encode('utf-8'))
print(md5.hexdigest())
# 同样的结果
```

### 算法对比

| 算法 | 输出长度 | 速度 | 安全性 |
|---|---|---|---|
| `md5` | 128 bit (32 hex) | 最快 | **已破** ⚠️ |
| `sha1` | 160 bit (40 hex) | 快 | **已破** ⚠️ |
| `sha256` | 256 bit (64 hex) | 中 | 安全 ✓ |
| `sha512` | 512 bit (128 hex) | 慢 | 安全 ✓ |
| `blake2b` | 自定义 | 极快 | 安全 ✓ |

`update()` 接收 `bytes`——传 `str` 必须先 `.encode('utf-8')`。

### 经典用途

| 场景 | 例子 |
|---|---|
| 文件完整性 | 下载文件后比对 `sha256` 是否被篡改 |
| Git 对象 ID | Git commit 哈希就是 SHA-1 |
| 去重 | 海量文件按哈希分组，相同哈希 = 同一文件 |
| 一致性哈希 | 分布式系统决定数据落在哪台机器 |

## 3. 存密码：哈希 + salt

### 最 naive 的做法：明文存

```text
username  password
michael   123456         ← 数据库泄露 = 全部密码暴露
```

### 升级 1：存 MD5/SHA

```text
username  password (md5)
michael   e10adc3949ba59abbe56e057f20f883e
```

听起来安全，但**有问题**：

- 用户喜欢用 `123456` / `password` 这种弱密码
- 黑客预先把常用密码全部算好 MD5 存成**彩虹表**：`{e10adc...: '123456'}`
- 拿到数据库后直接查表，秒破

### 升级 2：加 salt

```python
def hash_password(password):
    return hashlib.md5((password + 'the-Salt').encode()).hexdigest()
```

salt 是程序员定的"佐料字符串"，让 `hash('123456' + 'the-Salt')` 不在通用彩虹表里。

但还有个问题——两个用户都用 `123456`，存的哈希一样，能看出"这俩密码相同"。

### 升级 3：每个用户独立 salt

```python
import hashlib, random

class User:
    def __init__(self, username, password):
        self.username = username
        # 随机生成 20 字符的 salt
        self.salt = ''.join([chr(random.randint(48, 122)) for _ in range(20)])
        self.password = hashlib.sha256(
            (password + self.salt).encode()
        ).hexdigest()

def login(user, password):
    return user.password == hashlib.sha256(
        (password + user.salt).encode()
    ).hexdigest()
```

| 阶段 | 安全性 |
|---|---|
| 明文 | 0 |
| MD5 | 防内部窥视，但彩虹表破 |
| MD5 + 固定 salt | 防通用彩虹表，但需 salt 不泄露 |
| MD5 + 每用户 salt | 即使同密码哈希也不同，是基本及格线 |

### **生产实战：不要自己写**

上面这套是教学用的"最低要求"。真正生产环境应该用 **bcrypt** 或 **argon2**：

```python
# pip install bcrypt
import bcrypt

# 注册
hashed = bcrypt.hashpw(password.encode(), bcrypt.gensalt())
# bcrypt 自动生成 salt 并嵌入到结果里

# 登录
bcrypt.checkpw(password.encode(), hashed)   # True/False
```

bcrypt / argon2 比 MD5/SHA 优越在：

- **故意慢**：CPU 跑一次几十毫秒，暴力破解极慢
- **自动 salt**：存在结果字符串里，不用单独管理
- **可调强度**：未来 CPU 变快，加大 work factor 重新加密

**口诀**：存密码 = bcrypt/argon2，**绝对不要**直接 `hashlib.md5(password)`。

## 4. hmac：带 key 的哈希

`hmac(key, message)` = 把 key 混入哈希算法的标准方式。和"自己拼接 salt 再算 hash"相比：

| | 自己 `hash(msg + salt)` | `hmac(key, msg)` |
|---|---|---|
| 通用性 | 私有，难审计 | 标准算法（RFC 2104）|
| 算法切换 | 自己改代码 | 换参数 `digestmod` 即可 |
| 已知攻击 | 某些算法可能"长度扩展攻击" | 设计上免疫 |

### Python 用法

```python
import hmac

message = b'Hello, world!'
key = b'secret'

h = hmac.new(key, message, digestmod='MD5')
print(h.hexdigest())
# fa4ee7d173f2d97ee79022d1a7355bcf
```

也支持分块：

```python
h = hmac.new(key, digestmod='SHA256')
h.update(b'part 1')
h.update(b'part 2')
print(h.hexdigest())
```

key 和 message 都必须是 `bytes`，字符串要先 `.encode('utf-8')`。

### 经典用途

| 场景 | 怎么用 |
|---|---|
| **API 签名** | 客户端用 secret 计算 `hmac(secret, request)`，服务端验证 |
| **JWT 签名** | JWT 的 HS256 算法就是 `hmac-sha256` |
| **Webhook 验签** | GitHub / Stripe 用 hmac 防止 webhook 被伪造 |
| **存密码 salt** | 替代手写 salt 拼接（虽然 bcrypt 更推荐）|

### 安全比较：用 `hmac.compare_digest`

比较两个签名时**不要用 `==`** ——攻击者可以通过响应时间差猜出正确的签名（计时攻击）。用 `compare_digest`，它是**恒定时间**的：

```python
import hmac

expected = hmac.new(key, msg, 'sha256').hexdigest()

# ❌ 易受计时攻击
if user_sig == expected:
    ...

# ✓ 恒定时间比较
if hmac.compare_digest(user_sig, expected):
    ...
```

## 5. 三个工具组合使用

很多 API 签名机制：

```text
1. 把请求参数排序拼接成字符串 → message
2. 用 secret 算 hmac-sha256(secret, message) → digest
3. base64.urlsafe_b64encode(digest) → signature
4. 把 signature 加到请求头
5. 服务端拿到请求，相同算法重算，hmac.compare_digest 验证
```

```python
import hmac, hashlib, base64

def sign(secret: bytes, message: bytes) -> str:
    digest = hmac.new(secret, message, hashlib.sha256).digest()
    return base64.urlsafe_b64encode(digest).decode().rstrip('=')

sig = sign(b'mysecret', b'GET /api/users?id=1')
```

这就是 AWS / 阿里云 等签名机制的简化版。

## 6. 速查表

| 任务 | 写法 |
|---|---|
| 二进制 → URL 安全文本 | `base64.urlsafe_b64encode(b'...')` |
| 文件 SHA-256 | 循环 `update()`，最后 `hexdigest()` |
| 字符串 MD5 | `hashlib.md5(s.encode()).hexdigest()` |
| HMAC 签名 | `hmac.new(key, msg, 'sha256').hexdigest()` |
| 恒定时间比较 | `hmac.compare_digest(a, b)` |
| 存密码 | **用 `bcrypt`，不要自己 hash** |

## 7. 实际选型

| 需求 | 工具 |
|---|---|
| 二进制嵌入 URL/Cookie/邮件 | `base64.urlsafe_b64encode` |
| 校验文件完整性 | `hashlib.sha256` |
| 给数据生成唯一指纹（缓存 key 等）| `hashlib.sha256` / `blake2b` |
| 存用户密码 | **`bcrypt`** 或 `argon2`（第三方）|
| API 请求签名 | `hmac.new(secret, msg, 'sha256')` |
| Webhook 验签 | `hmac.compare_digest` 比 |
| 真正的加密（可解密） | `cryptography` 库的 Fernet 或 AES（**不是** hashlib）|
