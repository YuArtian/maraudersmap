# 调试技巧

## TL;DR

**Python 提供四档调试手段，从简单到强大依次是：print → assert → logging → pdb，最强的是 IDE 断点。** 选型建议：

| 工具 | 适合场景 | 代价 |
|---|---|---|
| `print()` | 快速看一眼变量值 | 提交前必须删，污染输出 |
| `assert` | 中断"不该到这里的逻辑" | 没法关掉就一直在；Python `-O` 可全局关 |
| `logging` | 长期保留的运行信息 | 配置一次，按级别开关 |
| `pdb` | 单步执行、看调用栈 | 命令行交互略麻烦 |
| **IDE 断点** | 复杂 bug 的最终武器 | 需要 VSCode/PyCharm |

**资深开发者最后都靠 logging**——调试代码留下来当运行时观测，不用反复删。

---

## 1. `print`：最原始的调试

```python
def foo(s):
    n = int(s)
    print('>>> n = %d' % n)         # 临时打印
    return 10 / n

foo('0')
# >>> n = 0
# ZeroDivisionError: division by zero
```

| 优点 | 缺点 |
|---|---|
| 不用学任何东西 | 提交前忘记删 → 污染日志 |
| 0 配置 | 想长期保留不容易关 |

**使用建议**：只用在交互式调试，写完 PR 前用 `grep print` 检查清理。

---

## 2. `assert`：可关闭的运行时检查

```python
def foo(s):
    n = int(s)
    assert n != 0, 'n is zero!'      # 不满足条件就抛 AssertionError
    return 10 / n
```

```python
foo('0')
# AssertionError: n is zero!
```

`assert 条件, 消息` 在条件为假时抛 `AssertionError`。

### 关键特性：`-O` 可一键关闭

```bash
python -O err.py    # -O 是大写字母 O（不是数字 0），关闭所有 assert
```

加 `-O` 后所有 `assert` 都被解释器视为 `pass`——所以**生产环境**默认会关掉。

### assert 适合什么、不适合什么

| 场景 | 适合？ |
|---|---|
| 调试时验证内部不变式 | ✓ 用 |
| 表达"这里不可能到达" | ✓ 用 |
| 校验用户输入 | ✗ 用 `if + raise ValueError` |
| 校验函数参数 | △ 慎用，`-O` 一关就没了 |

**口诀**：assert 只用于"应该总是为真"的内部断言；任何**安全相关**的检查都不能用 assert（攻击者可能跑 `-O`）。

## 3. `logging`：长期保留的运行信息

```python
import logging
logging.basicConfig(level=logging.INFO)   # ← 关键，没这行什么都不输出

s = '0'
n = int(s)
logging.info('n = %d', n)
print(10 / n)
```

```text
INFO:root:n = 0
ZeroDivisionError: division by zero
```

### 五个级别

```text
DEBUG → INFO → WARNING → ERROR → CRITICAL
  ↑                                  ↑
最详细                              最严重
```

| 方法 | 级别 | 何时用 |
|---|---|---|
| `logging.debug()` | 10 | 详细的开发调试信息 |
| `logging.info()` | 20 | 程序正常运行的关键事件 |
| `logging.warning()` | 30 | 不影响功能但要注意的问题 |
| `logging.error()` | 40 | 错误发生，部分功能失效 |
| `logging.critical()` | 50 | 严重错误，程序可能崩溃 |

`basicConfig(level=logging.INFO)` 表示**只输出 INFO 及以上**——开发时设 DEBUG 看全，生产设 WARNING 只看异常。

### logging 比 print 强在哪

| 特性 | print | logging |
|---|---|---|
| 按级别过滤 | ✗ | ✓ |
| 输出到文件 | 手动 redirect | 内置 FileHandler |
| 自动加时间戳/模块名 | ✗ | ✓ |
| 多个目的地（console + file） | ✗ | ✓ |
| 生产环境保留 | ✗ 一般要删 | ✓ 该留就留 |

### 常用配置

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s [%(levelname)s] %(name)s: %(message)s',
    handlers=[
        logging.FileHandler('app.log'),       # 写文件
        logging.StreamHandler(),               # 同时打到 console
    ]
)
```

## 4. `pdb`：命令行单步调试

### 方式一：整个文件用 pdb 启动

```bash
python -m pdb err.py
> err.py(2)<module>()
-> s = '0'
(Pdb)
```

进入交互式调试器，可用命令：

| 命令 | 作用 |
|---|---|
| `l` (list) | 看当前代码上下文 |
| `n` (next) | 执行下一行（不进入函数）|
| `s` (step) | 执行下一行（进入函数）|
| `c` (continue) | 继续运行，遇到下一断点暂停 |
| `p 变量名` | 打印变量值 |
| `pp 变量名` | 漂亮打印（嵌套结构）|
| `b 行号` | 在某行设置断点 |
| `q` (quit) | 退出调试器 |
| `h` (help) | 看所有命令 |

### 方式二：`pdb.set_trace()` 设置断点

更实用——只在需要的地方暂停：

```python
import pdb

s = '0'
n = int(s)
pdb.set_trace()         # 跑到这里自动停下来
print(10 / n)
```

Python 3.7+ 起有更简洁的写法 `breakpoint()`：

```python
breakpoint()            # 等价于 import pdb; pdb.set_trace()
```

而且可以通过环境变量切换调试器：

```bash
PYTHONBREAKPOINT=ipdb.set_trace python app.py    # 用 ipdb 代替 pdb
PYTHONBREAKPOINT=0 python app.py                  # 关闭所有 breakpoint()
```

### 用 IDE 代替 pdb

命令行 pdb 在复杂程序里很累。**VSCode** / **PyCharm** 都能可视化设断点、看变量、看调用栈，强烈推荐。`pdb` 仅作为没有 IDE 时的备用（比如 SSH 上线机器）。

## 5. 实战经验

### 经验 1：调试代码不删，留作日志

```python
# ✗ 调试用 print，提交时删除
print(f'user_id={user_id}')

# ✓ 调试用 logging，可以留下来
logger.debug('user_id=%s', user_id)     # 开发时 level=DEBUG 看到，生产关闭
```

### 经验 2：用 `%s` 而不是 f-string 给 logger

```python
# ✗ 即使日志级别没启用，f-string 也会构造字符串（CPU 浪费）
logger.debug(f'expensive_repr={expensive_repr(obj)}')

# ✓ 用占位符，logger 内部判断级别后才格式化
logger.debug('expensive_repr=%s', expensive_repr(obj))
```

### 经验 3：异常时记录调用栈

```python
try:
    risky()
except Exception:
    logger.exception('risky failed')      # 自动带 traceback
    # 等价于 logger.error('msg', exc_info=True)
```

### 经验 4：模块级 logger，而不是 root

```python
# 每个文件顶部
logger = logging.getLogger(__name__)

# 用 logger 而不是 logging.info
logger.info('something happened')
```

好处：日志里能看到来源模块，可以按模块单独调级别。

## 6. 速查表

| 场景 | 用什么 |
|---|---|
| 一次性确认变量值 | `print()` |
| 临时强保证（运行后会改回来） | `assert` |
| 长期运行时观察 | `logging.info()` |
| 不该到达的分支 | `raise AssertionError` 或 `assert False` |
| 在特定位置暂停看现场 | `breakpoint()` (3.7+) / `pdb.set_trace()` |
| 完整步进、查看调用栈 | IDE 断点（VSCode / PyCharm）|
| 程序崩溃后事后排查 | `python -m pdb script.py` 或 `pdb.pm()` |
