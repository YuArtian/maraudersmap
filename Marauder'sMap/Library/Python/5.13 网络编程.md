# 网络编程

## TL;DR

**网络编程 = 让 Python 进程通过 socket 跟另一个进程"对话"。** Python `socket` 模块是 BSD socket API 的薄包装，TCP/UDP 都用同一个 API：

| 协议 | 创建 | 特征 |
|---|---|---|
| TCP | `socket(AF_INET, SOCK_STREAM)` | 可靠、有连接、按字节流；HTTP/SMTP 都建立在它之上 |
| UDP | `socket(AF_INET, SOCK_DGRAM)` | 不可靠、无连接、按数据报；DNS、视频流、游戏用 |

核心套路：

- **客户端**：`socket()` → `connect((ip, port))` → `send/recv` → `close`
- **服务器**：`socket()` → `bind` → `listen` → 循环 `accept` → 每个连接开新线程
- **UDP** 没有 `listen`/`accept`/`connect`，直接 `recvfrom` / `sendto`
- 收到的都是 `bytes`，自己 `.decode('utf-8')` / `.encode('utf-8')`
- **实战中**几乎不直接写 socket——用 requests / aiohttp / FastAPI 等高层框架；本文是"理解原理"的层级

## 1. TCP/IP 基础速览

```text
应用层    HTTP / SMTP / DNS / 自定义协议
              ↑ 用得最多
传输层    TCP（可靠、有序）       UDP（快、不保证到达）
              ↑ 本文重点
网络层    IP（把包从 A 路由到 B）
              ↑ 给计算机一个唯一地址
链路层    以太网 / WiFi（电信号 / 无线电波）
```

### 几个基础概念

| 概念 | 解释 |
|---|---|
| **IP 地址** | 计算机在网络上的唯一标识。IPv4 是 32 位（`192.168.0.1`），IPv6 是 128 位（`2001:db8::1`） |
| **端口** | 同一台机器上区分不同程序的"门牌号"，0-65535 |
| **`127.0.0.1`** | localhost，只能本机访问 |
| **`0.0.0.0`** | 绑定到**所有**网卡（包括外网）|
| **众所周知端口** | 0-1023 是系统保留（HTTP=80、HTTPS=443、SSH=22、SMTP=25），需 root |
| **私有端口** | 1024 以上随便用 |

### TCP vs UDP

```text
TCP「打电话」                  UDP「寄明信片」
───────────────────────       ──────────────────────────
1. 拨号、对方接听（握手）         1. 写好地址直接扔出去
2. 全程保持连接                  2. 寄完拍拍手走人
3. 你一句我一句、有序             3. 不知道对方收没收到
4. 挂电话（断开）                4. 顺序也可能乱
                              
✓ 可靠：丢包自动重传              ✓ 快：没握手、没确认
✓ 有序：包按顺序到达              ✓ 无状态：服务端不用维护连接
✗ 慢：要握手、确认                ✗ 不保证到达
                              
HTTP / SSH / 数据库 / Git       DNS / 视频通话 / 游戏 / NTP
```

## 2. TCP 客户端：模拟浏览器抓网页

```python
import socket

# 创建 TCP socket
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
#                  ^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^
#                  IPv4          TCP（"流式"）

# 连接到服务器
s.connect(('www.sina.com.cn', 80))    # 注意是 tuple
```

参数：

| 选项 | 用途 |
|---|---|
| `socket.AF_INET` | IPv4 |
| `socket.AF_INET6` | IPv6 |
| `socket.AF_UNIX` | Unix 域 socket（同机进程间）|
| `socket.SOCK_STREAM` | TCP（流式）|
| `socket.SOCK_DGRAM` | UDP（数据报）|

### 发请求 + 收响应

```python
# 发 HTTP 请求（手动拼一个 GET）
s.send(b'GET / HTTP/1.1\r\nHost: www.sina.com.cn\r\nConnection: close\r\n\r\n')

# 循环 recv 直到对方关闭连接
buffer = []
while True:
    d = s.recv(1024)         # 一次最多 1024 字节
    if d:
        buffer.append(d)
    else:
        break
data = b''.join(buffer)

s.close()

# 切分 HTTP 头和 body
header, html = data.split(b'\r\n\r\n', 1)
print(header.decode('utf-8'))
with open('sina.html', 'wb') as f:
    f.write(html)
```

```text
浏览器 = TCP 客户端 + HTTP 协议
└─ TCP 负责把字节可靠地送到对面
└─ HTTP 规定字节怎么排：GET 路径 HTTP/1.1\r\n... 这种格式
```

实际写爬虫当然用 [[5.10 urllib HTTP 客户端]] 里的 `requests`——但理解到这一层"`requests` 内部就是这么干的"，遇到底层问题才能 debug。

## 3. TCP 服务器：多线程 echo 服务

服务端比客户端多三个步骤：`bind` / `listen` / `accept`，然后**每个连接开新线程**。

```python
import socket, threading, time

# 1. 创建 socket
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# 2. 绑定 IP + 端口
s.bind(('127.0.0.1', 9999))      # 127.0.0.1 只本机能连
#                                 # 0.0.0.0 所有网卡都能连进来

# 3. 开始监听，参数是"等待队列长度"
s.listen(5)
print('Waiting for connection...')

# 4. 每来一个连接就开线程处理
def tcplink(sock, addr):
    print(f'Accept new connection from {addr}')
    sock.send(b'Welcome!')
    while True:
        data = sock.recv(1024)
        time.sleep(1)
        if not data or data.decode('utf-8') == 'exit':
            break
        sock.send(('Hello, %s!' % data.decode('utf-8')).encode('utf-8'))
    sock.close()
    print(f'Connection from {addr} closed.')

while True:
    sock, addr = s.accept()                      # 阻塞，等待新连接
    t = threading.Thread(target=tcplink, args=(sock, addr))
    t.start()
```

```text
服务器内部流程:

  ┌─────────────────────────────────────────────┐
  │ 主线程                                       │
  │   while True:                                │
  │     sock, addr = s.accept()  ← 阻塞等连接     │
  │     start_thread(handler, sock)               │
  │                                              │
  │     (一来连接就把它扔给子线程,                  │
  │      主线程立刻回去等下一个连接)               │
  └─────────────────────────────────────────────┘
            │           │           │
            ▼           ▼           ▼
       子线程 1     子线程 2    子线程 N
       (跟客户端 A) (跟客户端 B) (跟客户端 N)
       的会话)      的会话)     的会话)
```

**为什么必须多线程**？`recv` / `send` 都是阻塞的——单线程只能一对一服务。多线程让一个主进程可以同时和很多客户端对话。

### 配套客户端

```python
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect(('127.0.0.1', 9999))
print(s.recv(1024).decode('utf-8'))                # 'Welcome!'

for data in [b'Michael', b'Tracy', b'Sarah']:
    s.send(data)
    print(s.recv(1024).decode('utf-8'))            # 'Hello, Michael!' ...

s.send(b'exit')
s.close()
```

## 4. UDP 编程：服务端

UDP 没有连接概念——直接绑定端口然后 `recvfrom` / `sendto`：

```python
import socket

s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)   # ← DGRAM
s.bind(('127.0.0.1', 9999))                            # 没有 listen() / accept()

print('Bind UDP on 9999...')
while True:
    data, addr = s.recvfrom(1024)                      # 收数据 + 对方地址
    print(f'Received from {addr[0]}:{addr[1]}')
    s.sendto(b'Hello, %s!' % data, addr)               # 直接回 addr
```

```text
TCP 服务器:    socket → bind → listen → accept → recv/send → close
                                          ↑
                                  每个客户端开一个 socket

UDP 服务器:    socket → bind → recvfrom/sendto
                                ↑
                          一个 socket 对所有客户端
```

### UDP 客户端

```python
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
for data in [b'Michael', b'Tracy', b'Sarah']:
    s.sendto(data, ('127.0.0.1', 9999))                # 直接 sendto
    print(s.recv(1024).decode('utf-8'))
s.close()
```

不需要 `connect()`——拿目标地址就发。

### TCP / UDP 对比表

| 维度 | TCP | UDP |
|---|---|---|
| socket type | `SOCK_STREAM` | `SOCK_DGRAM` |
| 建立连接 | `connect()` | 不需要 |
| 服务端等连接 | `listen()` + `accept()` | `bind()` 后直接 `recvfrom` |
| 发数据 | `send(data)` | `sendto(data, addr)` |
| 收数据 | `recv(n)` | `recvfrom(n)` 同时返回对方地址 |
| 一个 socket 一个连接 | 是（每个客户端一个）| 否（一个 socket 对所有客户端）|
| 多客户端 | 必须多线程 | 单线程也行 |

## 5. socket API 速查

### 通用方法

| 方法 | 作用 |
|---|---|
| `socket(family, type)` | 创建 socket |
| `.bind((host, port))` | 绑定地址 |
| `.close()` | 关闭 |
| `.settimeout(s)` | 设置阻塞超时（None = 永久阻塞）|
| `.setsockopt(...)` | 调整 socket 选项（如 `SO_REUSEADDR`）|
| `.getsockname()` | 返回本地地址 |
| `.getpeername()` | 返回对方地址 |

### TCP 专有

| 方法 | 作用 |
|---|---|
| `.connect((host, port))` | 客户端发起连接 |
| `.listen(backlog)` | 服务端开始监听 |
| `.accept()` | 服务端接受一个连接，返回 `(sock, addr)` |
| `.send(data)` | 发字节，**可能只发一部分**，要检查返回值 |
| `.sendall(data)` | 发完整个 data，内部循环 |
| `.recv(n)` | 收最多 n 字节 |

### UDP 专有

| 方法 | 作用 |
|---|---|
| `.sendto(data, addr)` | 发到指定地址 |
| `.recvfrom(n)` | 收数据，同时返回 `(data, addr)` |

## 6. 几个常见陷阱

### 陷阱 1：`send` 不一定一次发完

```python
# ❌ 错：发大数据时可能只发了一部分
s.send(big_data)

# ✓ 用 sendall 保证全部发完
s.sendall(big_data)
```

`send` 返回**实际发送字节数**，可能小于 `len(big_data)`。`sendall` 内部循环直到发完。

### 陷阱 2：`recv(n)` 可能收不满 n 字节

```python
# ❌ 假设 recv(1024) 一定返回 1024 字节
data = s.recv(1024)
parse(data)         # data 实际可能只有 100 字节

# ✓ 循环收，直到拿够期望长度
def recv_exactly(sock, n):
    buf = bytearray()
    while len(buf) < n:
        chunk = sock.recv(n - len(buf))
        if not chunk:
            raise ConnectionError('peer closed')
        buf.extend(chunk)
    return bytes(buf)
```

TCP 是**字节流**——它不保证你发一次就收一次。可能发 1 次收 3 次，也可能发 3 次收 1 次。**消息边界要自己定**（用长度前缀或分隔符）。

### 陷阱 3：端口被占用 `Address already in use`

刚关闭的服务端立刻重启会报这个错。两种解法：

```python
# 方法 1：设置 SO_REUSEADDR
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
s.bind((host, port))

# 方法 2：换个端口或者等几分钟（TIME_WAIT 状态结束）
```

### 陷阱 4：阻塞 / 超时

默认 `connect` / `recv` / `accept` 都是**永久阻塞**。生产代码必须设超时：

```python
s.settimeout(10)
try:
    data = s.recv(1024)
except socket.timeout:
    print('Timeout!')
```

### 陷阱 5：UDP 包不能太大

单个 UDP 包理论最大 64KB，但实际**别超过 1400 字节**（IPv4 MTU 1500 - 头部）——超了就会分片，分片丢一个整个包就废。

### 陷阱 6：服务器永远跑

服务器 `while True: accept()` 不会自己退出——必须 Ctrl+C 或主动 close。生产用 systemd / supervisor 管理生命周期。

## 7. 现代实战：别直接写 socket

```text
裸 socket   ← 本文这一层，理解原理
   │
   ▼
HTTP 协议处理   ── http.server / urllib（stdlib）
   │
   ▼
Web 框架       ── Flask / FastAPI / Django
   │
   ▼
专用客户端     ── requests / httpx / aiohttp
```

| 需求 | 用什么 |
|---|---|
| 写 HTTP 客户端 | [[5.10 urllib HTTP 客户端]] 里的 `requests` / `httpx` |
| 写 HTTP 服务 | Flask / FastAPI / Django，**别**手写 socket |
| 高并发网络服务 | `asyncio` + `aiohttp`（参考 [[4.03 并发编程]]）|
| 自定义二进制协议 | socket + [[5.12 struct 二进制处理]] |
| RPC | gRPC / Thrift / 自定义协议 |
| WebSocket | `websockets` 库 |
| TCP/UDP 学习实验 | 直接用 socket 是合适的 |

直接用 socket 的场景**很少**：

- 实现自定义协议（如 MQTT 客户端、游戏私有协议）
- 调试网络问题、写最小复现
- 教学/学习

## 8. 完整最小示例：echo 服务 + 客户端

```python
# server.py
import socket, threading

def handle(conn, addr):
    print(f'[+] {addr} connected')
    while data := conn.recv(1024):    # 海象赋值，Python 3.8+
        conn.sendall(b'echo: ' + data)
    conn.close()
    print(f'[-] {addr} closed')

s = socket.socket()
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
s.bind(('0.0.0.0', 9999))
s.listen(5)
print('Listening on :9999...')

while True:
    conn, addr = s.accept()
    threading.Thread(target=handle, args=(conn, addr), daemon=True).start()
```

```python
# client.py
import socket

s = socket.socket()
s.connect(('127.0.0.1', 9999))

for msg in [b'hello', b'world', b'bye']:
    s.sendall(msg)
    print(s.recv(1024).decode())

s.close()
```

```bash
# 终端 1
$ python server.py
Listening on :9999...
[+] ('127.0.0.1', 54321) connected

# 终端 2
$ python client.py
echo: hello
echo: world
echo: bye
```

## 9. 与 JavaScript / Go 对比

```python
# Python (socket)
import socket
s = socket.socket()
s.connect(('host', 80))
s.send(b'data')
```

```javascript
// Node.js (net 模块) - 异步
const net = require('net')
const s = net.createConnection({host: 'host', port: 80})
s.write('data')
s.on('data', (chunk) => { /* ... */ })
```

```go
// Go (net) - 并发自然
conn, _ := net.Dial("tcp", "host:80")
conn.Write([]byte("data"))
go handleConn(conn)         // goroutine 一行
```

**Python socket 是同步阻塞的**——多并发只能开线程（GIL 下不算真并行但 IO 阻塞时会释放 GIL）。要真正高并发要用 `asyncio` 或换 Go/Node。
