# 异常处理

## TL;DR

**Python 用 `try...except` 捕获异常，可以按类型精确捕获，也可以用 `Exception` 兜底。** 核心要点：

- `except 错误类型 as e:` 按类型分支捕获，`as` 给异常对象起别名
- 不确定错误类型时用 `except Exception as e:` 兜底
- Python 遇到错误立刻抛异常（不像 JS 返回 `Infinity` / `NaN`）
- `as` 关键字在 Python 多处出现，统一含义是"起别名"
- `logging` 模块提供 5 个级别的日志，支持格式化、文件输出、异常堆栈

---

## 1. 基本语法

```python
try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f'出错了: {e}')         # division by zero
finally:
    print('无论是否出错都执行')
```

对比 JS：

```python
# Python -- 可以按类型分支
try:
    do_something()
except KeyError:
    print('键不存在')
except ValueError:
    print('值有问题')
except Exception as e:
    print(f'未知错误: {e}')
```

```javascript
// JS -- 只有一个 catch，自己判断类型
try {
    doSomething()
} catch (e) {
    if (e instanceof TypeError) { ... }
    else { ... }
}
```

## 2. 常见错误类型

| 错误 | 触发场景 | 示例 |
|------|---------|------|
| `SyntaxError` | 语法写错 | `if x = 1:` |
| `NameError` | 变量未定义 | `print(abc)` |
| `TypeError` | 类型不对 | `'1' + 2` |
| `ValueError` | 值不对 | `int('abc')` |
| `IndexError` | 索引越界 | `[1,2][5]` |
| `KeyError` | dict 键不存在 | `d['xxx']` |
| `AttributeError` | 属性不存在 | `'abc'.foo` |
| `ZeroDivisionError` | 除以零 | `1 / 0` |
| `FileNotFoundError` | 文件不存在 | `open('xxx.txt')` |
| `ImportError` | 导入失败 | `import xxx` |
| `StopIteration` | 迭代结束 | `next()` 到头了 |

---

## 3. 异常继承层级

```text
BaseException
 └─ Exception            ← 几乎所有常见错误的父类
     ├─ ValueError
     ├─ TypeError
     ├─ KeyError
     ├─ IndexError
     ├─ AttributeError
     ├─ ZeroDivisionError
     ├─ FileNotFoundError
     └─ ...
```

捕获 `Exception` 就能兜住绝大部分错误。

---

## 4. 不确定错误类型时的写法

先精确捕获已知错误，再用 `Exception` 兜底：

```python
try:
    result = some_api_call()
except KeyError:
    print('键不存在')            # 精确处理
except ValueError:
    print('值有问题')            # 精确处理
except Exception as e:
    print(f'未知错误: {type(e).__name__}: {e}')  # 兜底
```

---

## 5. Python vs JS 的错误哲学

| 场景 | Python | JavaScript |
|------|--------|-----------|
| `10 / 0` | 抛出 `ZeroDivisionError` | `Infinity` |
| `0 / 0` | 抛出 `ZeroDivisionError` | `NaN` |
| 设计理念 | 错误就该立刻报错 | 尽量不崩溃 |

## 6. `as` 关键字的统一含义

`as` 在 Python 多处出现，统一含义都是**起别名**：

| 场景 | 语法 | 含义 |
|------|------|------|
| 异常捕获 | `except Exception as e` | 给异常对象起名 `e` |
| 导入模块 | `import numpy as np` | 给模块起别名 `np` |
| with 语句 | `with open('f.txt') as f` | 给返回对象起名 `f` |

注意和 TS 的 `as` 不同：

| | 含义 |
|---|---|
| Python `as` | **起别名**，给对象一个名字 |
| TS `as` | **类型断言**，告诉编译器类型 |

## 7. logging 模块

`print` 能打印但不专业（没有级别、时间、位置信息）。`logging` 是 Python 内置的日志模块：

```python
import logging

logging.debug('调试信息')
logging.info('一般信息')
logging.warning('警告')       # 默认只显示这个及以上
logging.error('出错了')
logging.critical('严重错误')
```

### 5 个级别（从低到高）

| 级别 | 用途 | 示例场景 |
|------|------|---------|
| `DEBUG` | 开发调试的细节 | 变量值、执行路径 |
| `INFO` | 正常运行信息 | "服务启动成功" |
| `WARNING` | 有潜在问题（默认级别） | "磁盘快满了" |
| `ERROR` | 出错但程序还能跑 | API 调用失败 |
| `CRITICAL` | 严重错误，可能崩溃 | 数据库连接断开 |

设置级别后，**低于该级别的不显示**：

```python
logging.basicConfig(level=logging.DEBUG)  # 显示所有
logging.basicConfig(level=logging.ERROR)  # 只显示 ERROR 和 CRITICAL
```

### 自定义格式

```python
logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s [%(levelname)s] %(message)s'
)

logging.info('服务启动')
# 2026-04-07 14:30:00,123 [INFO] 服务启动
```

常用格式变量：

| 变量 | 含义 | 输出示例 |
|------|------|---------|
| `%(asctime)s` | 时间 | `2026-04-07 14:30:00` |
| `%(levelname)s` | 级别 | `INFO` |
| `%(message)s` | 日志内容 | `服务启动` |
| `%(filename)s` | 文件名 | `app.py` |
| `%(lineno)d` | 行号 | `42` |

### 输出到文件

```python
logging.basicConfig(
    level=logging.INFO,
    filename='app.log',
    format='%(asctime)s [%(levelname)s] %(message)s'
)
```

### 在异常中记录日志

```python
try:
    result = 10 / 0
except Exception as e:
    logging.exception('计算出错')  # 自动附带完整堆栈信息
```

`logging.exception()` 等价于 `logging.error(msg, exc_info=True)`，会打印完整错误堆栈。

### 对比 JS

| Python | JavaScript | 说明 |
|--------|-----------|------|
| `logging.debug()` | `console.debug()` | 调试 |
| `logging.info()` | `console.info()` | 信息 |
| `logging.warning()` | `console.warn()` | 警告 |
| `logging.error()` | `console.error()` | 错误 |

JS 的 `console` 没有级别过滤、没有文件输出、没有格式化，生产环境一般用第三方库（winston、pino）。Python 的 `logging` 内置且功能完整。
