# 并发编程

## TL;DR

**Python 有三种并发方式：多进程、多线程、协程，选哪个取决于任务类型和并发量。** 核心要点：

- 进程（重）→ 线程（中）→ 协程（轻），从操作系统调度到程序自己调度
- GIL 限制多线程只能做 IO 密集任务，CPU 密集必须用多进程
- 协程用 `async/await` + 事件循环，1 个线程处理几万并发
- 日常脚本同步就够，Web 服务才需要考虑并发

---

## 1. 进程 vs 线程 vs 协程

```text
进程（Process）
  └─ 线程（Thread）
       └─ 协程（Coroutine）

从重到轻：进程 > 线程 > 协程
```

| | 进程 | 线程 | 协程 |
|---|---|---|---|
| 类比 | 一家公司 | 公司里的员工 | 员工的多个待办任务 |
| 谁来调度 | 操作系统 | 操作系统 | **程序自己**（事件循环） |
| 内存 | 各自独立（~几十MB） | 共享（~8MB/个） | 极轻量（~几KB） |
| 切换开销 | 大 | 中 | 极小 |
| 1万并发 | 不现实 | 勉强 | 轻松 |
| 能用多核 | 能 | 不能（GIL） | 不能 |
| 一个崩了 | 不影响其他 | 可能整个进程崩 | 不影响其他 |

## 2. 多线程 threading

```python
import threading
import time

def task(name):
    print(f'{name} 开始')
    time.sleep(2)
    print(f'{name} 结束')

t1 = threading.Thread(target=task, args=('线程1',))
t2 = threading.Thread(target=task, args=('线程2',))

t1.start()
t2.start()
t1.join()     # 等待完成
t2.join()
# 两个线程并行，总共 2 秒而不是 4 秒
```

## 3. 多进程 multiprocessing

CPU 密集任务用多进程，绕开 GIL：

```python
import multiprocessing

def heavy_task(name):
    total = sum(i * i for i in range(10**7))
    print(f'{name}: {total}')

if __name__ == '__main__':
    p1 = multiprocessing.Process(target=heavy_task, args=('进程1',))
    p2 = multiprocessing.Process(target=heavy_task, args=('进程2',))

    p1.start()
    p2.start()
    p1.join()
    p2.join()
```

### os.fork() 只能在 Unix 系

Python `os` 模块封装了 Unix 的 `fork` 系统调用：

```python
import os
pid = os.fork()        # 复制一份当前进程
if pid == 0:
    print('我是子进程')
else:
    print('我是父进程')
```

但 **Windows 没有 fork**，调用会直接报错：

| | Unix/Linux/macOS | Windows |
|---|---|---|
| 创建进程方式 | `fork()` + `exec()`（复制再替换） | `CreateProcess()`（直接新建） |
| `os.fork()` | 支持 | 不支持 |

### multiprocessing 是跨平台的

`multiprocessing` 自动适配不同操作系统：

```text
Unix/Linux/macOS:  multiprocessing → 底层用 fork()
Windows:           multiprocessing → 底层用 CreateProcess() + spawn
```

**结论**：学多进程**直接用 `multiprocessing`**，跳过 `os.fork()`。后者只是 Unix 底层接口，了解概念即可。

### Windows 必须用 `if __name__ == '__main__'`

```text
Linux fork：
  子进程是父进程的副本，继承所有状态
  不会重新执行模块代码

Windows spawn：
  子进程从零启动新的 Python 解释器
  会重新执行一遍模块代码
  没有 if __name__ == '__main__' 保护，
  子进程也会 p.start() → 又创建子进程 → 无限循环！
```

跨平台的最佳实践是**永远写上**：

```python
if __name__ == '__main__':
    p = Process(target=task)
    p.start()
```

## 4. GIL（Global Interpreter Lock）

CPython 解释器里的一把锁：**同一时刻只有一个线程能执行 Python 字节码。**

```text
没有 GIL（理想）：         有 GIL（实际）：
  线程1: ████████████       线程1: ██  ██  ██
  线程2: ████████████       线程2:   ██  ██  ██
  真正同时跑                 轮流拿锁，交替跑
```

### 为什么需要 GIL

Python 用引用计数管理内存，多线程同时修改引用计数会出错。GIL 用一把大锁保证安全。

### 关键：等 IO 时释放 GIL

```text
CPU 密集（GIL 成瓶颈）：
  线程1: [拿锁 计算] [拿锁 计算]
  线程2: [等锁...]   [等锁...]       → 实际串行

IO 密集（GIL 不是瓶颈）：
  线程1: [拿锁] [释放锁，等IO...] [拿锁]
  线程2:        [拿锁] [释放锁，等IO...]  → 有效果
```

| 任务类型 | 多线程有用吗 | 正确方案 |
|---------|-----------|---------|
| IO 密集（文件/网络） | 有用 | `threading` 或 `asyncio` |
| CPU 密集（计算） | 没用 | `multiprocessing` |

### 多进程为什么能绕开 GIL

每个进程有自己独立的 GIL 和内存，互不影响：

```text
进程1 [自己的 GIL] [自己的内存] → 线程跑
进程2 [自己的 GIL] [自己的内存] → 线程跑
```

## 5. 协程与 asyncio

协程是**可以暂停和恢复的函数**，用 `async/await` 定义：

```python
import asyncio

async def task(name, seconds):
    print(f'{name} 开始')
    await asyncio.sleep(seconds)   # 暂停，让出控制权
    print(f'{name} 结束')

async def main():
    await asyncio.gather(
        task('A', 2),
        task('B', 1),
        task('C', 3),
    )

asyncio.run(main())  # 启动事件循环
# A开始 B开始 C开始 → B结束(1s) → A结束(2s) → C结束(3s)
# 总共 3 秒，不是 6 秒
```

### 事件循环

事件循环负责调度所有协程：

```text
┌──────────────────────────────┐
│         事件循环               │
│                              │
│  协程A: await 网络请求 → 暂停   │
│  协程B: await 读文件  → 暂停   │
│  协程C: 正在执行...            │
│                              │
│  网络响应回来了 → 恢复协程A     │
│  文件读完了    → 恢复协程B     │
│  所有协程完成  → 退出          │
└──────────────────────────────┘
```

### 协程的本质：generator 的进化

| | generator | 协程 |
|---|---|---|
| 暂停关键字 | `yield` | `await` |
| 暂停时做什么 | 返回一个值给调用者 | 等 IO，让事件循环调度别人 |
| 恢复方式 | `next()` 手动恢复 | 事件循环自动恢复 |

## 6. 多线程 vs 异步 IO

| | 多线程 | 异步 IO |
|---|---|---|
| 1000 个用户要 | 1000 个线程 | 1 个线程 |
| 内存占用 | 高（每线程 ~8MB） | 低（几乎不增长） |
| 切换开销 | 有（OS 上下文切换） | 无（自己调度） |
| 编程难度 | 简单（同步写法） | 较高（async/await） |
| 并发上限 | 几千 | 几万甚至几十万 |

```text
类比：
  多线程 = 餐厅雇 1000 个服务员，每人盯一桌
  异步IO = 1 个服务员照看 1000 桌，哪桌菜好了就去送
```

## 7. 怎么选

```text
什么任务？
  │
  ├─ IO 密集（文件/网络/数据库）
  │    ├─ 几十个并发 → threading（简单）
  │    └─ 几千几万  → asyncio（高性能）
  │
  └─ CPU 密集（计算/图像处理）
       └─ multiprocessing
```

## 8. 对比 JS

| | Python | JavaScript |
|---|---|---|
| 默认模型 | 同步阻塞 | 异步非阻塞 |
| 多线程 | `threading`（有 GIL） | `Worker Threads`（真并行） |
| 多进程 | `multiprocessing` | `child_process` / `cluster` |
| 异步 | `asyncio`（需手动启动事件循环） | 原生 async/await（事件循环内置） |

JS 从一开始就是异步的（浏览器环境），Python 是同步的，异步后来才加。
