# 单元测试

## TL;DR

**单元测试 = 对一个函数、一个类的"行为"写一组断言，跑过去能确保代码没坏。** 核心要点：

- 测试类继承 `unittest.TestCase`，`test_xxx` 方法自动被发现并执行
- 用 `assertEqual` / `assertTrue` / `assertRaises` 而不是 `assert`——失败信息更清晰
- `setUp()` / `tearDown()` 在每个测试前后跑一次，用于建/拆资源（数据库、临时文件等）
- 跑测试推荐 `python -m unittest module.Class.method`，可以精确到一个方法
- 单元测试是**重构的底气**：通过 ≠ 没 bug，但**不通过一定有 bug**

---

## 1. 为什么写单元测试

```python
def abs(x):
    return x if x >= 0 else -x
```

写完函数后你脑子里其实已经过了这些用例：

| 输入 | 期望 |
|---|---|
| 正数 `1`, `1.2` | 原样返回 |
| 负数 `-1`, `-1.2` | 取相反数 |
| `0` | 返回 `0` |
| `None`, `[]`, `{}` | 抛 `TypeError` |

把这些用例写成代码，就是**单元测试**。最大的好处是——**未来改代码时，可以反复跑测试确认没改坏**。

> "通过 ≠ 没 bug。不通过 = 一定有 bug。"

## 2. 第一个 unittest

被测对象（`mydict.py`）：

```python
class Dict(dict):
    """像 dict 一样使用，也能用属性访问"""
    def __init__(self, **kw):
        super().__init__(**kw)

    def __getattr__(self, key):
        try:
            return self[key]
        except KeyError:
            raise AttributeError(f"'Dict' has no attribute '{key}'")

    def __setattr__(self, key, value):
        self[key] = value
```

测试文件（`mydict_test.py`）：

```python
import unittest
from mydict import Dict

class TestDict(unittest.TestCase):
    def test_init(self):
        d = Dict(a=1, b='test')
        self.assertEqual(d.a, 1)
        self.assertEqual(d.b, 'test')
        self.assertTrue(isinstance(d, dict))

    def test_key(self):
        d = Dict()
        d['key'] = 'value'
        self.assertEqual(d.key, 'value')      # dict 设的，能用属性读

    def test_attr(self):
        d = Dict()
        d.key = 'value'
        self.assertTrue('key' in d)            # 属性设的，能用 key 读
        self.assertEqual(d['key'], 'value')

    def test_keyerror(self):
        d = Dict()
        with self.assertRaises(KeyError):
            value = d['empty']

    def test_attrerror(self):
        d = Dict()
        with self.assertRaises(AttributeError):
            value = d.empty

if __name__ == '__main__':
    unittest.main()
```

```text
测试类:  继承 unittest.TestCase
            │
            ├── test_init   ┐
            ├── test_key    │  方法名以 test_ 开头才会被
            ├── test_attr   │  自动发现并运行
            ├── test_keyerror
            └── test_attrerror

每个 test_xxx 方法独立运行,互不影响:
   setUp()  →  test_xxx()  →  tearDown()
   setUp()  →  test_yyy()  →  tearDown()
```

## 3. 断言：assertEqual / assertTrue / assertRaises

不要用 Python 内置的 `assert`——用 TestCase 提供的方法，失败信息更详细。

| 方法 | 用途 |
|---|---|
| `assertEqual(a, b)` | a == b |
| `assertNotEqual(a, b)` | a != b |
| `assertTrue(x)` | bool(x) is True |
| `assertFalse(x)` | bool(x) is False |
| `assertIsNone(x)` | x is None |
| `assertIsNotNone(x)` | x is not None |
| `assertIn(item, container)` | `item in container` |
| `assertIsInstance(x, type)` | `isinstance(x, type)` |
| `assertRaises(Exc)` | 上下文里的代码必须抛 Exc |
| `assertAlmostEqual(a, b)` | 浮点近似相等 |

### 测异常用 with assertRaises

```python
def test_keyerror(self):
    d = Dict()
    with self.assertRaises(KeyError):
        value = d['empty']          # 这一行必须抛 KeyError，否则测试失败
```

也可以接收异常对象做进一步断言：

```python
with self.assertRaises(ValueError) as cm:
    score_must_be_int('abc')

self.assertIn('integer', str(cm.exception))
```

## 4. 运行测试的几种方式

### 方式一：把测试当脚本跑

```python
if __name__ == '__main__':
    unittest.main()
```

```bash
python mydict_test.py
```

### 方式二：`python -m unittest`（**推荐**）

```bash
python -m unittest mydict_test                    # 跑整个文件
python -m unittest mydict_test.TestDict           # 跑整个类
python -m unittest mydict_test.TestDict.test_attr  # 跑一个方法
```

```text
Ran 5 tests in 0.000s
OK
```

### 方式三：按关键字过滤 `-k`

```bash
python -m unittest mydict_test -k attr -v
# 跑所有名字里包含 attr 的测试
# -v 显示每个测试名
```

| 命令片段 | 作用 |
|---|---|
| `-v` | verbose，显示每个测试名 |
| `-k 关键字` | 名字匹配的才跑 |
| `-f` (fail fast) | 第一次失败就停 |

### 方式四：用 pytest（实际项目通常这个）

```bash
pip install pytest
pytest mydict_test.py                  # 自动发现 test_*.py
pytest -k attr                          # 关键字过滤
pytest --maxfail=1                      # 第一次失败就停
```

`pytest` 兼容 `unittest`，但语法更简洁：

```python
# pytest 风格 — 不需要继承 TestCase
def test_attr():
    d = Dict()
    d.key = 'value'
    assert 'key' in d                  # 直接用 assert，pytest 改写失败信息
    assert d['key'] == 'value'

def test_keyerror():
    import pytest
    with pytest.raises(KeyError):
        Dict()['empty']
```

`pytest` 也支持 fixture（更强的 setUp）、参数化测试等。**实际工作中绝大多数项目用 pytest**。

## 5. `setUp` / `tearDown`：每个测试前后跑

如果多个测试需要相同的准备工作（连数据库、起服务），不要每个方法都写一遍——用 setUp：

```python
class TestDB(unittest.TestCase):
    def setUp(self):
        self.conn = connect_db()
        self.conn.execute('BEGIN')        # 每个测试用单独事务

    def tearDown(self):
        self.conn.execute('ROLLBACK')     # 测试完回滚，互不影响
        self.conn.close()

    def test_insert(self):
        self.conn.execute('INSERT ...')

    def test_query(self):
        self.assertEqual(self.conn.query(...), expected)
```

```text
每个 test_xxx() 都被独立的 setUp/tearDown 包裹:

  setUp()  →  test_insert()  →  tearDown()
  setUp()  →  test_query()   →  tearDown()
```

| 钩子 | 何时跑 |
|---|---|
| `setUp(self)` | 每个 test 方法**前** |
| `tearDown(self)` | 每个 test 方法**后**（即使测试失败也跑） |
| `setUpClass(cls)` | 类里所有 test **之前**只跑一次 |
| `tearDownClass(cls)` | 类里所有 test **之后**只跑一次 |

类级钩子用 `@classmethod` 修饰，适合开销大的资源（启动 docker、连远程服务）。

## 6. 写好测试的几个原则

### 原则 1：覆盖正常路径、边界、异常

写测试时问自己："这个函数会被怎样的输入打挂？"

| 类别 | 例子（测 `abs()`）|
|---|---|
| 正常 | `abs(5)` → 5 |
| 边界 | `abs(0)` → 0 |
| 类型异常 | `abs('x')` 抛 TypeError |
| 极值 | `abs(float('inf'))` |
| 浮点精度 | `abs(-0.0)` 是 0 还是 -0 |

### 原则 2：一个测试只验一件事

不要在 `test_user` 里同时测注册、登录、退出——拆成 `test_register` / `test_login` / `test_logout`。失败时定位才快。

### 原则 3：测试代码本身要简单

> 单元测试代码要非常简单，如果测试代码太复杂，那么测试代码本身就可能有 bug。

测试里有 if/else、循环时要警惕——往往意味着应该拆成多个测试。

### 原则 4：测试独立

每个测试不能依赖其他测试留下的状态。用 setUp/tearDown 隔离，或者用临时目录/事务回滚。

### 原则 5：测试要快

慢测试没人愿意跑。能 mock 的外部依赖（HTTP、DB）就 mock，留下慢的"集成测试"分一类单独跑。

## 7. 速查表

| 操作 | 写法 |
|---|---|
| 定义测试类 | `class TestX(unittest.TestCase):` |
| 定义测试方法 | `def test_yyy(self):` 名字必须以 `test_` 开头 |
| 断言相等 | `self.assertEqual(actual, expected)` |
| 断言抛异常 | `with self.assertRaises(ValueError):` |
| 跑整个文件 | `python -m unittest module` |
| 跑某个方法 | `python -m unittest module.Class.test_method` |
| 关键字过滤 | `python -m unittest module -k pattern` |
| 详细输出 | 加 `-v` |
| pytest 等价 | `pytest`, `pytest -k pattern`, `pytest -v` |
