# CSS 隔离机制

## TL;DR

**微前端的样式冲突两个方向：子应用之间互相污染、子应用污染主应用**。四类方案按隔离强度排：**约定/工程化前缀**（BEM、CSS Modules——防君子）→ **运行时 scoped 改写**（qiankun 实验性 scoped：选择器加 `div[data-qiankun=app]` 前缀）→ **样式卸载重建**（qiankun 默认：切应用时移除/恢复 style）→ **Shadow DOM**（浏览器级硬隔离，但弹窗类组件出边界即失效）。

---

## 1. 冲突从哪来

CSS 只有全局作用域（见 [[1.03 选择器与优先级计算]]）：子应用 A 的 `.button { color: red }` 会命中主应用与 B 应用的所有 .button；第三方组件库（两个应用用了不同版本的同一 UI 库）冲突更隐蔽。

---

## 2. 四类方案逐个说

**① 工程化前缀（构建期，防患于未然）**：BEM 约定、CSS Modules 哈希、或 postcss 给子应用所有选择器统一加命名空间前缀（`.app-a .button`）。成本最低、无运行时开销；防不住第三方库样式与运行时动态插入。方案细节见 [[1.09 CSS 工程化：模块化方案、iconfont 与字体]]。

**② 动态样式表劫持——卸载重建（qiankun 默认行为）**：劫持子应用动态插入的 style/link 节点并登记，**unmount 时移除、再次 mount 时恢复**——保证「同一时刻只有活跃应用的样式生效」。解决**应用切换**场景的污染；**并存多应用时无效**（样式都在文档里）。

**③ 运行时 scoped（qiankun `experimentalStyleIsolation`）**：给子应用容器加特殊属性，改写其所有样式规则加上属性选择器前缀：

```css
/* 子应用原样式 */ .button { color: red; }
/* 改写后 */ div[data-qiankun="app-a"] .button { color: red; }
```

原理同 Vue scoped（属性选择器版命名空间）。短板：**改写有运行时成本**；子应用**挂到 body 的弹窗/抽屉在容器外**，前缀选择器够不着——弹窗样式丢失是最高频的坑（解法：组件库配置弹窗挂载点回容器内，antd 的 getPopupContainer / ConfigProvider）。

**④ Shadow DOM（`strictStyleIsolation` / 无界方案）**：子应用渲染进 shadowRoot，浏览器级样式边界——内外互不穿透，隔离最彻底。代价清单（为什么 qiankun 不默认开）：**弹到 body 的组件直接失去样式**（样式都关在 shadow 里）；事件冒泡边界、`document.querySelector` 找不到 shadow 内节点，需要框架代理（无界用 proxy 把 DOM 操作转发进 shadowRoot，见 [[1.01 微前端概览与选型]]）；React 老版本合成事件在 shadow 边界的兼容问题。

---

## 3. 选型口径

| 场景 | 方案 |
|---|---|
| 路由级切换、同刻单应用 | qiankun 默认的样式卸载重建就够 |
| 多应用并存（聚合页） | scoped 改写 或 Shadow DOM（配好弹窗挂载点） |
| 自有代码的长期治理 | 工程化前缀/CSS Modules 打底，运行时方案兜第三方 |
| 新起项目、隔离优先 | 无界（Shadow DOM 全套 + DOM 代理已封装好） |

万能答题句：**「构建期约定打底，运行时隔离兜底，弹窗挂载点是所有方案共同的坑」**。

## 面试问答

### Q: 微前端的 CSS 隔离有哪些方案？

满分答案：按强度四层——工程化前缀（BEM/CSS Modules/postcss 命名空间）构建期解决自有代码；qiankun 默认的动态样式劫持：登记子应用 style，卸载移除、再挂载恢复，覆盖切换场景；experimentalStyleIsolation 运行时把子应用选择器改写加 data 属性前缀，支持并存但有改写开销；Shadow DOM 浏览器级硬隔离最彻底。共同命门：挂到 body 的弹窗逃出隔离边界——要么配置组件库弹窗容器，要么像无界那样代理 DOM 操作。

### Q: Shadow DOM 做样式隔离有什么问题？

满分答案：隔离是双向的——子应用弹窗/抽屉若挂到 body，样式全留在 shadowRoot 内，弹窗裸奔；document 级的查询和事件委托拿不到 shadow 内节点，第三方库假设的全局 DOM 失效；老版本 React 合成事件跨 shadow 边界有兼容问题。所以 qiankun 的 strictStyleIsolation 不默认开；无界能用好 Shadow DOM 的原因是它同时用 proxy 把 iframe 里的 document 操作系统性转发进 shadowRoot，把这些坑在框架层填平了。

### Q: 子应用弹窗样式丢失怎么排查和解决？

满分答案：先定性——弹窗默认挂 document.body，逃出了容器前缀选择器或 shadowRoot 的隔离范围。解决三选：组件库配置弹窗挂载容器回子应用内（antd 的 getPopupContainer/ConfigProvider、element 的 append-to）；或把弹窗类样式提为全局样式单独加命名空间；或升级到对弹窗做了代理处理的框架方案。这题是 CSS 隔离机制理解的落地检验。
