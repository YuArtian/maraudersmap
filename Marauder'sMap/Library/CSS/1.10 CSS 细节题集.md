# CSS 细节题集

## TL;DR

**高频小题打包**：隐藏元素三巨头对比（display:none / visibility:hidden / opacity:0 的占位与可点性）、单行/多行文本溢出省略、网页一键变灰（filter: grayscale）、点击穿透（pointer-events）、CSS 画扇形、iPhone 刘海屏安全区适配（env + viewport-fit）。

---

## 1. 隐藏元素的方法与差异（必背表）

| 方法 | 占空间 | 可点击 | 触发回流 | 过渡动画 | 子元素可反显 |
|---|---|---|---|---|---|
| `display: none` | ✘ | ✘ | ✔（移出渲染树） | ✘ | ✘ |
| `visibility: hidden` | ✔ | ✘ | ✘（仅重绘） | ✔（离散过渡） | **✔**（子元素设 visible 可单独显示） |
| `opacity: 0` | ✔ | **✔** | ✘（合成层） | ✔ 平滑 | ✘ |

补充队员：`position: absolute; top: -999em`（移出视口，屏幕阅读器仍读——无障碍隐藏的惯用法）、`clip-path: inset(100%)`、`transform: scale(0)`（占位与否取决于是否配合定位）、`height:0; overflow:hidden`（可做展开收起动画的基础）。

答题框架：先报三巨头的**占位、事件、回流、动画**四维差异，再按需求选——要过渡动画不能用 display:none（可用 grid-template-rows 0fr→1fr 或新的 `transition-behavior: allow-discrete` 补救）。

## 2. 文本溢出省略

```css
/* 单行 */
.one { white-space: nowrap; overflow: hidden; text-overflow: ellipsis; }

/* 多行（现代标准答案，兼容性已足够好） */
.multi {
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 3;
  overflow: hidden;
}
```

追问点：line-clamp 起源于 WebKit 私有属性、现已进入标准化（`line-clamp`）且各内核支持；老式兜底是「定高 + 伪元素绝对定位在右下角画 …」（缺点：不足三行也显示省略号，需 JS 判断）；表格单元格内省略还需 `max-width` 或 `table-layout: fixed` 配合。

## 3. 一行代码类

```css
/* 全站变灰（哀悼日）：作用于根元素 */
html { filter: grayscale(100%); }

/* 点击穿透：让遮罩层「透明于事件」 */
.overlay { pointer-events: none; }   /* 事件穿到下层；子元素可 auto 恢复 */

/* CSS 扇形（90° 示例）：圆角 + 隐藏 */
.sector {
  width: 100px; height: 100px;
  border-radius: 100px 0 0 0;       /* 单角圆化 = 四分之一扇 */
  background: coral;
}
/* 任意角度用 conic-gradient：
   background: conic-gradient(coral 0 45deg, transparent 45deg); + border-radius: 50% */
```

filter 细节（追问）：filter/opacity 都在合成层工作不触发回流重绘（见 [[1.08 CSS 动画与渲染性能]]）；但 filter 会**创建层叠上下文和包含块**——祖先加 filter 会「劫持」fixed 后代（见 [[1.07 定位与包含块]]），全站变灰导致弹窗定位异常就是这个坑，规避法是变灰只应用于内容容器而非 html。

pointer-events 的实战：穿透水印层、禁用整块表单（`none` + 局部恢复）、SVG 命中区域微调。

## 4. iPhone 刘海屏 / 安全区适配

三步走：

1. **meta 开启**：`<meta name="viewport" content="…, viewport-fit=cover">`——不设 cover 页面默认缩进安全区（contain），谈不上适配；
2. **env() 读取安全区**：

```css
.footer {
  padding-bottom: env(safe-area-inset-bottom);            /* 底部小黑条让位 */
  padding-bottom: constant(safe-area-inset-bottom);       /* iOS < 11.2 兼容（历史） */
}
```

3. 横屏时 left/right 同理。`env()` 是浏览器注入的环境变量（区别于 `var()` 读自定义属性），除安全区外还有键盘高度等新变量陆续加入。

## 面试问答

### Q: display:none、visibility:hidden、opacity:0 的区别？

满分答案：四个维度——占位：后两者占、none 不占（移出渲染树）；事件：只有 opacity:0 可点击可交互；性能：none 的切换触发回流，hidden 仅重绘，opacity 走合成层最轻；继承行为：visibility 特殊——子元素设 visible 能在隐藏的父级里反向显示。选型：要动画不能用 none，要「视觉隐藏但可交互」（自定义上传按钮盖住 input）用 opacity:0，无障碍隐藏用移出视口法保留屏幕阅读器可读。

### Q: 多行文本溢出省略怎么做？

满分答案：-webkit-box + -webkit-line-clamp + overflow:hidden 三件套是事实标准，line-clamp 已进入标准化、各内核均支持；单行则 nowrap + ellipsis。补充边界：老兜底方案用定高加伪元素画省略号但无法感知「是否真的溢出」，需要精确控制（展开/收起按钮联动）时用 JS 比较 scrollHeight 与 clientHeight。

### Q: 哀悼日全站变灰怎么实现？有什么坑？

满分答案：html { filter: grayscale(100%) } 一行。两个坑要主动说：filter 会为元素创建层叠上下文与包含块，导致页面里 position:fixed 的弹窗、吸顶栏定位异常——解法是把滤镜下移到内容容器、排除弹层节点；部分老浏览器需要 -webkit- 前缀或 SVG filter 兜底。加分点：filter 在合成层工作，性能本身无虞。

### Q: iPhone 刘海屏怎么适配？

满分答案：先在 viewport meta 加 viewport-fit=cover 让页面铺满全屏（默认 contain 会自动避让），再用 env(safe-area-inset-bottom/top/left/right) 给受影响区域补 padding——典型是底部操作栏让开 Home 指示条；旧 iOS 用 constant() 兜底写在 env() 前。本质：系统通过 CSS 环境变量把异形屏的安全边界暴露给页面。
