# CSS 工程化：模块化方案、iconfont 与字体

## TL;DR

**CSS 模块化四代方案：BEM（命名约定）→ scoped/CSS Modules（构建期哈希隔离）→ CSS-in-JS（运行时/编译期 JS 生成）→ 原子化（Tailwind）**。核心矛盾始终是「全局作用域 + 特异性战争」。字体优化记住 `font-display: swap` 和按需子集化。

> 特异性治理的另一半（@layer、覆盖顺序）见 [[1.03 选择器与优先级计算]] 与 [[CSS Import 顺序与样式覆盖]]。

## 1. 模块化方案演进

**① BEM**（纯约定，零工具）：`block__element--modifier` 全类名扁平命名——特异性恒为一层类 `(0,1,0)`，覆盖只看顺序；代价是名字冗长、纪律靠自觉。

**② Vue scoped**：编译器给组件元素加 `data-v-hash` 属性、选择器补属性后缀实现隔离；穿透到子组件用 `:deep()`。**原理是属性选择器**，不是真作用域——全局样式仍能打进来。

**③ CSS Modules**（React 系主流）：`import styles from './a.module.css'` —— 构建期把类名编译成唯一哈希，JS 侧以对象属性引用：

```jsx
import styles from './Button.module.css';
<button className={styles.primary} />   // 渲染为 class="Button_primary__x7Kd2"
```

特性：默认全局隔离（`:global()` 逃生）、`composes` 组合复用、天然与 Tree Shaking 亲和。由 css-loader 的 modules 选项或 Vite 内置支持（`.module.css` 约定）。

**④ CSS-in-JS**（styled-components/emotion）：模板字符串写样式、插值引用 JS 变量做动态主题——**运行时注入 style 标签有性能税**（SSR 与并发渲染下问题更大），新一代方案转向**零运行时**（vanilla-extract、StyleX、Linaria：编译期抽出静态 CSS）。

**⑤ 原子化（Tailwind）**：预生成单一用途小类，HTML 里组合——样式复用率极高、产物尺寸稳定，代价是模板可读性与学习成本。现状一句话：**新项目主流是「CSS Modules 或 Tailwind」，运行时 CSS-in-JS 退潮**。

**按需加载**：组件库样式按需——现代库（antd5 CSS-in-JS、ESM 组件库）import 即按需；老项目用 babel-plugin-import 改写导入路径带上样式（机制见 [[2.03 Tree Shaking 与按需引入]]）。

## 2. 图标方案演进

| 方案 | 原理 | 问题/现状 |
|---|---|---|
| 雪碧图 | 一张大图 + background-position | 缩放糊、维护难，已淘汰 |
| **iconfont 字体图标** | 图标打进字体文件，伪元素 unicode 或类名使用 | 单色限制、字体加载闪烁、基线对齐怪；渐退 |
| **SVG（现役答案）** | inline SVG / SVG symbol sprite（`<use href="#icon">`） | 矢量、多色、可 CSS 控制 fill、可 currentColor 跟随文字颜色 |

iconfont 平台的三种用法（Unicode/Font class/Symbol）中 Symbol 就是 SVG sprite——回答「为什么从字体图标转向 SVG」：多色支持、无字体加载时序问题、语义与无障碍更好。

## 3. 自定义字体与优化

```css
@font-face {
  font-family: 'Brand';
  src: url('/fonts/brand.woff2') format('woff2');
  font-display: swap;      /* 先用回退字体渲染，加载完替换 —— 消灭 FOIT */
  unicode-range: U+4E00-9FFF;   /* 按码位分包，用到才下载 */
}
```

优化清单：**woff2** 格式（压缩最优）；**font-display: swap** 处理 FOIT（浏览器等字体的白字期，部分浏览器长达 3 秒）——swap 立即回退渲染、加载完替换（代价是 FOUT 闪一下+可能的布局偏移，用 `size-adjust`/`font-size-adjust` 缓解 CLS）；**子集化**（中文字体几 MB → 按需抽取几十 KB，构建工具 fontmin/subset）；关键字体 `<link rel="preload" as="font" crossorigin>`（见 [[2.04 script 加载与资源提示]]）。

## 面试问答

### Q: CSS 模块化有哪些方案？各自原理？

满分答案：按代际答——BEM 是命名约定，把特异性拉平靠纪律；Vue scoped 用编译期附加 data-v 属性 + 属性选择器实现软隔离，穿透用 :deep；CSS Modules 构建期把类名哈希化、JS 对象引用，默认硬隔离带 composes 复用；CSS-in-JS 用 JS 生成样式支持动态主题，但运行时注入有性能与 SSR 代价，新趋势是 vanilla-extract 等零运行时编译方案；Tailwind 原子类换极致复用。选型：组件化项目 CSS Modules/scoped 起步，设计系统化团队考虑原子化。

### Q: 字体图标（iconfont）和 SVG 图标怎么选？

满分答案：现役答案是 SVG——inline 或 symbol sprite（use 引用），矢量清晰、支持多色、fill 用 currentColor 跟随文本色、无字体加载时序问题、无障碍友好。iconfont 把图标塞进字体：只能单色、受 font-display 与基线影响、反爬字体之外场景已渐退。历史脉络（雪碧图→字体图标→SVG）顺带展示知识层次。

### Q: 自定义字体怎么优化加载？

满分答案：四板斧——格式用 woff2；font-display: swap 消灭 FOIT（立即回退渲染、就绪后替换，配 size-adjust 缓解替换时的布局偏移）；中文字体必须子集化（几 MB 压到几十 KB）加 unicode-range 分包按需下载；首屏关键字体 preload 提前拉取（记得 crossorigin）。衡量指标关联 CLS 与 LCP，体现性能观。
