# 选择器与优先级计算

## TL;DR

**优先级按 (a, b, c) 三元组从左到右逐位比较：a=ID 选择器数，b=类/伪类/属性数，c=元素/伪元素数**——高位一票否决，`(0,1,0)` 恒大于 `(0,0,999)`。内联样式压过一切选择器，`!important` 再压内联。同分时**后出现的赢**（这条与构建产物顺序的纠葛见 [[CSS Import 顺序与样式覆盖]]）。

---

## 1. 选择器清单（报得出类别即可）

基础：`*` 通配、`div` 元素、`.cls` 类、`#id`、`[attr=val]` 属性；伪类 `:hover/:focus/:nth-child()/:not()`；伪元素 `::before/::after/::first-line`。组合器：后代（空格）、子代 `>`、相邻兄弟 `+`、后续兄弟 `~`。现代新贵：**`:is()/:where()`**（选择器分组，where 优先级恒为 0——写低侵入默认样式的利器）、**`:has()`**（「父选择器」终于来了：`li:has(> img)` 选中含图的 li）。

---

## 2. 优先级计算：层叠的完整决策链

冲突声明的裁决顺序（从高到低）：

1. **来源与重要性**：`!important` 的用户代理样式 > `!important` 的页面样式 > 正常页面作者样式 > 浏览器默认样式；
2. **是否内联**：style 属性 > 任何选择器；
3. **特异性 (a, b, c)**：

```text
a：ID 选择器个数
b：类、伪类、属性选择器个数
c：元素、伪元素个数
（* 和组合器不计分；:where() 强制 0；:is()/:not() 取参数中最高者）

#nav .list li:hover  →  (1, 2, 1)
.header .nav a       →  (0, 2, 1)
div p                →  (0, 0, 2)
```

**逐位比较不进位**：`(0,1,0)` > `(0,0,任意多)` ——「一万个标签选择器干不过一个类」；
4. **同分看顺序**：文档中后声明的胜出（层叠的本义）。

两条独立于特异性的规则常被误解：**继承来的样式优先级最低**（任何直接命中的声明都压过继承，无关特异性）；**特异性与 DOM 距离无关**（选择器离元素「近」不加分）。

---

## 3. 工程视角

- `!important` 是债：想覆盖它只能更高特异性 + 又一个 important，滚雪球——仅限覆盖不可控的第三方样式；
- 特异性膨胀的治理：BEM 命名（全类名单层选择器，特异性恒 `(0,1,0)`，覆盖只看顺序）、CSS Modules/scoped（构建期哈希隔离，见 [[1.09 CSS 工程化：模块化方案、iconfont 与字体]]）；
- **`@layer` 级联层**（现代答案）：`@layer reset, vendor, app;` 显式声明层级——**层间优先级压过特异性**，第三方库扔进低层，业务样式怎么写都能赢，从机制上终结「特异性军备竞赛」；
- 顺序坑的典型现场：组件库 CSS 与业务 CSS 的打包输出顺序（详见 [[CSS Import 顺序与样式覆盖]]）。

## 面试问答

### Q: CSS 优先级是怎么计算的？

满分答案：完整决策链——先比来源与 important（!important > 内联 > 普通规则 > 浏览器默认），再比特异性三元组 (ID 数, 类/伪类/属性数, 元素/伪元素数)，从高位逐位比较、不进位，(0,1,0) 大于任意多的 (0,0,n)；全同分时文档后出现者胜。两个易错点：继承样式的优先级低于一切直接命中的声明；:where() 特异性恒为 0，:is() 取参数最高值。

### Q: !important 有什么问题？应该怎么管理样式覆盖？

满分答案：它跳出正常层叠，覆盖它需要「更高特异性 + 又一个 important」，形成军备竞赛且难以调试，只应该用于对抗不可控的第三方内联样式。治理正道：BEM 单类选择器把特异性拉平、CSS Modules 做作用域隔离，以及现代的 @layer 级联层——把第三方样式放低层、业务样式放高层，层间关系压过特异性，覆盖问题从「计分」变成「声明」。

### Q: :is()、:where()、:has() 是什么？

满分答案：:is(a, b) 是选择器分组，特异性取参数中最高者；:where() 功能相同但特异性恒为 0——写组件库默认样式用它，使用者一个类名就能覆盖；:has() 是关系选择器（俗称父选择器），如 li:has(>img) 选中包含图片的 li、form:has(:invalid) 选中含非法输入的表单，主流浏览器已全面支持。三者大幅减少 JS 参与样式判断的场景。
