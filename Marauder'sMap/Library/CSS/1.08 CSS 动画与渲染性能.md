# CSS 动画与渲染性能

## TL;DR

**CSS 动画三件套：transition（状态过渡）、animation + @keyframes（多帧编排）、transform（真正的动画载体）**。性能铁律：**只动 transform 和 opacity**——它们走合成层由合成线程/GPU 处理，跳过回流重绘，主线程卡死动画照跑；动 width/left/margin 每帧回流，必卡。

> 渲染流水线与合成层的机制见 [[2.03 浏览器渲染原理与回流重绘]]，rAF 与 JS 动画的关系见 [[2.04 并发控制与耗时任务优化]]。

---

## 1. 三种动画方式

```css
/* transition：两个状态间的自动过渡（需要触发条件：hover、类切换） */
.btn { transition: transform .3s ease, opacity .3s; }
.btn:hover { transform: scale(1.05); }

/* animation：多关键帧、可循环、可暂停，不依赖触发 */
@keyframes bounce {
  0%, 100% { transform: translateY(0); }
  50%      { transform: translateY(-20px); }
}
.ball { animation: bounce 1s ease-in-out infinite; }
```

对比要点：transition 是「A→B」的插值，得有状态变化才动；animation 自主编排帧序列，支持 infinite/alternate/paused、steps() 硬切帧。**序列帧动画**：`steps(N)` 配雪碧图逐帧切换 `background-position`——加载动画、表情动效的实现方式。

## 2. 性能分层（本篇核心）

| 动的属性 | 触发的流水线 | 成本 |
|---|---|---|
| width / height / margin / left / top | **回流** → 重绘 → 合成 | 最贵，每帧全套 |
| color / background / box-shadow / visibility | 重绘 → 合成 | 中 |
| **transform / opacity**（合成层上） | **仅合成** | 最便宜，不占主线程 |

原理复述：transform/opacity 的元素可提升为独立**合成层**，动画由合成线程调 GPU 完成——不重新布局、不重新绘制，**主线程被 JS 长任务阻塞时动画照常运行**（判断「这个动画卡不卡」的试金石）。位移动画的正确写法永远是 `transform: translateX()` 而不是 `left`。

配套手段：`will-change: transform` 提前提升合成层（用完移除，防层爆炸）；不得不动布局属性时至少用 rAF 节流 + FLIP 技巧（先记录终态、用 transform 反演播放——把布局动画转译成 transform 动画）。

**现代 API 补充**：Web Animations API（`el.animate()`，JS 里声明关键帧、可控可组合）；`@scroll-timeline`/`animation-timeline: scroll()` 滚动驱动动画；View Transitions API 做页面/元素切换过渡——答出任意一个都说明知识在保鲜。

## 3. 两个衍生话题

**动画的可访问性**：`@media (prefers-reduced-motion: reduce)` 为晕动症用户关闭非必要动画——工程素养加分点。

**CSS 动画 vs JS 动画**：CSS 声明式、浏览器可优化到合成线程、简单省心；JS（rAF/WAAPI/动画库）可中断、可编排复杂时序、可物理模拟。选型：状态过渡与循环动效用 CSS；跟手交互、复杂编排用 JS——两者都遵守「只动 transform/opacity」的铁律。

## 面试问答

### Q: CSS 动画怎么做性能优化？

满分答案：核心一条——只动 transform 和 opacity：它们在合成层上由合成线程与 GPU 处理，跳过布局和绘制，主线程阻塞也不掉帧；动 left/width 类布局属性每帧触发回流必卡。配套：will-change 或 translateZ(0) 提前提升合成层但用完移除防内存爆炸；布局类动画用 FLIP 手法转译成 transform；用 DevTools 的 Layers 和 Performance 面板验证。再补 prefers-reduced-motion 的无障碍适配体现全面性。

### Q: transition 和 animation 的区别？

满分答案：transition 定义两个状态间的过渡插值，必须由状态变化触发（hover、类名切换），只有起点终点；animation 绑定 @keyframes 帧序列，自主运行，支持循环、往返、暂停、延迟和 steps 逐帧模式，无需触发条件。经验法：交互反馈用 transition，持续动效和多阶段编排用 animation，两者动画属性都应收敛到 transform/opacity。

### Q: 为什么 transform 动画不会被 JS 阻塞？

满分答案：渲染流水线分工——主线程负责样式、布局、绘制指令，合成线程负责把已栅格化的层拼装上屏。transform/opacity 变化只需要在合成阶段调整层的变换矩阵或透明度，不回主线程走布局绘制；所以即使主线程被长任务占死，合成线程仍按帧率独立工作，动画流畅。这也是滚动不卡的同一机制。反例：动 margin 必须主线程重新布局，JS 一卡动画就停。
