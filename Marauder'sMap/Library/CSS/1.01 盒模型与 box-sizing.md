# 盒模型与 box-sizing

## TL;DR

**每个元素都是四层盒子：content → padding → border → margin**。`box-sizing` 决定 width 算到哪一层：`content-box`（默认）的 width 只是内容宽，实际占位还要加 padding/border；`border-box`（怪异盒模型）的 width 直接是「边框以内整体宽」——现代工程一律全局设 border-box。

---

## 1. 四层结构与两种计算模式

```text
┌── margin（外边距，不算尺寸、透明）─────────┐
│ ┌─ border ─────────────────────────┐ │
│ │ ┌ padding ───────────────────┐   │ │
│ │ │        content             │   │ │
│ │ └────────────────────────────┘   │ │
│ └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

| | `content-box`（标准） | `border-box`（IE/怪异） |
|---|---|---|
| `width: 200px` 的含义 | 内容区 200px | **内容+padding+border = 200px** |
| 实际占位宽 | 200 + padding×2 + border×2 | 200（margin 另算） |
| 心智 | 「加 padding 会把盒子撑大」 | 「盒子多大就是多大，内容自动缩」 |

全局重置的标准写法（各大 UI 框架都这么干）：

```css
*, *::before, *::after { box-sizing: border-box; }
```

border-box 的价值：`width: 50%` + padding 不会破布局、表单元素与 div 行为统一——「为什么推荐 border-box」的答案就是**尺寸可预测**。

---

## 2. margin 的三个特有话题

- **纵向 margin 合并**：相邻块级盒子的上下 margin 取较大值而非相加（机制与解法见 [[1.02 BFC、margin 塌陷与清除浮动]]）；
- **margin: auto 水平居中**：块级盒在包含块中剩余空间由 auto 吃掉；纵向 auto 在普通流不生效（flex 里横纵都生效——绝招见 [[1.06 水平垂直居中方案大全]]）；
- **百分比 margin/padding 的基准都是包含块的宽度**（含纵向的 padding-top！）——「padding-top 百分比做等比例占位图」技巧的原理。

---

## 3. 关联单位题：px、em、rem

`px` 是 CSS 像素（与设备像素隔着 DPR）；`em` 相对**当前元素**的 font-size（用在 font-size 上则相对父级，层层嵌套会复利叠乘——坑）；`rem` 相对**根元素** html 的 font-size（移动端 rem 适配方案的基座，构建期转换见 [[2.07 Babel 与编译体系]] 的 px2rem 一节）；现代补充 `vw/vh`、`clamp(min, ideal, max)`（流式排版一行搞定上下限）。

**Chrome 最小字号 12px 问题**：中文版 Chrome 对小于 12px 的 font-size 强制取 12px。显示更小字的方法：`transform: scale(0.8)`（作用于元素而非字体，注意占位仍按原尺寸算，需配合负 margin 或调整容器）；SVG 文本也可绕过。

## 面试问答

### Q: 说说 CSS 盒模型？box-sizing 两个值的区别？

满分答案：元素由 content、padding、border、margin 四层组成。box-sizing 决定 width/height 的语义——content-box（默认）只包含内容区，实际占位还要累加 padding 和 border；border-box 让 width 直接等于边框以内的总宽，内容区自动收缩。工程实践统一全局 border-box：尺寸可预测，百分比布局加 padding 不会溢出。补充：margin 永远不计入元素尺寸，且纵向相邻会合并。

### Q: em 和 rem 的区别？移动端为什么常用 rem？

满分答案：em 相对当前元素字号（定义 font-size 时相对父级），嵌套时逐层相乘难以控制；rem 只相对根元素字号，全局单一基准。移动端 rem 方案：按屏宽动态设置 html 的 font-size，配合构建期 px 转 rem，实现设计稿等比缩放。现代替代：vw 单位或 clamp() 可以无 JS 达到类似效果。

### Q: 怎么显示小于 12px 的字体？

满分答案：Chrome（中文版）有 12px 最小字号限制，直接设 10px 无效。方案：transform: scale() 缩放元素——注意缩放不改变布局占位，需要处理容器尺寸；或用 SVG 绘制文本。顺带说明 zoom 是非标属性不推荐。这题考的是「知道限制来源 + 知道 transform 不影响布局流」两个点。
