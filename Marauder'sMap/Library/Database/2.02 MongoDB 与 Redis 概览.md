# MongoDB 与 Redis 概览

## TL;DR

**MongoDB 是文档数据库：BSON 文档 + 灵活 schema，Node 生态配 Mongoose 建模——适合结构多变的业务数据**。**Redis 是内存键值库：五大数据结构 + 单线程命令模型，标配用途是缓存、会话、分布式锁、排行榜**。缓存三兄弟（穿透/击穿/雪崩）是 Redis 面试的必答题。

---

## 1. MongoDB：文档模型

对照 MySQL 记概念：database → database，table → **collection**，row → **document**（BSON，可嵌套对象与数组），column → field；不强制 schema——同一集合的文档结构可以不同（灵活是双刃剑，约束靠应用层）。

**选型口径**：结构频繁演化、层级天然嵌套（内容管理、配置、日志）、快速原型 → MongoDB；强事务、多表关联、报表聚合 → MySQL。补一句纠偏：MongoDB 4.0+ 也有多文档事务与聚合管道，「Mongo 没事务」是过时结论；但关系密集型场景仍是关系库主场。

**Node 侧 Mongoose 三件套**：

```js
const UserSchema = new mongoose.Schema({          // Schema：给无模式的库补上模型约束
  name: { type: String, required: true },
  tags: [String],
}, { timestamps: true });
const User = mongoose.model('User', UserSchema);  // Model：集合的操作句柄
await User.findOneAndUpdate({ name }, { $push: { tags: 'vip' } }, { new: true });
```

Mongoose 的价值：schema 校验、中间件钩子（pre save）、类型转换、填充关联（populate）——「在应用层给 MongoDB 找回纪律」。

## 2. Redis：内存数据结构服务器

五大结构与用途一一对应（背这张表）：

| 结构 | 典型用途 |
|---|---|
| String | 缓存对象 JSON、计数器（INCR）、分布式锁（SET NX EX） |
| Hash | 对象字段级读写（购物车：user → {sku: 数量}） |
| List | 消息队列（LPUSH/BRPOP）、最新列表 |
| Set | 去重、共同关注（交集） |
| ZSet | **排行榜**（score 排序）、延迟队列（score=时间戳） |

单线程命令执行为什么快：纯内存 + 单线程免锁免切换 + IO 多路复用（epoll）；6.0 的多线程只用于网络 IO，命令执行仍单线程——原子性的根基。

**缓存三兄弟**（高频必答）：

- **穿透**：查「根本不存在」的 key，缓存永远 miss、打穿到 DB——恶意流量常见。解法：空值也缓存（短 TTL）、布隆过滤器前置拦截；
- **击穿**：某个**热点 key 过期瞬间**，并发全部涌向 DB。解法：互斥锁（只放一个请求去重建）、热点永不过期 + 异步刷新；
- **雪崩**：**大量 key 同时过期**（或 Redis 宕机），DB 被洪峰冲垮。解法：TTL 加随机抖动、多级缓存、限流降级兜底、集群高可用。

记忆锚点：穿透是「查无此人」，击穿是「一点破洞」，雪崩是「集体失效」。

**缓存一致性**（追问层）：主流是 **Cache-Aside**——读：先缓存后 DB 并回填；写：**先更新 DB 再删除缓存**（延迟双删/订阅 binlog 兜底极端竞态）。为什么删而不是更新缓存：避免并发写乱序留下旧值，且惰性回填省无效计算。

## 面试问答

### Q: MongoDB 和 MySQL 怎么选？

满分答案：按数据形态与一致性需求——文档天然嵌套、schema 频繁演化、写入量大的场景（日志、内容、配置）选 MongoDB，读写模型就是业务对象，免 JOIN；强事务、复杂关联与报表选 MySQL。纠偏两句：Mongo 4.0+ 已支持多文档事务和聚合管道，但关系密集仍不是它的主场；Node 侧用 Mongoose 的 Schema/钩子在应用层补约束。

### Q: Redis 有哪些数据结构？各举一个用途？

满分答案：String 缓存与计数器、SET NX EX 做分布式锁；Hash 存对象支持字段级更新（购物车）；List 当消息队列（LPUSH+BRPOP 阻塞消费）；Set 去重与交并集（共同关注）；ZSet 按 score 排序做排行榜和延迟队列。加分点：单线程命令模型保证单命令原子性，6.0 的多线程仅限网络 IO；复杂原子操作用 Lua 脚本。

### Q: 缓存穿透、击穿、雪崩的区别与对策？

满分答案：穿透——查不存在的 key，缓存永远无法命中，对策是缓存空值加短 TTL、布隆过滤器拦截非法 key；击穿——单个热点 key 过期瞬间并发直击 DB，对策是重建加互斥锁、热点逻辑过期异步刷新；雪崩——大批 key 同时失效或缓存宕机，对策是 TTL 随机抖动、多级缓存、限流降级、哨兵/集群保可用。回答按「定义一句 + 对策两条」的节奏最清晰。

### Q: 缓存和数据库的一致性怎么保证？

满分答案：Cache-Aside 模式——读走缓存、miss 查库回填；写先更新数据库再删缓存（删除优于更新：并发写时不会留下乱序旧值，下次读时惰性回填）。极端竞态（读回填旧值覆盖删除）概率低，要求高的场景用延迟双删或订阅 binlog（canal）异步失效。强一致要求则别用缓存旁路，考虑读写穿透或干脆读库。
