# script 加载与资源提示

## TL;DR

**defer：并行下载、HTML 解析完后按顺序执行、在 DOMContentLoaded 前；async：并行下载、下完就执行、顺序不保证**。资源提示四件套按「确定性」排：preload 本页马上要用（高优先级）、prefetch 下一页可能用（空闲下载）、preconnect 提前建连、dns-prefetch 只提前解析域名。

---

## 1. script 的三种形态

```mermaid
flowchart TD
    A["普通 script：解析 ➜ ⏸暂停(下载+执行) ➜ 继续解析"]
    B["async：解析与下载并行 ➜ 下载完⏸立即执行 ➜ 继续解析"]
    C["defer：解析与下载并行 ➜ 解析全部完成 ➜ 按顺序执行 ➜ DOMContentLoaded"]
```

| | 下载 | 执行时机 | 顺序 | DOMContentLoaded |
|---|---|---|---|---|
| `<script>` | 阻塞解析 | 立即 | 文档顺序 | 之后才触发 |
| `async` | 并行 | **下完就执行**（可能在解析中途） | **不保证** | 不等它（但 load 事件等） |
| `defer` | 并行 | HTML 解析完、DCL **之前** | **保持文档顺序** | 等它执行完才触发 |

选型：有依赖关系、要操作 DOM 的业务脚本用 **defer**；完全独立的（埋点、广告）用 **async**；`type="module"` 默认就是 defer 行为。

冷知识（考细节）：**动态创建的 script 默认 async**——`document.createElement('script')` 插入后不阻塞解析、下完即执行，想保顺序要手动 `script.async = false`。

## 2. 资源提示（Resource Hints）

```html
<link rel="preload" href="/main.js" as="script">      <!-- 本页关键资源，提前高优下载 -->
<link rel="prefetch" href="/next-page.js">            <!-- 下一页资源，空闲时低优下载 -->
<link rel="preconnect" href="https://api.example.com"><!-- 提前 DNS+TCP+TLS 三连 -->
<link rel="dns-prefetch" href="//cdn.example.com">    <!-- 只做 DNS，老浏览器兜底 -->
```

**preload**：告诉浏览器「本页马上要用，提前下」——下载与执行分离，下完放内存不执行，等真正的 `<script>`/CSS 引用时直接用。必须写对 `as`（决定优先级和缓存匹配），字体还要加 `crossorigin`。典型对象：首屏字体、LCP 大图、关键脚本。**滥用反而有害**：preload 抢占带宽，把非关键资源提前了，关键的反而慢。

**prefetch**：「下一页可能要用」，空闲时下载存入 HTTP 缓存。注意坑：**当前页马上要用的资源千万别用 prefetch**——它优先级极低且可能与正常请求重复下载。典型对象：下一步路由的 chunk（很多路由库的鼠标悬停预加载就是它）。

**preconnect vs dns-prefetch**：preconnect 把 DNS + TCP + TLS 全做完（每个连接有开销，只给关键第三方域名开 2-3 个）；dns-prefetch 只解析域名，成本低可以多撒。

进阶补充：HTTP 103 Early Hints 可以让服务器在正式响应前先送一批 preload/preconnect 提示（替代被废弃的 HTTP/2 Server Push，见 [[1.02 HTTP 协议与版本演进]]）。

## 3. 事件时间线（把概念串起来）

`HTML 解析完成 → defer 脚本按序执行 → DOMContentLoaded → 图片等子资源加载完 → load`。

async 脚本游离在时间线外（下完就插队执行）；CSS 会推迟 DCL 吗？——CSS 本身不直接阻塞 DOM 解析，但会阻塞后续 JS 执行，从而间接推迟 DCL（机理见 [[2.03 浏览器渲染原理与回流重绘]]）。

## 面试问答

### Q: script 的 async 和 defer 有什么区别？

满分答案：两者下载都不阻塞 HTML 解析，区别在执行——async 下载完立即执行（此刻可能还在解析中，仍会打断），多个 async 谁先下完谁先跑，顺序不保证，DOMContentLoaded 也不等它；defer 等 HTML 解析完成后、DOMContentLoaded 之前按文档顺序执行。选型：依赖 DOM 或彼此有依赖的用 defer，完全独立的统计脚本用 async。补充：动态插入的 script 默认 async，module 脚本默认 defer。

### Q: preload 和 prefetch 的区别？各用在什么场景？

满分答案：preload 是「本页关键资源提前高优下载」，下载与执行分离，需要正确的 as 属性，用于首屏字体、LCP 图片、关键 chunk；prefetch 是「下一导航可能用的资源空闲低优下载」，用于预取下一页路由 chunk。反模式要点名：本页马上用的资源用 prefetch 会重复下载且优先级过低；preload 滥用会抢关键资源带宽。再补 preconnect（预建连，限量用）和 dns-prefetch（只解析 DNS，成本最低）。

### Q: DOMContentLoaded 和 load 的区别？

满分答案：DOMContentLoaded 在 DOM 树构建完成且 defer 脚本执行完后触发，不等图片、样式表引用的图像等子资源；load 等页面所有资源（图片、iframe、async 脚本）加载完毕才触发。性能上关注 DCL 意义有限，现代指标更看 LCP/INP；但理解两者是理解 defer/async 行为边界的前提。
