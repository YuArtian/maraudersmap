# Node 部署与 Docker

## TL;DR

**Node 部署三形态：裸机 + PM2 守护 → Docker 容器化 → K8s 编排**。Dockerfile 两大心法：**package.json 先拷贝单独装依赖（吃层缓存）**、**多阶段构建（builder 装依赖构建，runtime 只留产物）**。容器内进程必须**前台运行**（daemon 化会让容器认为「命令结束」直接退出）。

> 多进程与 PM2 见 [[1.04 Node 多进程与集群]]；CDN/OSS 上静态资源的架构见 [[1.05 DNS 与 CDN]]。

---

## 1. 部署形态演进

**裸机时代**：`npm ci --omit=dev` 装依赖（JS 无需编译，「构建」主要是装依赖 + 前端产物）→ PM2 启动守护（cluster 模式、开机自启、日志轮转）→ Nginx 反代（见 [[2.03 Nginx 配置精要]]）。

**容器时代**：环境打进镜像，「在我机器上是好的」终结；配合镜像仓库 + CI/CD 实现「构建一次，处处运行」。

**编排时代**：K8s 管副本数、滚动更新、自愈、扩缩容——容器内单进程、进程管理交给编排层。

## 2. Node 应用的 Dockerfile（判分点全在注释里）

```dockerfile
# ---- 构建阶段 ----
FROM node:20-alpine AS builder
WORKDIR /app
# ★ 先只拷贝依赖清单：源码变化不会击穿「装依赖」这一层的缓存
COPY package.json pnpm-lock.yaml ./
RUN corepack enable && pnpm install --frozen-lockfile
COPY . .
RUN pnpm build && pnpm prune --prod        # 构建后裁掉 devDependencies

# ---- 运行阶段 ----
FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
# ★ 只带走运行所需：产物 + 生产依赖，镜像从 1GB+ 瘦到百 MB 级
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
USER node                                   # 非 root 运行
EXPOSE 3000
CMD ["node", "dist/main.js"]                # ★ 前台运行，不要 daemon
```

四个必答要点：

1. **层缓存**：镜像逐层构建、逐层缓存，只有该层输入变化才重建——依赖清单与源码分开 COPY，改代码不重装 node_modules；
2. **多阶段构建**：构建工具链留在 builder 阶段，运行镜像只含产物——体积与攻击面双降；
3. **前台进程**：容器生命周期 = PID 1 的生命周期，`--daemon`/`pm2 start`（后台模式）会让容器秒退——用 `node` 直跑或 `pm2-runtime`；
4. **敏感信息不进 Dockerfile**：构建期变量用 `ARG`（--build-arg 传入），运行期用环境变量/secret 管理——镜像会被 history 检查，硬编码密钥等于公开。

**纯前端静态站的 Docker**：多阶段构建出 dist 后换 `FROM nginx:alpine`，COPY 产物到 html 目录——「构建环境与运行环境分离」的最小示范。进阶方案是构建时把带 hash 的静态资源推上 OSS/CDN，镜像里只留 HTML（发布/回滚只动 HTML，静态资源永不下线）。

## 3. 运行配套清单

- **优雅退出**：监听 SIGTERM——停止接新请求、等存量请求完成、断开 DB 再 exit（K8s 滚动更新给 30s 宽限期）；
- **健康检查**：/healthz 端点 + 容器 HEALTHCHECK / K8s 探针（liveness 自愈、readiness 摘流量）；
- **资源匹配**：`--max-old-space-size` 与容器内存配额对齐（见 [[1.05 Node 内存泄漏排查]]），否则 V8 还没 GC 就被 OOMKilled；
- **Web 安全基线**（框架内建能力要会点名）：CSRF token、XSS 过滤、安全响应头（呼应 [[1.07 Web 安全：XSS 与 CSRF]]）。

## 面试问答

### Q: Node 应用怎么部署？从简单到复杂说说？

满分答案：三段演进——裸机：npm ci 装依赖、PM2 cluster 模式守护（崩溃拉起、平滑 reload）、Nginx 反代与 TLS 终止；容器化：Dockerfile 多阶段构建出瘦镜像，环境一致性由镜像保证，进程前台运行交容器管理；编排：K8s 管副本、滚动更新与探针自愈，容器内不再需要 PM2。补充优雅退出（SIGTERM 排水）和健康检查端点是各形态通用的必修项。

### Q: 写 Node 的 Dockerfile 有哪些优化点？

满分答案：四点——package.json 与 lock 单独先 COPY 再装依赖，利用层缓存让改代码不重装依赖；多阶段构建，运行镜像只带 dist 和生产依赖（prune --prod），基于 alpine 体积再降；进程必须前台运行，容器把 PID 1 当生命周期，daemon 模式会导致容器立即退出；机密不进镜像——构建期 ARG 传入、运行期环境变量注入，另加 USER node 非 root 运行。

### Q: 前端静态项目用 Docker 部署的思路？

满分答案：多阶段——node 镜像里构建出 dist，第二阶段换 nginx:alpine 只 COPY 产物和 nginx 配置，最终镜像几十 MB。进阶：构建阶段把带内容 hash 的 JS/CSS 直接上传 OSS 配 CDN，镜像只保留 index.html——发布与回滚只涉及 HTML，旧版本静态资源仍在 CDN 上，天然支持灰度和秒级回滚；此时缓存策略配合「HTML 不缓存 + 资源长缓存」形成闭环。
